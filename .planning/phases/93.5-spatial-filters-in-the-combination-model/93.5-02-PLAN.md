<objective>
Make the combination-orchestrator the SOLE owner of spatial materialization. Each chart widget +
table-bound map layer now resolves its accepted spatial shapes (via resolveSpatialShapes), folds
them into stableComboHash (Plan 01's 4th param) when an eligible spatial target exists, and the
orchestrator includes spatialFilters + spatialTarget in the materialize for spatial-bearing combos.
Remove the now-subsumed useMapOnlySpatialMaterialize hook. Resolve the records disposition with the
least-risk option (exclude records from orchestrator enumeration — it stays on its self-contained,
already-spatial-correct legacy island). Add orchestrator spec scenarios + assert the sole-trigger gate.

Purpose: Closes SPATIAL-V118-01. Today (post-Phase-91) a table shared by a chart and a map DROPS
spatial because the orchestrator only fires on filterVersion (not spatialFilterVersion) and never
folds shapes. This plan fixes the drop and prevents double-materialization.

Output: Spatial-aware orchestrator + spec scenarios; deleted useMapOnlySpatialMaterialize (file +
import + call + its spec); records excluded from enumeration; sole-trigger grep gate documented + passing.
Zero server changes (Plan 01 + research confirmed the server already composes spatial ∧ column and
appends _c<hash8>; client args + in-flight cache key already handle spatial-distinct combos).
</objective>
