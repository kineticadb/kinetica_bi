# Phase 93.5 Plan 02: Spatial-Aware Combination Orchestrator Summary

**One-liner:** Combination orchestrator extended to fold accepted spatial shapes into combo hash + materialize args via resolveSpatialShapes per viz, spatialFilterVersion dep, and shapesForHash Pitfall-1 guard; useMapOnlySpatialMaterialize deleted; records excluded from enumeration; sole-trigger invariant enforced by grep gate.

## What Was Built

### Orchestrator Spatial Fold-In (Task 1)

`useCombinationOrchestrator.ts` gained:

1. **New imports**: `resolveSpatialShapes`, `aggregateSpatialTargetsByTable`, `useSpatialFilterStore`, `Shape`, `SpatialTarget`.

2. **`spatialFilterVersion` primitive selector** added to the hook's reactive subscriptions (S-02 compliant — primitive int). Added to the Effect dep array alongside `filterVersion`:
   ```
   [filterVersion, spatialFilterVersion, dashboardId, widgetsKey, layersKey, ceiling]
   ```
   No-loop proof: `spatialFilterVersion` bumps only on user draw/remove/clear events. `setEntry` bumps `combinationVersion` (excluded) — NOT `spatialFilterVersion`. Zero feedback loop.

3. **Imperative shapes read** inside the setTimeout callback:
   ```typescript
   const shapes = useSpatialFilterStore.getState().shapes;
   const targetsByTable = aggregateSpatialTargetsByTable(widgets);
   ```
   Avoids re-render storm from subscribing to `s.shapes` (array reference). Same pattern as the deleted `useMapOnlySpatialMaterialize`.

4. **Widget + layer loops** (STEP A): for each viz, compute:
   ```typescript
   const acceptedShapes = resolveSpatialShapes(cfg, shapes);
   const spatialTarget = targetsByTable.get(tableId);
   const shapesForHash = (spatialTarget && acceptedShapes.length > 0) ? acceptedShapes : [];
   const hash = stableComboHash("table", tableId, resolved, shapesForHash);
   ```
   Pitfall-1 guard ensures `shapesForHash` is empty when no eligible spatial target exists for the table — this prevents two vizs on a non-spatial table from getting different hashes due to spatial state.

5. **Extended `HashEntry` and `DesiredEntry` types** with `acceptedShapes: Shape[]` and `spatialTarget?: SpatialTarget` fields.

6. **STEP D** (`materializeFilter` call) includes spatial args when applicable:
   ```typescript
   const spatialArgs = (acceptedShapes.length > 0 && spatialTarget)
     ? { spatialFilters: acceptedShapes.map((s) => ({ id: s.id, wkt: s.wkt })), spatialTarget }
     : {};
   materializeFilter({ dashboardId, tableId, filters: resolved, combinationKey: hash, ...spatialArgs }, ctrl.signal)
   ```
   The hash already encodes the shapes (Plan 01 4th param), so `combinationKey: hash` is the correct per-spatial-combo dedup key.

### RECORDS DISPOSITION Decision

`"records"` added to `NON_TRIGGER_TYPES`. Rationale:
- `RecordsTableRenderer` (widget.type === "records") is a **separate renderer** from `AggregatedWidgetRenderer` — it reads from `filterViewStore.views[tableId]` (not the combo store) and runs its own already-spatial-correct legacy materialize trigger at `WidgetRenderer.tsx:1918-1955`.
- Pre-Phase-93.5, the orchestrator was minting an orphan `w:<id>` combo view for records widgets that **no renderer consumed** (records doesn't read the combo store).
- Excluding records stops the orphan view, leaves records exactly as-is (self-contained legacy island — read + write + spatial all on filterViewStore), and keeps the sole-trigger invariant scoped to orchestrator-owned paths (charts + layers).
- `"table"` is intentionally **NOT** excluded: `widget.type === "table"` (TableRenderer) is rendered inside `AggregatedWidgetRenderer` and correctly reads the combo store.

### useMapOnlySpatialMaterialize Removal (Task 2)

The orchestrator's STEP A layer enumeration (Phase 92) now enumerates every table-bound layer as `l:<layerId>`. After Task 1's spatial fold-in, every map-displayed table has its spatial combo materialized by the orchestrator. The map-only gap the deleted hook was designed to fill is now fully closed.
