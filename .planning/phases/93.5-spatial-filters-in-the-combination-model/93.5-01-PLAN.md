<objective>
Extend the pure dedup-hash + resolution layer so spatial (map-draw) shapes fold into the
per-combination hash exactly as column filters do, and add the all-or-nothing per-viz spatial
acceptance resolver. This is the FRONTEND-ONLY, dependency-free foundation for SPATIAL-V118-01;
the orchestrator wiring (Plan 02) consumes both functions.

Purpose: A visualization's combination identity must incorporate the spatial shapes it accepts,
so two vizs accepting the same columns + same shapes share ONE view, and a viz excluding spatial
gets a distinct (column-only) view. Order-independence + WKT-only hashing guarantee dedup holds.

Output: Extended `stableComboHash` (optional 4th `shapes?` param), new `resolveSpatialShapes`
pure function, and full unit coverage. Zero server changes, zero new deps, zero store/renderer edits.
</objective>

    import type { Shape } from "../store/spatialFilterStore";
    import type { FilterSelectionConfig } from "../types/filterSelection";
    import { SPATIAL_DRAWS_SENTINEL } from "../components/charts/filterSourceTypes";

    // Pure: all-or-nothing spatial acceptance per visualization.
    // Accept-all (cfg undefined OR sourceMode "all") → all shapes (v1.5/v1.17-identical).
    // Allowlist + SPATIAL_DRAWS_SENTINEL present → all shapes. Otherwise → [].
    // Shapes carry no per-shape sourceWidgetId, so there is NO per-shape selection —
    // the sentinel is a single per-viz "accepts spatial draws" toggle.
    // Never mutates inputs. Returns a slice() so callers cannot mutate the store array.
    export function resolveSpatialShapes(
      cfg: FilterSelectionConfig | undefined,
      allShapes: Shape[],
    ): Shape[] {
      if (cfg === undefined || cfg.sourceMode === "all") return allShapes.slice();
      const accepts = cfg.allowedSourceWidgetIds.includes(SPATIAL_DRAWS_SENTINEL);
      return accepts ? allShapes.slice() : [];
    }
