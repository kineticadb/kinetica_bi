## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline button padding, chip internal spacing |
| sm | 8px | Toolbar button gap (between buttons in the vertical stack), toast gap |
| md | 16px | Section padding, modal body padding |
| lg | 24px | Modal header / major section breaks |
| xl | 32px | Layout outer padding |
| 2xl | 48px | Page-level spacing |
| 3xl | 64px | Page-level spacing (reserved) |

Exceptions:
- **Toolbar button size:** 36px × 36px minimum (matches `.widget-map-toolbar-btn` `min-width: 36px; min-height: 36px` established in Phase 11). Buttons are square icon-only — this is a touch-target exception, not a spacing token.
- **OL zoom control seam:** `MapDrawToolbar` abuts the bottom edge of the OL zoom control with 0px gap. CSS `margin-top: 0` on the overlay container creates the flush join. The OL zoom control height is OL-managed (~64px for two buttons); the draw toolbar's `top` position is calculated to follow it.

> Source: `global.css` established scale (Phase 11 annotation) + `29-CONTEXT.md` toolbar position lock

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13px | 400 (regular) | 1.4 | General UI text, button labels, toolbar `aria-label`, toast messages |
| Label | 12px | 600 (semibold) | 1.4 | Measurement pill text (live tooltip + persistent label), config hints |
| Heading | 16px | 600 (semibold) | 1.2 | Modal titles (reused from existing modal patterns) |
| Display | 13px | 600 (semibold) | 1.4 | Active toolbar button label (screen-reader only; button is icon-only visually) |

> Source: `global.css` `body` (13px/1.4), `.widget-title` (13px/600), `.modal-title` (16px/700), `.config-hint` (12px) — clamped to 3 visible sizes + 2 weights: 400 (body) and 600 (label + heading + display). Font-weight 700 used in existing modals; this phase uses 600 for headings to preserve parity with established heading weight in `29-CONTEXT.md` operator-accepted defaults. Label uses 600 (semibold) rather than 500 to maximise legibility at 12px — the smaller size already differentiates the label role visually.

**Measurement label typography (pill):**
- Font: 12px, weight 600, line-height 1.4
- Color: `#ffffff` (white) on dark semi-transparent background
- No thousand separator; SI spacing (space between number and unit): `2.5 km`, `750 m`, `12.4 km²`
- Decimal precision: 1 decimal for km/km² (`2.5 km`); 0 decimals for m/m² (`750 m`)
- Bbox format: `{W} × {H}` — width first, height second

> Source: `29-CONTEXT.md` Measurement labels & precision (all decisions locked by operator)

## Component Inventory

### New Components

**`MapDrawToolbar.tsx`** — React `<div>` overlay, absolutely positioned.

```
Props: {
  drawMode: DrawMode,         // 'pan' | 'info' | 'bbox' | 'lasso' | 'circle'
  onModeChange: (mode: DrawMode) => void,
  shapesCount: number,
  onClearAll: () => void
}
```

Structure:
```
<div class="map-draw-toolbar" style="pointer-events: none">
  [PanButton]        faHand       aria-label="Pan"
  [InfoButton]       faCircleInfo aria-label="Info"
  [BboxButton]       faVectorSquare aria-label="Draw bounding box"
  [LassoButton]      faDrawPolygon aria-label="Draw lasso"
  [CircleButton]     faCircle     aria-label="Draw circle"
  <div class="map-draw-toolbar-divider" />   (border-top separator, 4px margin)
  [TrashButton]      faTrash      aria-label="Clear all shapes"
                                  (hidden when shapesCount === 0)
</div>
```

CSS class contract:
- `.map-draw-toolbar` — `position: absolute; top: {computed to abut OL zoom bottom}; left: 8px; display: flex; flex-direction: column; gap: 0; pointer-events: none; z-index: 1;`
- `.map-draw-toolbar-btn` — `pointer-events: auto; width: 36px; height: 36px; display: flex; align-items: center; justify-content: center; border: 1px solid var(--border); background: rgba(11,18,36,0.85); color: var(--text); cursor: pointer; transition: background 0.15s, border-color 0.15s;`
- `.map-draw-toolbar-btn.active` — `background: var(--accent); color: #0b1224; border-color: var(--accent);`
- `.map-draw-toolbar-btn:hover:not(.active)` — `border-color: var(--accent); color: var(--accent);`
- `.map-draw-toolbar-divider` — `height: 1px; background: var(--border); margin: 4px 4px;`
- First button (top): `border-radius: 0;` (the OL zoom control's bottom edge provides the visual cap above)
- Last visible button before divider: `border-radius: 0;`
- Trash button: `border-radius: 0 0 8px 8px;` (bottom-rounded to close the unified bar)

> Note on border-radius top: The OL zoom control renders with its own bottom border-radius. The `MapDrawToolbar` top border (first button) should have `border-radius: 0` on its top corners so the seam reads as one bar. If the OL zoom control's bottom is not rounded (theme-dependent), set `border-radius: 8px 8px 0 0` on the first button for a clean top cap.

## Interaction Contract

### Cursor states

| Mode | Cursor | Set Via |
|------|--------|---------|
| Info (default) | `default` | `map.getViewport().style.cursor` |
| Pan | `grab` (active: `grabbing`) | same |
| Bbox / Lasso / Circle | `crosshair` | same |

Cursor set in a standalone `useEffect` with `[drawMode]` deps. Cleanup return resets to `default` (covers mode change + unmount — V15-P-02).

### Mode transitions

| From | Action | To | Side Effect |
|------|--------|----|-------------|
| Any | Click mode button | That mode | `previousMode` updated if moving INTO a draw mode; cursor changes |
| Draw mode | `drawend` fires | `previousMode` (typically Info) | Shape committed, measurement computed, overlay placed |
| Draw mode | ESC keydown | `previousMode` | `draw.abortDrawing()` called; no shape committed |
| Draw mode | Click already-active button | No change | No-op |
| Draw mode | Click Trash | Draw mode preserved; shapes cleared | `clearAll()`, overlays disposed |

### Selection

- Click on committed shape (only in Bbox/Lasso/Circle modes) → selected (4px outline + white halo)
- Click empty map area (in draw mode) → clears selection
- Switching to Info or Pan mode → clears selection
- ESC with selection active → clears selection
- Delete keydown with shape selected → `removeShape(id)`, overlay disposed
- Delete keydown with no selection → silent no-op
- Multi-select: not supported

### Trash button visibility

- Visible only when `shapesCount > 0`
- On click: immediate `clearAll()`, all overlays disposed, toolbar shows no shapes
- No confirmation dialog (matches Phase 28 "remove target = no confirmation" convention)

## Accessibility

- All toolbar buttons: `aria-label` (see Copywriting Contract), `aria-pressed={drawMode === thisMode}` for mode buttons
- Trash button: `aria-label="Clear all shapes"`, `aria-hidden={shapesCount === 0}` when not rendered (or `display: none`)
- Measurement pill: `aria-hidden="true"` — visual affordance only; screen reader information is conveyed via `aria-label` on the toolbar buttons
- ESC keydown: aborts draw + restores mode (keyboard-accessible cancel)
- Delete keydown: removes selected shape (keyboard-accessible delete)
- Focus ring: `outline: 2px solid var(--accent)` via browser default `:focus-visible` (no custom override needed — existing pattern)
- Toast: rendered in `role="status"` `aria-live="polite"` container (existing `Toast.tsx` pattern)
