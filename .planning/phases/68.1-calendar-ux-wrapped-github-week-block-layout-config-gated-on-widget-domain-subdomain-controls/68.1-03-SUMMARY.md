## Decisions Made

- **`blocks` useMemo placement:** must be before early-return render states (loading/error/empty) to avoid "Rendered more hooks than during the previous render" violation — discovered during TDD and fixed inline as Rule 1 (bug).
- **DOW_LABEL_ROWS:** [0, 2, 4] (Mon/Wed/Fri) — derived from WEEK_START=Monday (calendarLayout.WEEK_START); WEEK_START imported into renderer so the dependency is explicit, not hardcoded.
- **Test 31 precise invariant:** checks `patch(` absence and component signature; excludes JSX `onChange={}` prop (event handler not config write).
- **Test 32 uses "week" subdomain:** avoids async timing issues with "hour" (gapFillCalendar may produce empty rows for hour data on CANNED_ROWS); "week" remains a valid month subdomain, CANNED_ROWS still returns data, and the 604_799_999ms span is deterministic.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed hooks-count violation: moved `blocks` useMemo before early-return render states**
- **Found during:** Task 3 (TDD — first vitest run after appending specs)
- **Issue:** `blocks` useMemo was placed after `if (loading)`, `if (error)`, `if (data.length === 0)` early returns. When loading=true, React called fewer hooks than after data loaded, causing "Rendered more hooks than during the previous render" uncaught exception on state transitions.
- **Fix:** Moved `blocks` useMemo immediately after the `grid` useMemo (before any early returns), matching the same pattern as `colorDomain`, `colors`, `useChartAxisColors`.
- **Files modified:** packages/web/src/components/charts/CalendarRenderer.tsx
- **Verification:** All 38 tests pass; no uncaught exceptions in vitest.
