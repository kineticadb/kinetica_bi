<domain>
## Phase Boundary

Two operator-driven UX changes to the (already-shipped) calendar widget:

**(A) Wrapped GitHub week-block layout.** Replace the current flat grid (`columns = domain
buckets × rows = subdomain buckets`, which renders one very tall column for fine subdomains
over few domain groups) with wrapped 2D blocks per domain group, so the calendar is compact
in both dimensions.

**(B) Config-gated on-widget domain/subdomain controls.** A config toggle (default OFF) that,
when ON, renders 2 VIEWER-FACING dropdowns on the widget so a dashboard viewer can switch
domain/subdomain live (re-fetch; enforce the 8 valid combos). Distinct from the Phase 66
operator-only set-once config dropdowns.

Frontend-only (packages/web). Edits the shipped `CalendarRenderer.tsx` (Phase 67) and
`CalendarConfigPanel.tsx` (Phase 66). New requirement IDs to add: **CALUX-V113-01** (wrapped
layout), **CALUX-V113-02** (on-widget interactive controls).

</domain>

<decisions>
## Implementation Decisions

### (A) Wrapping geometry — per subdomain
Each domain group becomes a 2D block; cell (x,y) is computed from the cell's DATE
(`subdomainKey`), not a flat row index.
- **day** (month×day, year×day, week×day): **7-row day-of-week × week columns** (classic
  GitHub). month×day → ~5 week-cols; year×day → ~52; week×day → 1 col. Rows = day-of-week.
- **hour** (day×hour, week×hour): **compact grid block** (~4 rows × 6 cols for 24 hours).
- **week** (year×week, month×week): **compact grid** — year×week (52) wraps into rows
  (e.g. ~13×4); month×week (4–5) short row/col.
- **month** (year×month): **compact grid** — 3×4 / 4×3 year grid.

### (A) Macro layout — domain-group arrangement
- **Separate labeled blocks**, each its own spaced block with a group label (e.g. "Mar 2026"),
  flowing **left→right then wrapping** to the next row when width runs out (set of mini-calendars).
- **NEW config option: layout mode = Wrap (default) | Continuous strip.** Continuous = blocks
  side-by-side in one horizontal strip (GitHub year view), horizontal-scroll if wide; no vertical
  wrap. Operator picks.
- **Week-start day:** match the Kinetica `DATE_TRUNC` week anchor used by the SQL bucketing
  (Phase 65). ⚠ That anchor (Mon vs Sun) is still NOT-YET-VERIFIED (`KINETICA_DATE_TRUNC_UNITS`
  annotation in calendarBin.ts; Phase 69 spike). **Interim fallback: Monday-start (ISO 8601)** if
  the spike hasn't run at build time — keep the week-start in ONE constant so Phase 69 can correct it.
- **Axis labels:** day-of-week labels (sparse: Mon/Wed/Fri) down the left; each domain group's
  label above its block. (Replaces the current top domain-axis + left subdomain-axis scheme.)

### (B) On-widget dropdowns
- **Placement:** a thin **control bar at the top of the widget body**, above the SVG/legend,
  holding Domain + Subdomain dropdowns (reuse the config `ds-select` styling).
- **Init + gating:** Domain defaults to the operator's configured `domain`; Subdomain to
  configured `subdomain`. Subdomain options are **dependent** — only valid subdomains for the
  chosen domain (`VALID_DOMAIN_SUBDOMAIN` / `isValidCombo`), same gating as the Phase 66 panel.
  Changing either **re-fetches** (new buildCalendarSql with the chosen domain/subdomain).
- **Persistence: VIEW-LOCAL.** The viewer's selection lives in component state ONLY — it does
  NOT write back to the saved widget config. On reload the widget returns to the operator's
  configured default. Non-destructive exploration.

### (B) Config toggle + Display section
- **New config field** (e.g. `showDomainSubdomainControls: boolean`), checkbox labeled exactly
  **"Show domain/subdomain controls"**, **default OFF (false)**, with an **info icon** beside it
  whose hover tooltip gives a friendlier, more detailed description (e.g. "When on, viewers get
  dropdowns on the widget to change the time grouping live, without editing the widget").
  No shared Info-icon component exists → use a native `title` attribute on a small "ⓘ" glyph
  (theme-safe, minimal); a richer tooltip only if trivially available.
- **Placement:** a NEW **"Display"** section in `CalendarConfigPanel`, AFTER the existing
  domain/subdomain/metric/palette fields, grouping BOTH new options: the layout mode
  (Wrap / Continuous strip) AND the "Show domain/subdomain controls" toggle.
- **OFF state (default):** no dropdowns; widget renders the static grid at the operator's
  configured domain/subdomain (today's behavior + the new wrapped layout). OFF only hides the
  controls — it never changes the grid.

### Carried-forward invariants (unchanged this phase)
- Theme tokens only — no raw hex in CalendarRenderer.tsx / CalendarConfigPanel.tsx (theme-guard).
- CalendarRenderer NEVER imports `materializeFilter`/`dropFilterView`/`fromSwap` (sole-trigger).
- Cell-drill (Phase 68), gap-fill, color scale, FROM resolution + `respondToFilters` toggle
  (Phase 68) all stay; the wrapped layout must preserve them (the active-cell highlight, drill
  click, empty-cell non-interactivity carry over to the new cell positions).
- 8 valid combos + cap (calendarBin.ts) unchanged.

### Claude's Discretion
- Exact field names in code (labels "Show domain/subdomain controls", "Wrap"/"Continuous strip"
  locked; field identifiers are the planner's).
- Pixel math: block dimensions, gaps between blocks, responsive cell sizing, wrap breakpoints,
  hour/week/month grid exact rows×cols.
- Empty-block / partial-week handling (leading/trailing blanks in a month's week grid).
- Info-tooltip exact wording.
- Whether layout-mode is a 2-option select or a checkbox.

</decisions>

<specifics>
## Specific Ideas

- Operator saw the live Phase 67 calendar render as "everything in one line / too long
  vertically" — root cause is the flat `domain-column × subdomain-row` grid; GitHub week-block
  wrapping is the fix.
- "2 dropdowns on the visual" so viewers apply different week/month/day groupings as they need —
  but only when an operator opts in (config toggle), default OFF.
- Layout should default to wrapped mini-calendar blocks, but continuous-strip is available as an
  option.

</specifics>
