# Phase 109.1: Filter Scope for Custom-Panel Charts Summary

**Threaded `widgetId` through `ConfigPanelProps` and wired the existing `FilterSelectionPanel` into Calendar/Timeline/NumericLine config panels, closing the last gap where those three chart types had no per-visualization filter-scope control.**

## Performance

- **Duration:** ~25 min
- **Started:** 2026-07-10T19:00:00Z (approx.)
- **Completed:** 2026-07-10T19:18:03Z
- **Tasks:** 2 completed
- **Files modified:** 8 (2 shared + 3 panels + 3 specs)

## Accomplishments
- `ConfigPanelProps.widgetId?: number` added and forwarded from `ChartConfigPanel`'s `<Custom>` slot render, giving custom panels the widget's own id for self-exclusion (mirrors the generic body's `selfWidgetId={widgetId}` usage).
- `FilterSelectionPanel` now renders in `CalendarConfigPanel`, `TimelineConfigPanel`, and `NumericLineConfigPanel` — each wired to `config.filterSelection` via the panel's own `patch()` auto-save helper, with the same source-widget allow-list, `selfWidgetId`, `allowSpatial`, and `dvFilterScopeDisabled` dv-bound gate as the generic `ChartConfigPanel` body.
- Calendar's dv-bound instance correctly hides the control when the operator-level `dvFilterScopeDisabled` flag is set, matching bar/pie/table's existing behavior exactly.
- bar/pie/table (served by the generic `ChartConfigPanel` body) were not touched — `git diff --name-only` confirms only `registry.ts`, `ChartConfigPanel.tsx`, and the three custom panels + their specs changed.

## Decisions Made
- Filter Scope block placed as the **last** visible section in each panel, consistent across all three, per the plan's explicit instruction.
- Timeline/NumericLine add a `dynamicViewId = cfg.dynamicViewId` local (always `undefined`) purely to keep the FilterSelectionPanel-wiring expression byte-for-byte identical to Calendar's and to the generic `ChartConfigPanel` usage, rather than special-casing those two panels — reduces future drift risk if a dv picker is ever added to Timeline/NumericLine.
