**1. A shared JSON-string reader** — `cb_config`, `track_config` and (Task 3) `info_columns` are
all TEXT columns holding JSON:

```ts
const readJsonString = (raw: string | null): { parsed: unknown; malformed: boolean } => {
  if (raw === null || raw.trim() === "") return { parsed: undefined, malformed: false };
  try { return { parsed: JSON.parse(raw), malformed: false }; }
  catch { return { parsed: undefined, malformed: true }; }
};
```

**2. The malformed-JSON fallback — the rule that keeps a corrupt blob from erasing a reference.**
When `malformed` is true, do NOT return silently and do NOT throw. Instead run
`scanFreeSql(raw, column)` over the RAW string and emit ONE finding at the site that owns the
record's primary column-bearing field (`layer.cb_config.attr` for `cb_config`,
`layer.track_config.trackIdAttr` for `track_config`, `layer.info_columns` for `info_columns`),
with:
- `confidence: "heuristic"` (or `"low-confidence"` per `isLowConfidenceColumnName`) — the exact
  path could not be proven, so the claim is downgraded;
- `tableId` / `tableScope` from the record's `resolved` — the RECORD's table is still known, so
  this is NOT a free-SQL finding and must not be marked `"free-sql"`;
- `matches` from `scanFreeSql`, so Phase 124 can show the operator the corrupt text.

Rationale, and write it into the comment: `coalesceTrackConfig` in
`packages/web/src/lib/trackConfig.ts` returns `{ enabled: false }` on a parse failure — it SWALLOWS
the error, which is right for a renderer and catastrophically wrong for an impact report. A
malformed blob that silently reports zero references is precisely the confidently-incomplete
outcome this phase exists to prevent. 123-CONTEXT.md's discretion clause is explicit: fail toward
REPORTING a match; a missed finding is the expensive failure and a false positive is merely noise.

Then AMEND the `matches` doc comment on the `ColumnRef` type (written by Plan 123-01) to name this
third case, so the contract text stays true:
`// ... EMPTY for value-equality sites ... and NON-EMPTY for a JSON-string site whose stored JSON
failed to parse (malformed-JSON fallback, Plan 123-03).`
