Popstate is not vetoable. Design (MEDIUM confidence, 134-RESEARCH Q6): when `view.mode === "open"` and `hasUnsavedAiChanges()`, re-push the dashboard entry with `openDashboardUrl(view.dashboard.id)` (marked as ours, so a later `leaveDashboardUrl()` pops it), keep the view, and `requestLeave(() => { leaveDashboardUrl(); setViewState({ mode: "list" }); onViewChange?.("list"); })`. On "Discard and leave" the dialog resets the session BEFORE calling proceed, so the popstate fired by `leaveDashboardUrl()`'s `history.back()` sees a clean session and takes the normal path. FALLBACK if the re-push misbehaves in jsdom or the operator's browser: show the dialog without restoring the URL, and on Stay call `openDashboardUrl` then. Record which variant shipped in the SUMMARY; 134-09 checks it in a real browser.

`beforeunload`: an effect keyed on the dirty boolean (selector `selectHasUnsavedAiChanges`) registers ONE handler that re-reads `hasUnsavedAiChanges()` at event time and calls `e.preventDefault(); e.returnValue = "";`. Symmetric add/remove keeps StrictMode (mount -> cleanup -> mount, main.tsx:14) at exactly one listener. Never put `reset()` in a mount effect.
