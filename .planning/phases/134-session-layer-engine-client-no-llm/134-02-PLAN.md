<objective>
Build the pure core of the session layer: the type contracts, an apply-time evaluator that records each op as applied or skipped, a pure `foldSession` that turns a log prefix into derived added/removed/patched entities, and ref-stable merge helpers for the read sites.

DESIGN DEVIATION (recorded on purpose, do not "fix"): milestone PITFALLS C7 prescribes a command pattern with inverse ops. This phase uses op-log + cursor + pure fold instead (134-RESEARCH "Summary", "Alternatives Considered"). The saved dashboard (`widgets` state, `dashboardLayersStore`, dv list) is never mutated, so revert/forward is "fold a different prefix" and Discard is "drop the log". D-01's "inverse/snapshot data" is satisfied by replayability. Inverses would be dead code and a bug surface.

Scope for 134 (D-17, CONTEXT out-of-scope): `add_dynamic_view`, `remove_dynamic_view`, `apply_filter`, `clear_filter` are recorded `skipped: "unsupported_in_134"` (Phases 139/138 own them). `add_layer` uses a minimal default-filled builder `makeSessionLayer` that Phase 136 replaces. Per-type `add_widget` config validation is Phase 136.

Purpose: AISES-V20-02 (turn 2 builds on turn 1) and AISES-V20-03 (any prefix is reconstructible).
Output: `lib/aiSession/{types,constants,foldSession,applySession}.ts` + specs; `splitLayerSnapshot` exported.
