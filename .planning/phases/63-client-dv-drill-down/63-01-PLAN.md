<objective>
Add dv-scoped parallel slices to the two filter stores so a dynamic-view drill-down can be keyed by `dynamicViewId` without ever colliding with a `tableId` (both are numbers). This is the foundation the bug fix stands on: the current bug is that a dv drill lands in `filters[tableId]` because there was no dv-keyed home for it.

Purpose: A dv id and a table id are BOTH numbers — `filters[dvId]` would collide with `filters[tableId]`. The LOCKED approach (63-CONTEXT.md `<decisions>`) is PARALLEL dv-keyed slices, NOT re-keying the existing maps. The existing table path stays byte-unchanged (lowest-risk); composite-string re-keying is the rejected alternative.

Output: `useFilterStore` gains `dvFilters: Record<number, ActiveFilter[]>` + `addDvFilter/removeDvFilter/clearDvFilters`; `useFilterViewStore` gains `dvViews: Record<number, FilterViewEntry>` + `setDvView/markDvMaterializing/clearDvView`; both `reset()` impls zero the new slices (satisfies DVDRILL-V112-05 lifecycle with NO new reset call sites — App.tsx ~89-90 + DashboardsPage.tsx ~479-480 already call reset()).
</objective>

```typescript
export type ActiveFilter = {
  column: string;
  value: string | number | boolean | Date | null | (string|number)[] | [number,number] | [string,string];
  dataType: "string" | "number" | "boolean" | "datetime" | "null";
  operator?: "eq" | "in" | "between" | "isNull";
  sourceWidgetId?: number;
  addedAt: number;
};
export const FILTER_CAP_PER_TABLE = 25;
export type FilterState = {
  filters: Record<number, ActiveFilter[]>;   // keyed by tableId
  filterVersion: number;
  addFilter: (tableId: number, filter: ActiveFilter) => void;
  setBulkFilters: (tableId: number, filters: ActiveFilter[]) => void;
  removeFilter: (tableId: number, column: string) => void;
  clearFilters: (tableId: number) => void;
  reset: () => void;
};
// reset today: () => set({ filters: {}, filterVersion: 0 })
// addFilter logic: cap check (FILTER_CAP_PER_TABLE), exact-dup dedupe (silent no-op),
//   same-column-different-value REPLACE, bump filterVersion on real change.
// removeFilter / clearFilters: no-op (no version bump) when nothing changes; clearFilters uses delete-key semantics.
```

```typescript
  viewName: string;
  expiresAt: number;

export type FilterViewState = {
  views: Record<number, FilterViewEntry>;     // keyed by tableId

  setView: (tableId, { viewName, expiresAt }, dashboardId) => void;
  clearView: (tableId) => void;
  markMaterializing: (tableId, dashboardId) => void;
  clearMaterializing: (tableId) => void;
  bumpMaterializeVersion: (tableId) => void;
  reset: () => void;
};

// clearView uses delete-key semantics + no-op when absent.
```
