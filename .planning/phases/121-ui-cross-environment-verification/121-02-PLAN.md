POST it, and then read the FULL import report.

Purpose: DXIM-V124-10 exists because of an operator decision recorded in Phase 120's CONTEXT: when a

succeeded" throws away exactly the thing the operator agreed to watch for.

interface ImportDashboardModalProps {
  onClose: () => void;
  /** Called once, after a successful import, with the report. DashboardsPage uses it to refetch

}

**Two phases in ONE modal shell** (`modal-overlay` > `modal-content` > `modal-header` + `modal-body`),
switching on `report === null`:

*Phase A — pick (report is null).* `modal-title` = `"Import dashboard"`. Header carries the
`ghost-sm` Close. Body:
```tsx
<div className="muted" style={{ marginBottom: "12px" }}>
  Choose a dashboard export file (.json) produced by Export on another environment.
</div>
{error && <div className="error">{error}</div>}
<div className="ds-field">
  <span className="ds-field-label">Import file</span>
  <input type="file" accept="application/json,.json" aria-label="Import file"
         onChange={(e) => { setError(null); setFile(e.target.files?.[0] ?? null); }} />
</div>
<div className="ds-actions">
  <button className="btn-primary btn-sm" disabled={!file || busy} onClick={handleImport}>
    {busy ? "Importing…" : "Import"}
  </button>
  <button className="ghost-sm" onClick={onClose}>Cancel</button>
</div>
```
`btn-primary btn-sm` + `ghost-sm` inside `ds-actions` is CLAUDE.md's canonical matched-height action
pair. Bare `btn-primary` next to `ghost-sm` is the WRONG combo — do not use it.

`handleImport`: `setBusy(true); setError(null);` then `await importDashboardFile(file)`; on success
`setReport(r); onImported(r);` in a `finally` `setBusy(false)`. On throw
`setError((err as Error).message)` and leave `report` null so the picker stays available.

*Phase B — report (report is non-null).* `modal-title` = `` `Import report: ${report.dashboardName}` ``.
Header carries the `ghost-sm` Close. Body sections, in this order:

1. `<h3 className="modal-section-title">Created</h3>` then a `datasets-table` of `ds-row`s with
   `style={{ gridTemplateColumns: "1fr auto" }}`: `Dashboard id` / `{report.dashboardId}`,
   `Widgets` / `{report.widgetsCreated}`, `Layers` / `{report.layersCreated}`,
   `Dynamic views` / `{report.dynamicViewsCreated}`.
2. `modal-section-title modal-section-title-spaced` `Tables`. One `ds-row` per entry:
   `tablesMatched` rendered with a `<span className="muted">matched</span>` right cell,
   `tablesCreated` with `created`. Left cell is `t.tableRef`. Key on
   `` `matched-${t.newId}` `` / `` `created-${t.newId}` `` — oldId collisions across the two arrays
   are possible, newId is not, but prefix anyway.
   If BOTH arrays are empty render `<div className="muted">No tables in this file.</div>`.
3. `Custom metrics` section, same shape, over `metricsMatched` / `metricsCreated`, left cell
   `` `${m.label} — ${m.tableRef}` ``.
4. **Metric conflicts** — render ONLY when `report.metricConflicts.length > 0`:
```tsx
<h3 className="modal-section-title modal-section-title-spaced">
  Metric conflicts — review before trusting these widgets
</h3>
{report.metricConflicts.map((c) => (
  <div key={`conflict-${c.newId}`} className="error" style={{ marginBottom: "8px" }}>
    {c.message}
  </div>
))}
```
   `{c.message}` and nothing else. No `.slice()`, no `.length`, no "N conflicts" summary anywhere in
   this component. `.error` is the existing "needs attention" signal.
5. **Warnings** — only when `report.warnings.length > 0`: `modal-section-title
   modal-section-title-spaced` `Warnings`, then one `<div className="muted">{w}</div>` per string,
   keyed by index. Verbatim. This is where `layerFilterWidened` surfaces.
6. **Stripped references** — only when `report.strippedReferences.length > 0`: section title
   `References removed`, one `ds-row` per entry, left cell
   `` `${s.from} — ${s.kind} #${s.id}` ``, right cell `<span className="muted">removed</span>`.
7. **Pre-flight dangling** — only when `report.preflightDangling.length > 0`: section title
   `Dangling references found before import`, same `ds-row` shape.
8. A final `<div className="ds-actions">` with a single `ghost-sm` `Done` button calling `onClose`.
