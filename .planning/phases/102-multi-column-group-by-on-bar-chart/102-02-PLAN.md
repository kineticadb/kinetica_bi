<objective>
Extend the generic `ChartConfigPanel` with a BAR-ONLY multi-column group-by builder (add/remove ordered column rows, adapting the `NumericLineConfigPanel` metrics[] pattern) and a multi-column `generatedSql` branch, while keeping the single-`groupByColumn` select — and the byte-identical single-column SQL — for the ≤1 case and for every other chart type.

Purpose: The bar chart already uses the generic `ChartConfigPanel`, where Phase 98 `whereCustomWhere`, Phase 100 `metricId`/`resolveMetricExpr`, Phase 101 `yAxisScale` passthrough, and the sort/limit controls all live cohesively inside `generatedSql` (~312-386). Forking a new `BarConfigPanel` would force re-implementing (and risk regressing) those three just-shipped phases. We EXTEND instead — a conditional bar-specific control + a conditional SQL branch — so all existing bar wiring keeps flowing unchanged.

**Panel approach (stated per steering):** EXTEND `ChartConfigPanel` — chosen because the bar's Phase 98/100/101 wiring and `generatedSql` are already cohesive there; a fork would duplicate the metric picker, custom-metric resolution, custom-WHERE injection, and yAxisScale passthrough. The multi-column builder is gated on `widgetType === "bar"`; the multi-column SQL branch is gated on `isMultiColumnBarGroupBy(draft)`.

Output: bar config field + builder UI + multi-column SQL branch + backward-compat + generatedSql specs.
</objective>
