## Summary

Phase 58.1 goal is fully achieved. The three structural defects from Phase 58 are all corrected:

1. **Allow-list field name fixed:** `render_mode` (snake) is gone; `renderMode` (camelCase) is the allow-listed key with location `"layer.config"`. `track_config`/`cb_config` correctly retain location `"layer"`. `visible`/`opacity` correctly declare location `"layer.config"`. `ALLOW_LIST_VERSION` bumped to `"v2"`.

2. **Location-aware routing:** `applyWidgetAction` uses `splitLayerPatch` (from allow-list, no hardcoded names) to produce a DTO-shaped overlay. Config fields go under a `config` sub-object; top-level fields stay top-level. Pre-write config deep-merge prevents the store's depth-1 merge from clobbering prior nested config keys on repeated patches. Idempotency compares deep-merged effective layers. Dangling-safety, rejection, and TRANSIENT-ONLY are all intact.

3. **Deep-merge effectiveLayers:** The flat spread in `MapChartRenderer.tsx` is replaced with `{ ...l, ...topLevel, config: { ...l.config, ...cfgPatch } }`. `config.renderMode` now actually changes when a renderMode overlay is applied.

4. **Render-mode canary (CASE C):** Three tests prove the nested-config path end-to-end on a mounted map. CASE A (widget.config) and CASE B (top-level track_config/cb_config) remain green. 1849/1849 vitest, tsc clean, zero server diff.
