# Phase 118 — Zoom-Aware Layer Legend — Operator Walkthrough

**What was built:** A third, distinct visual state in the layers legend (in-map panel AND the
standalone Legend widget) — "zoom-inactive" — for a layer whose configured `[minZoom, maxZoom]`
range does not include the map's current zoom. The legend now reads the map's LIVE fractional
zoom reactively (via `mapCurrentViewStore`, keyed by widget id), so the panel tracks the map with
no reload and no re-open. As a deliberate side effect, the info-click gate was fixed to use the
exact same zoom-range formula OpenLayers uses internally, so a layer visibly drawn at a fractional
zoom (e.g. 2.9 with `minZoom: 3`) now responds to clicks — previously it silently did not.

This UAT record is BLOCKING: three of this phase's requirements are not honestly
machine-checkable in this repository (see `118-03-PLAN.md`'s "why this checkpoint is blocking"
note) — the CSS opacity tokens chosen are not provably legible by any automated gate, "three
different things at a glance" is a perceptual claim, and the harness's store mock cannot prove a
real zustand auto-re-render. The operator's eyes are the only guard on those three claims.

## Setup (once, before any check below)

Open a dashboard with a map widget that has at least FOUR layers, configured via the Layers
panel so that:
  - **L1** — no zoom range at all (minZoom/maxZoom unset). Regression canary.
  - **L2** — zoom range 3-10.
  - **L3** — zoom range 12-18.
  - **L4** — zoom range 3-10, eye toggled OFF.

Turn ON the map widget's "Layers panel" option so the in-map legend renders. Zoom the map to
roughly zoom 8.

Record PASS / FAIL / NOT-EXERCISED per check below, verbatim, plus a one-line note for any FAIL.

## Checks

### UAT-118-A. Regression canary — a layer with no configured range looks untouched (ZLGND-V123-07)
expected: Look at **L1**. PASS = L1 looks EXACTLY as it did before this phase — normal
brightness, no coloured left rule, and NO chip of any kind next to its name. Most layers in real
dashboards have no configured range, so a regression here is the most visible possible failure.
Result: PASS. L1 (no configured range) renders exactly as before this phase — normal
brightness, no coloured left rule, no chip. This was the highest-visibility regression risk
since most layers in real dashboards carry no configured range, and it held.

### UAT-118-B. Active vs zoom-inactive, and the range chip (ZLGND-V123-01/03)
expected: At zoom ~8: **L2** looks ACTIVE (normal brightness) and carries a chip reading
`zoom 3–10`. **L3** looks ZOOM-INACTIVE (faded, coloured left rule) and carries a chip reading
`zoom 12–18`. PASS = you can tell at a glance which of L2/L3 the map is actually drawing, and the
chip tells you what zoom would bring L3 back.
Result: PASS. At zoom ~8, L2 reads active (normal brightness, chip `zoom 3–10`) and L3 reads
zoom-inactive (faded, coloured left rule, chip `zoom 12–18`). At a glance it is clear which
layer the map is actually drawing, and the chip states what zoom would bring L3 back.

### UAT-118-C. Live update — no reload, no re-open (ZLGND-V123-04)
expected: WITHOUT reloading the page and WITHOUT collapsing/re-opening the panel, scroll-zoom in
to about zoom 14. L2 and L3 must SWAP states (L2 fades, L3 becomes normal). Zoom back to ~8 and
confirm they swap back. PASS = the panel tracks the map live. FAIL = a reload or panel re-open is
needed to see the change, or it only updates after some other interaction. Also note whether the
swap happens smoothly at the end of each zoom gesture (expected — the store publishes on
`moveend`, not continuously) or feels laggy/stuck.
Result: PASS. Scroll-zooming in to ~14 without reloading or re-opening the panel swapped
L2/L3 states (L2 faded, L3 normal); zooming back to ~8 swapped them back. The panel tracks the
map live, updating smoothly at the end of each zoom gesture (moveend-driven, as expected) —
not laggy or stuck.

### UAT-118-D. Zoom-inactive vs eye-off must NOT look the same — DARK THEME (ZLGND-V123-02)
expected: In dark theme, at zoom ~8, compare **L2** (active), **L3** (zoom-inactive), **L4**
(eye-off) side by side. PASS only if all THREE read as three different things without having to
think about it. FAIL if L3 and L4 are hard to tell apart. Also confirm L3's left rule colour is
clearly visible against the panel background, and its chip text (`zoom 12–18`) stays fully
legible despite the row being faded.
Result: PASS. In dark theme, at zoom ~8, L2 (active), L3 (zoom-inactive), L4 (eye-off) all
read as three distinct things without having to think about it. L3's left rule is clearly

allowlists `global.css` and only ever asserts hex IS present there, never that it is absent —
and it held.
