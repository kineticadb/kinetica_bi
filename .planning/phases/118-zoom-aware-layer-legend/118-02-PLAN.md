<decisions_locked_for_this_plan>
These resolve RESEARCH's two open questions. They are decided; do not re-litigate.

**D1 — Precedence is computed in JS, mutually exclusive, never left to the CSS cascade.**
`showZoomInactive = visible && !stale && zoomActive === false`. A layer that is eye-off OR
dv-stale keeps exactly its existing treatment; the zoom-inactive treatment never stacks on top.
Rationale: `.hidden` and `--stale` already resolve against each other by pure `global.css` SOURCE
ORDER (same specificity), which is an accident, not a design. Adding a third independent boolean
would compound that. Mutual exclusion also makes `ZLGND-V123-02` ("must not look the same as
eye-off") true by construction rather than by visual judgement.

**D2 — The range chip renders whenever `zoomActive !== undefined`** — i.e. the range is configured
AND the current zoom is known — regardless of active/inactive, and regardless of hidden/stale.
Rationale: the operator's locked wording ("a zoom-limited layer shows its configured range") is
unconditioned, and gating on `inactive` would make the chip pop in and out exactly as the operator
zooms across the boundary trying to read the panel. Keying on `zoomActive !== undefined` rather than
`zoomRange !== undefined` is what makes `ZLGND-V123-06` free: zoom-unknown shows no chip.
(Note the existing `.hidden` / `--stale` rules already dim `.layers-legend-panel-mode-chip`, so a
chip on an eye-off row inherits the correct dimming with no new CSS.)

**D3 — Chip copy is locked** (both wire bounds are INCLUSIVE, so `≥`/`≤`, NOT `breakDisplayText`'s
exclusive-upper `<`):
  - both bounds:   `zoom 3–10`   (EN DASH U+2013, no surrounding spaces)
  - minZoom only:  `zoom ≥ 3`
  - maxZoom only:  `zoom ≤ 10`
The en dash is already used in assertions in `LayersLegendPanel.spec.tsx` (6 occurrences), so it is
proven safe in this file's tests.

**D4 — The chip REUSES `.layers-legend-panel-mode-chip` verbatim.** Per CLAUDE.md, never invent a
class for something that already exists: this is a small muted informational chip in the exact right
slot, already token-based, and currently dead code. Its doc comment must be updated in the same
commit. Six existing assertions in `LayersLegendPanel.spec.tsx` (lines 72, 83, 105, 123, 242, 262)
assert this class is `null` — confirmed safe because that spec file contains **0** occurrences of
`minZoom`/`maxZoom`, so none of those fixtures can produce a chip. **Verify that, do not assume it.**
