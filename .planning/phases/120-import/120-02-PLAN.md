which target rows do its tables and custom metrics resolve to.

Purpose: DXIM-V124-11 requires a rejected file to change NOTHING. The cheapest possible way to

"changes nothing" is trivially true rather than dependent on rollback working. DXIM-V124-06 and -07
are the two places where import deliberately does NOT create a fresh row: tables match by
`schema.name`, metrics match by label. Both matching rules have a failure mode that is silent, so

**Two-tier validation — from research Q6, adopted.**
- Tier 1 STRUCTURAL → REJECT. Wrong top-level types, a missing required key, a non-numeric id where
  a number is required, an unsupported `schemaVersion`, a duplicate id within a collection. Rejection

**Tier 1 — structural.** Implement with a small private `fail(code, message)` returning the rejection
shape, and a `reject` path that returns IMMEDIATELY on the first problem (fail fast — one clear
message beats a list). Use these two codes only:
  - `"UNSUPPORTED_SCHEMA_VERSION"` — message exactly of the form
    `Unsupported schemaVersion: 2 (this build supports 1).` Build the supported list from
    `SUPPORTED_IMPORT_SCHEMA_VERSIONS.join(", ")` so it cannot drift.
  - `"IMPORT_MALFORMED"` — message of the form
    `Import file is malformed: <path> <expectation> (got <actualType>).`
    e.g. `Import file is malformed: widgets[0].config must be an object (got string).`

Checks, in this order:
  1. `isPlainObject(raw)` else reject (`path` = the body itself).
  2. `asId(raw.schemaVersion)` is defined; then membership in `SUPPORTED_IMPORT_SCHEMA_VERSIONS`.
  3. `raw.dashboard` is a plain object; `dashboard.name` is a non-empty string.
     (`dashboard.id` is read for nothing but provenance — import ALWAYS allocates a new id — but
     still require it to be a positive integer so a mangled file is caught.)
  4. Each of `widgets`, `layers`, `dynamicViews`, `tables`, `customMetrics`, `dashboardTableIds` is
     `Array.isArray`. A MISSING key is a rejection, not an empty default — a file that lost a whole
     collection is exactly the hand-edited case DXIM-V124-11 names.
  5. Per-element checks (report the index in the path):
     - `tables[i]`: `id` positive int; `name` non-empty string; `schema` string (empty string is
       LEGAL — the DDL defaults it to `''`); `columns` a plain object.
     - `widgets[i]`: `id` positive int; `title` string; `type` non-empty string; `position` a number;
       `config` a plain object.
