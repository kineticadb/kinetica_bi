# Phase 63.1 Plan 01: Map-Layer DV-Filter FROM-Swap Summary

**One-liner:** WMS map layers FROM-swap to filtered-dv view (`_kbi_filt_…`) when a dv drill-down is active, using `dvFilter.materializeVersion` as `_mv`, via filtered-dv→raw-dv→skip precedence at both Effect 2 + Effect 3 `buildWmsParams` call sites, with a new `dvFilterViewsKey` re-render subscription.

## What Was Built

**Gap closed:** Phase 64 live UAT — WMS map layers bound to a dynamic view were stuck rendering the raw dv view (`_kbi_dv_…`) even when a dv drill-down filter had been materialized. Root cause confirmed: `MapChartRenderer` built the `dynamicViewEntry` arg at both `buildWmsParams` call sites only from `useDynamicViewStore` (raw dv), never consulting `useFilterViewStore.dvViews[dvId]`. The `dynamicViewsKey` re-render subscription also did not move when the filter store changed.

**Fix applied (DVDRILL-V112-02/-04):**

1. `dvFilterViewsKey` selector added (~line 609) — mirrors `viewsKey` but over `useFilterViewStore.dvViews`, scoped to `includedLayers'` dv ids, sorted ascending. Added to dep arrays of both Effect 2 and Effect 3.

2. Effect 2 (~line 1215-1222): filtered-dv precedence block inserted before `buildWmsParams` call. Reads `useFilterViewStore.getState().dvViews[layer.dynamic_view_id]`, checks `materializing === false` + non-empty `viewName`, overrides `resolvedDvEntry = { status: "materialized", viewName: dvFilter.viewName }` + `resolvedDvVersion = dvFilter.materializeVersion`. Falls through to raw-dv path when inactive.

3. Effect 3 (~line 1462-1469): identical precedence block. Existing `if (entry?.materializing) continue;` table suspend gate left unchanged — orthogonal to dv branch.
