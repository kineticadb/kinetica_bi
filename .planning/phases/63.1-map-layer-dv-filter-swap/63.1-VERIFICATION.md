### Gap-Closed Proof (Phase 64 UAT Gap)

The Phase 64 live UAT gap was: a dv-backed WMS map layer kept emitting `LAYERS=_kbi_dv_uadmin_d5_3` (the raw dv view) even when a dv drill-down filter had been materialized. Root cause: `MapChartRenderer` built `dynamicViewEntry` for both `buildWmsParams` call sites from `useDynamicViewStore` only — never consulting `useFilterViewStore.dvViews[dvId]`. The `dynamicViewsKey` subscription also did not move on filter-store changes.

Fix confirmed in code:
1. `dvFilterViewsKey` selector (line 609) reads `useFilterViewStore` `dvViews` slice — NOT `dynamicViewStore` — ensuring the React component re-renders when a dv-filter is applied or cleared.
2. Precedence block at Effect 2 (lines 1210-1223): when `dvFilter.materializing === false` AND `dvFilter.viewName` non-empty, overrides `resolvedDvEntry` to the filtered-dv view and `resolvedDvVersion` to `dvFilter.materializeVersion`.
3. Identical block at Effect 3 (lines 1458-1470): closes the second render path (the `updateParams` re-fire path) — a fix to only one effect would leave the other path stuck.
4. `dvFilterViewsKey` in both dep arrays (lines 1430, 1507): guarantees both effects re-fire on apply/clear/re-materialize.
