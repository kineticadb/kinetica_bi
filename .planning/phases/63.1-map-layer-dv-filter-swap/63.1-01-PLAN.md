<objective>
A WMS map layer bound to a dynamic view FROM-swaps its rendered tiles to the filtered-dv view (`_kbi_filt_…_dv<id>_s…`) when a chart/table drill-down has materialized a dv-filter, and reverts to the raw dv view (`_kbi_dv_…`) when cleared — so map widgets update LIVE in lock-step with the dv-bound charts.

This closes the Phase 64 live-UAT gap: dv drill-down works for charts/tables (Phases 62/63) but a WMS map layer bound to the same dynamic view keeps rendering the UNFILTERED dv view. Root cause (confirmed): MapChartRenderer builds the `dynamicViewEntry` arg for `buildWmsParams` at BOTH call sites (Effect 2 ~1186-1193, Effect 3 ~1418-1425) from `useDynamicViewStore` (raw dv) ONLY — it never consults `useFilterViewStore.dvViews[dvId]`. And the `dynamicViewsKey` re-render subscription tracks the raw dv store only, so it does not move when the filter store changes — the map is stuck.

Purpose: complete DVDRILL-V112-02 (every widget bound to the SAME dv re-renders to the filtered slice) + DVDRILL-V112-04 (filtered-dv → raw-dv read-path FROM-swap) for the MAP render path, which Phase 63 wired only for the chart/records WidgetRenderer.
Output: filtered-dv precedence at both call sites + a `dvFilterViewsKey` subscription, fully regression-locked. FRONTEND-ONLY (`packages/web`); ZERO `packages/server` diff.
