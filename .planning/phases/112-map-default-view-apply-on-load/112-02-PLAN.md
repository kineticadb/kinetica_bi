  <how-to-verify>
    Run the app (`npm run dev` for web, `npm run dev:server` for the API) and work through these four checks. Check 1 is the one that genuinely needs eyes.

    **Check 1 — MAPVIEW-V121-02: no visible world-view flash.** *(the important one)*
    1. Open a dashboard with a map widget. Pan/zoom the map to a recognisable place (e.g. a city) and note it.
    2. Open that widget's config → `DEFAULT VIEW` → click `Set as default — zoom … · …°N, …°W`. Close the config modal.
    3. Hard-reload the page (Cmd-Shift-R / Ctrl-F5).
    4. **Watch the map's very first paint closely.** Expected: the map appears already framed on your saved location. You should NOT see the whole world for a frame, and you should NOT see it glide/zoom from the world view to your location.
    5. Repeat once at a high zoom (street level) — a flash is easiest to spot when the distance travelled is large.

    **Check 2 — MAPVIEW-V121-03: no saved default is unchanged.**
    1. On a map widget that has NO default saved (or clear one via config → `DEFAULT VIEW` → `Clear`), reload the page.
    2. Expected: it opens on the whole world, zoomed out, exactly as maps did before this phase. Nothing new, nothing odd.
    3. If you cleared one: confirm the config panel now reads that no default is set, and that the map opened at the world view *on this reload* (it is intentional that clearing does not move the map you are currently looking at — the change takes effect next load).

    **Check 3 — MAPVIEW-V121-05: it really survives a reload.**
    1. Save a default on a map, reload, confirm it opens there.
    2. Now fully close the browser tab, reopen the app, and open that dashboard again. Expected: still framed on the saved view.
    3. Bonus if convenient: open the same dashboard in a second browser (or a private window, logging in again). The default is stored on the dashboard's widget, not per-browser, so it should be identical.

    **Check 4 — MAPVIEW-V121-06: two maps stay independent.**
    1. Put TWO map widgets on one dashboard. Frame them on clearly different places (e.g. one on London, one on New York) and save each as its own default.
    2. Reload. Expected: each map opens at its OWN saved view. Neither shows the other's location, and neither shows the world view.
    3. Now enable `VIEWPORT SYNC` → `Sync map viewport` on BOTH, and reload again. Expected: they still open at their own separate views; they only start following each other once you actually pan or zoom one of them. If reloading makes both maps snap to the same view before you touch anything, that is the bug this check exists to catch — report it.

    **Optional sweep (Phase 111 leftovers, not this phase's criteria):** while you have the config panel open, glance at whether the `Set as default — zoom … · …` label is legible against its accent fill in BOTH light and dark theme and doesn't wrap awkwardly, and that the `Current default:` line updates immediately after a save.
  </how-to-verify>
