<objective>
Rewire `gapFillCalendar` from the buggy GLOBAL subdomain axis (one set of subdomain keys cross-filled into every domain group → phantom month-shaped week blocks) to PER-DOMAIN-GROUP date-range gap-fill: each group is filled with ONLY the subdomain buckets within its own range, via Plan 01's `enumerateGroupBuckets`.

In-range missing buckets become GREY tiles (value:null — the existing empty-cell treatment). Out-of-range slots simply never become cells, so `layoutCalendar` positions nothing there and the renderer draws BLANK (no rect) — the true GitHub/calendar look. With WEEK_START aligned (Plan 02), a week×day group becomes a single 7-row column.

Update the Phase-67-VERIFIED `calendarGapFill.spec.ts` to the corrected per-group semantics (it currently asserts the global cross-fill behavior — that is the bug), update the renderer call site, and add the no-cross-fill / in-range-grey / week×day-single-column / out-of-range-blank tests. Preserve every Phase 67/68/68.1 invariant.

Purpose: The core CALUX-V113-03 correctness fix.
Output: per-group `calendarGapFill.ts` + updated specs + renderer call update.
</objective>
