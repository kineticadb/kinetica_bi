<objective>
Create a PURE, exhaustively unit-tested enumerator that, given a domain group key + the (domain, subdomain) units, returns the expected subdomain bucket keys that fall WITHIN that group's own time range — in the exact SQL string format the calendar query emits ("YYYY-MM-DD HH:mm:ss", UTC).

This is the foundation of the per-group gap-fill fix (CALUX-V113-03). Today `gapFillCalendar` builds ONE global subdomain axis and cross-fills every domain group with every key, giving a week×day group phantom month-shaped columns (operator-reported bug). This enumerator produces the CORRECT per-group expected-bucket set so Plan 03 can fill in-range gaps grey and leave out-of-range slots blank.

Purpose: Hardest, most-testable part of the fix — isolate it as a pure TDD module so date math (leap years, month lengths, year/month boundaries, UTC) is proven independently before wiring.
Output: `packages/web/src/lib/calendarBuckets.ts` + spec.
</objective>

KEY-KEY-KEY — the bucket-key STRING FORMAT (this is the contract Plan 03's gapFill and the SQL rows share):
- Kinetica DATE_TRUNC emits domain_bucket / subdomain_bucket as `"YYYY-MM-DD HH:mm:ss"` (space separator, NO trailing Z, NO milliseconds in the key) in UTC.
- parseUTCMs (calendarLayout.ts §282) canonicalizes by replacing " " with "T" and appending "Z".
- THEREFORE the enumerator MUST emit keys in `"YYYY-MM-DD HH:mm:ss"` (e.g. day bucket → "2024-10-09 00:00:00"; hour bucket → "2024-10-09 13:00:00"; month bucket → "2024-03-01 00:00:00"). It must NOT emit ISO "T...Z" strings — those would not string-equal the SQL rows' keys in Plan 03's per-group lookup.

The domainKey arrives in the SAME format (e.g. week domain group key "2024-10-07 00:00:00", month "2024-03-01 00:00:00", year "2024-01-01 00:00:00", day "2024-10-09 00:00:00"). Parse it with the same canonicalize-then-Date.UTC approach.
