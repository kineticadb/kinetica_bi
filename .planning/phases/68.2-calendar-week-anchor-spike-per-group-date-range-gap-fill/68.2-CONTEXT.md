# Phase 68.2: Calendar Week-Anchor Spike + Per-Group Date-Range Gap-Fill - Context

**Gathered:** 2026-06-17

<domain>
## Phase Boundary

Fix a calendar gap-fill correctness bug exposed by the Phase 68.1 wrapped layout, and
resolve the coupled (unverified) Kinetica week anchor.

**The bug:** `gapFillCalendar` builds ONE GLOBAL subdomain axis (all distinct subdomain
buckets across the whole dataset) and fills EVERY domain group with EVERY subdomain key
(`calendarGapFill.ts:82-99`). For week×day, the week-of-Oct-9 group therefore gets day-cells
for Oct 16, Oct 23, … (as nulls); `layoutDayBlock` positions those out-of-week days into
columns 1, 2, 3 → a month-shaped block where only the real week's column is filled. Latent
since Phase 67 (the old flat layout cross-filled too); 68.1's wrapping made it visible.

**The coupling:** live block labels showed week buckets on FRIDAYS (Oct 9/16/23), but
`layoutCalendar` assumes `WEEK_START = 1` (Monday) — the Phase 65 `DATE_TRUNC('week')`
anchor spike was NEVER RUN. So even a correct per-group fill could straddle two
Monday-columns if Kinetica anchors weeks on a different day. The two must be fixed together.

Requirement: CALUX-V113-03. Frontend + one live SQL spike. NOT a new server route.

</domain>

<decisions>
## Implementation Decisions

### (1) Week-anchor spike (do FIRST — it sets the constant the gap-fill aligns to)
- Run the live Kinetica `DATE_TRUNC('week', ts)` spike that Phase 65 deferred: confirm which
  day Kinetica anchors weeks to (Mon vs Sun vs other), via the app `/api/sql` path against the
  live instance (same approach as the Phase 65-02 spike plan that was recorded NOT-RUN).
- Set `WEEK_START` in `calendarLayout.ts` to the confirmed anchor (one-line change if it's not
  Monday). Record the result, clearing the Phase 65 NOT-YET-VERIFIED annotation on
  `KINETICA_DATE_TRUNC_UNITS`/the `week` unit in `calendarBin.ts`.
- If the live instance is unreachable at execution time: record the spike result as NOT-RUN
  again and keep `WEEK_START=1`, but STILL ship the gap-fill fix (it's correct for whatever
  anchor `WEEK_START` holds) — and re-flag the anchor for Phase 69. Do not block the gap-fill
  fix on instance availability.

### (2) Per-domain-group, date-range-aware gap-fill (the core fix)
- Replace the global subdomain axis with PER-GROUP expected buckets: each domain group
  contains ONLY the subdomain buckets that fall WITHIN that group's own time range.
  - week×day → the (up to) 7 days of that week
  - month×day → all days of that month
  - year×month → the 12 months of that year
  - day×hour → the 24 hours of that day  (also fixes the latent day×hour cross-fill)
  - month×week / year×week → the weeks whose start falls in that month / year
- Needs a pure, date-aware enumerator: given (domainKey, domain, subdomain), produce the
  expected subdomain bucket keys within the group's range, in the SAME string format the SQL
  emits (`"YYYY-MM-DD HH:mm:ss"`, UTC — see `parseUTCMs` in calendarLayout.ts and the
  DATE_TRUNC format). Keep it pure + unit-tested (mirrors computeCellBounds rigor).
- **In-range gaps → GREY tiles** (operator decision): a slot inside the group's range with no
  data renders grey (`value: null`, the existing empty-cell treatment). A week with data on
  only 5 of 7 days still shows 7 day-rows (2 grey). Preserves CAL-V113-04 gap-fill intent.
- **Out-of-range slots → BLANK no-tile** (operator decision): grid positions that belong to an
  adjacent period (e.g. the leading/trailing days of a partial week at a month edge) render as
  EMPTY SPACE — no rect at all. NOT grey. This is the true GitHub/calendar look.
  - Mechanism: out-of-range slots simply have NO PositionedCell, so the renderer draws nothing
    there. Only in-range buckets (real or grey-null) become cells.

### (3) Alignment guarantee
- With `WEEK_START` aligned to the live Kinetica anchor AND per-group day enumeration, a
  week×day group's 7 days map to a single 7-row column (cols === 1). Add a test asserting this.

### Carried-forward invariants (unchanged)
- Drill, active-cell highlight, color scale, tooltip, `respondToFilters` gating, the on-widget
  controls, theme tokens (no raw hex), no `materializeFilter`/`dropFilterView`/`fromSwap` import
  — all preserved. Empty/grey cells stay non-interactive (drill guard `value === null`).
- `computeCellBounds` half-open→inclusive semantics unchanged.

### Claude's Discretion
- Where the per-group enumerator lives (calendarBin.ts beside computeCellBounds, or a new
  calendar lib) and its exact name.
- Whether `gapFillCalendar` gains `(rows, domain, subdomain)` params or a new sibling builder is
  introduced (the renderer calls one or the other) — keep the change minimal and the contract
  clear; update Phase 67 gapFill specs to the corrected per-group semantics.
- Exact spike SQL + how the anchor result is recorded.

</decisions>
