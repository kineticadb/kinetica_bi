## Decisions Made

- **Signature extension vs new sibling:** Extended `gapFillCalendar` to `(rows, domain, subdomain)` — minimal change, preserves GapFillResult shape, renderer call site diff is one line.
- **subdomainKeys stays informational:** Layout already uses per-block cells; top-level union is kept as a convenience field for callers that need an axis sense but layout ignores it.
- **Test 32 updated with per-group-correct mock:** Old test assumed day-keyed data would show populated cells even after viewer switched to week subdomain — with per-group fill this is wrong (key format must match enumerator output). Fix: supply week-keyed mock data on the 2nd call.
- **Out-of-range blank is automatic:** No renderer change needed — per-group enumeration simply never produces a cell for out-of-range slots; `layoutCalendar` positions nothing; SVG draws nothing.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test 32 mock data mismatch after per-group fill**
- **Found during:** Task 2 (existing CalendarRenderer spec run after renderer update)
- **Issue:** Test 32 expected that switching viewer subdomain to "week" would still show a populated rect, using the old CANNED_ROWS (day-keyed data). With per-group gap-fill, `gapFillCalendar(data, "month", "week")` enumerates Monday-anchored week keys, none of which match the CANNED_ROWS day keys (`"2026-01-03 00:00:00"` etc.) → zero populated cells → no rect to click.
- **Fix:** Added `mockResolvedValueOnce` calls so first fetch returns day-keyed CANNED_ROWS (initial render) and second fetch returns week-keyed data (`"2026-01-05 00:00:00"` = first Monday in Jan 2026). This correctly models what would happen in production (runSql re-fetches with new subdomain, returning week-granularity DATE_TRUNC output).
- **Files modified:** `packages/web/src/components/charts/CalendarRenderer.spec.tsx`
