Verified AST facts:
- `RangeVar` = `{ schemaname?, relname, catalogname?, alias?, location }`; unquoted identifiers arrive lower-cased, quoted keep case (`DEMO."Trips"` -> schemaname "demo", relname "Trips").
- `location` is a UTF-8 BYTE offset (in `SELECT 'é' ... FROM aidv_101` it is 1 more than the JS string index). Use `Buffer` for any offset arithmetic.
- `EXTRACT(...)`, `TRIM(...)`, `SUBSTRING(a FROM 1 FOR 2)`, `a AT TIME ZONE 'UTC'` parse as `FuncCall` with `funcname = [pg_catalog, <name>]` and `funcformat: "COERCE_SQL_SYNTAX"` — these MUST be allowed. A user-written `myschema.fn(x)` has `funcformat: "COERCE_EXPLICIT_CALL"` and must be refused.
- `CAST(a AS int)`, `a::int`, `INTERVAL '1' DAY`, `COALESCE`, `NULLIF`, `GREATEST`, `CURRENT_DATE` produce no qualified FuncCall.
- `LIMIT 5` -> `SelectStmt.limitCount`; `SELECT 1; SELECT 2` -> `stmts.length === 2`; `QUALIFY` -> SqlError "syntax error at or near ...".
