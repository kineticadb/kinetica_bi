<objective>
Refactor `widgetActionStore` from target-keyed MERGE to SOURCE-CONTROL-keyed CONTRIBUTIONS so that re-selecting a radio option fully REPLACES that control's contribution (dropped fields revert to baseline) — while keeping the consumer-facing read as a DERIVED per-target overlay in the exact shape `MapChartRenderer.effectiveLayers` and `WidgetRenderer.effectiveWidget` already consume. This is the highest-risk task in the phase; the renderer (60-02) depends on it.

Purpose: Phase 58's `applyXOverride` MERGES into a target-keyed map (`{ ...existing, ...patch }`), so switching radio option A→B can never drop the fields A set but B doesn't. Switch-replace semantics (RADIO-V111-03) require per-control contribution replacement.

Output: Refactored store (control-keyed contributions + derived overlay selectors), `applyWidgetAction` write-side change (records a control's contribution, replacing its prior), DashboardsPage dispatch-closure threading of the control id, and migration of the 3 affected specs (store, applyWidgetAction, canary). Canary CASE A/B/C stay green; switch-replace proven by a new spec.
</objective>
