<objective>
Ship the fingerprint -> type-class rule and the three-level severity rule as a pure server lib.

Purpose: this is the decision the whole phase rests on. A Kinetica TIMESTAMP is stored as
`{ base: "long", refinements: ["timestamp"] }` — **live-verified**. `long` is a member of
`NUMERIC_TYPES`, so a classifier that looks at `base` alone calls that column `number`, and then
grades a `timestamp -> bigint` retype as **harmless when it is catastrophic**. That is exactly the
flattening `packages/server/src/lib/showTableTypes.ts` exists to undo, reintroduced one layer up in
the code that decides what to TELL the operator.

The rule: **check `refinements` for a class-determining marker FIRST, and only then fall back to
`base` membership.** It keys on the marker regardless of which base carries it, which is why it
survives the docs-vs-code contradiction 124-RESEARCH.md flagged (the repo's own
`showTableTypes.ts` header says DATE/TIME/DATETIME sit on `long`; Kinetica's published docs say
`string`; the rule is correct under either reading).

Output: `packages/server/src/lib/columnTypeClass.ts` (pure — no db, no express, no fetch, no
Kinetica call) and `packages/server/tests/lib.columnTypeClass.spec.ts`.
</objective>

```ts
export function classifyFingerprint(fp: ColumnFingerprint): ColumnTypeClass {
  // 1. Class-determining property MARKERS first, regardless of which base carries them.
  //    DATETIME_TYPES is {timestamp,date,time,datetime} — as REFINEMENT markers here, never as
  //    base values: none of those four ever appears as a fingerprint's `base` (124-RESEARCH §1.3).
  for (const r of fp.refinements) if (DATETIME_TYPES.has(r)) return "datetime";
  for (const r of fp.refinements) if (BOOLEAN_TYPES.has(r)) return "boolean";
  // `decimal(18,4)` -> normalizeType -> `decimal` ∈ NUMERIC_TYPES. Width markers like `char4`,
  // `int8` are handled here too and are harmless: `char4` matches nothing, `int8` is numeric and
  // its base `int` is numeric as well, so the answer is the same either way.
  for (const r of fp.refinements) if (NUMERIC_TYPES.has(normalizeType(r))) return "number";

  // 2. The normalizeAvroType failure sentinel. NEVER silently absorbed into a real class —
  //    a retype involving it is graded `breaking` by severityForRetype (Task 2).
  if (fp.base === "unknown" || fp.base === "") return "unknown";

  // 3. Base membership, mirroring inferDataTypeFromColumn's own order.
  if (NUMERIC_TYPES.has(normalizeType(fp.base))) return "number";
  if (BOOLEAN_TYPES.has(normalizeType(fp.base))) return "boolean";   // defensive: no native boolean base is known
  if (DATETIME_TYPES.has(normalizeType(fp.base))) return "datetime"; // defensive: only `timestamp` is a known long-base property

  // 4. Everything else — string / bytes bases, char*/ipv4/uuid/json/array/wkt refinements, and
  //    anything unrecognised. Matches inferDataTypeFromColumn's own default, and matches today's
  //    legacy behaviour for a `geometry` column (which also falls through to "string").
  return "string";
}
```
