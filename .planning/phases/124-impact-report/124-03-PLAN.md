<locked_design>
These are decisions, not options. They come from 124-CONTEXT.md (locked) or from the discretion it
explicitly delegated; where the latter, the reasoning is given so the SUMMARY can record it.

1. **Structure is severity -> column -> record -> reference.** Breaking, then changed, then
   harmless. All three sections are ALWAYS present; an empty one has an empty `columns` array and
   is never an omitted key. A column with mixed consequences can appear under more than one
   severity — accepted deliberately (124-CONTEXT.md).
2. **Grouping by record is REQUIRED.** A widget routinely produces BOTH an exact finding
   (`config.metricColumn`) and a heuristic one (`config.sql`) for the SAME column, because
   Phase 123's operator chose completeness over a quieter report. Ungrouped, that widget appears
   twice and the report looks buggy. Enforced by a TEST, not by prose.
3. **`collectColumnRefs` is called ONCE**, with the full set of removed + retyped column names, and
   the result is partitioned. No second traversal, no per-column call.
4. **The ref walk runs for removed and retyped columns only.** An added column carries
   `records: []`. An added column breaks nothing by definition (SSYNC-V125-11, criterion 3), and a
   pre-existing reference to a name that has just started to exist describes something that was
   already broken and is now FIXED — listing it under a harmless change would mislead. Discretion
   call; record it in the SUMMARY.
5. **`staleDrillDownType` is attached only to a widget, only under a BREAKING RETYPE.** It is
   produced by FILTERING the `collectColumnRefs` output to `site === "widget.config.drillDownColumn"`
   and reading `widget.config.drillDownColumnType` off the already-loaded row — no new traversal
   (124-RESEARCH.md §3.1). A `changed` retype leaves the frozen class correct (`int -> double` is
   still `number`), so flagging it there would be noise. 69 widget configs carry the field.
6. **"No findings" vs "not yet run" is settled by PRESENCE of the report, not by an empty array.**
   `impact` is attached (Plan 124-04) only to the `"diff"` outcome. Inside it,
   `outcome: "no_changes"` means the check ran and found nothing; `outcome: "changes"` means at
   least one column changed. A `baseline_required` or `table_missing` response carries no `impact`
   key at all. Phase 126 therefore distinguishes all three states without ambiguity.
7. **`dynamicView.columns_json[].type` is a recorded KNOWN GAP, not silent.** 124-CONTEXT.md:
   surface it if it fits the severity model cheaply, otherwise record it. It does not fit cheaply —
   unlike `drillDownColumn` there is NO `ColumnRef` site for it (Phase 123 enumerates
   `columns_json[].name` only), so surfacing it would mean writing a traversal `columnRefs.ts`
   deliberately does not provide. It is emitted as a `knownGaps` entry the UI renders verbatim.
8. **Byte-stable output.** No `localeCompare`, no `Date`, no locale-dependent ordering anywhere —
   Phase 125 persists this and a locale-dependent order produces spurious history churn between
   machines (the same discipline `schemaDiff.ts` and `columnRefs.ts` already state in their own
   sort comments). Grouping preserves `collectColumnRefs`'s order; columns within a section sort
   byte-ascending by name.
9. **JSON-serialisable only.** No `Map`, no `Set`, no functions, no class instances anywhere in the
   report — Phase 125 persists it.
</locked_design>

/** Which diff group a column came from. Severity is a function of this plus, for a retype, the
 *  type-class flip test in columnTypeClass.ts. */
export type ImpactChangeKind = "removed" | "retyped" | "added";

/** One reference SITE inside one record. Granularity is inherited from ColumnRef: one entry per
 *  site, not one per text match (the matches live inside). */
export type ImpactReference = {
  site: ColumnRefSite;
  path: string;
  /** The machine-readable tier, straight from ColumnRef. */
  confidence: RefConfidence;
  tableScope: ColumnRefTableScope;
  /** Report-ready prose the UI renders VERBATIM. Locked in 124-CONTEXT.md: the tier AND the
   *  prose, one source, so the wording cannot drift or soften in the rendering layer. */
  certainty: string;
  /** Matched line, 1-based line number and 0-based in-line offset, per free-SQL match. Empty for
   *  value-equality sites. */
  matches: ColumnRefMatch[];
};

/** One record affected by one column's change. ALL of that record's reference sites for that
 *  column are grouped here — a widget that matches through both a structured field AND its own
 *  config.sql appears ONCE, with two references. Grouping by record is REQUIRED, not optional
 *  (124-CONTEXT.md, carried from Phase 123). */
export type ImpactRecord = {
  recordKind: ColumnRefRecordKind;
  /** null ONLY for a column-format rule, whose key is (table_id, column_name). */
  recordId: number | null;
  /** The record's own name, "" when it carries none. */
  name: string;
  dashboardName: string | null;
  /** The composed operator-facing label, rendered VERBATIM. Title + dashboard name by default;
   *  the id appears only as a disambiguator or a fallback, and never without an advisory. */
  displayLabel: string;
  /** Naming advisories for THIS record. Also summarised once at report level. */
  advisories: ImpactAdvisory[];
  references: ImpactReference[];
  /** Present ONLY on a widget that carries a frozen `config.drillDownColumnType` for this column,
   *  and ONLY under a BREAKING retype (SSYNC-V125-12, ROADMAP criterion 4). Absent otherwise —
   *  never `null`, never an empty object. */
  staleDrillDownType?: { frozenType: string; message: string };
};

/** One changed column, with every record that references it. */
export type ImpactColumn = {
  column: string;
  changeKind: ImpactChangeKind;
  /** The rendered stored type (formatFingerprint). null for an ADDED column. */
  storedType: string | null;
  /** The rendered live type. null for a REMOVED column. */
  liveType: string | null;
  /** The stored/live type CLASS. null on the side that does not exist. */
  storedClass: ColumnTypeClass | null;
  liveClass: ColumnTypeClass | null;
  /** One-line, report-ready explanation of the change. Rendered VERBATIM. */
  summary: string;
  /** Empty for an ADDED column, by design — an added column breaks nothing. */
  records: ImpactRecord[];
};

  tableId: number;

**`certaintyProse`** — exported so the spec can assert each branch in isolation:

```ts
export function certaintyProse(
  column: string,
  path: string,
  confidence: RefConfidence,
  tableScope: ColumnRefTableScope,
): string {
  let base: string;
  if (confidence === "exact") {
    base = `confirmed — this record stores the column in its \`${path}\` field.`;
  } else if (confidence === "low-confidence") {
    base =
      `possibly affected — \`${column}\` is a short or common name, so this text match in ` +
      `\`${path}\` is more likely than most to be a false positive.`;
  } else {
    base =
      `possibly affected — \`${path}\` mentions \`${column}\`, but the match is text-based and ` +
      `may be a false positive.`;
  }
  if (tableScope === "unresolved") {
    base +=
      ` This record's own table could not be determined, so it is reported for every table that ` +
      `changes.`;
  }
  return base;
}
```

**`buildImpactReport`** — the entry point:

```ts
export type ImpactInput = {
  /** Must be the "diff" outcome. The caller (Plan 124-04) does not call this for the other two. */
  check: Extract<SchemaCheckResult, { outcome: "diff" }>;
  tableId: number;
  refsInput: ColumnRefsInput;
  dashboards: DashboardNameRow[];
};
export function buildImpactReport(input: ImpactInput): ImpactReport;
```

Algorithm, in this exact order:

1. `walkedColumns = [...check.removed.map(r => r.column), ...check.retyped.map(r => r.column)]`.
   **Added columns are deliberately excluded** (see `<locked_design>` item 4).
2. `const refs = walkedColumns.length === 0 ? [] : collectColumnRefs(refsInput, { tableId, columns: walkedColumns });`
   — ONE call, no per-column loop.
3. `const ctx = buildNamingContext(refsInput, dashboards);`
4. Build `byColumn: Record<string, ColumnRef[]>` by walking `refs` in order and pushing — this
   PRESERVES `collectColumnRefs`'s byte-stable ordering, so no re-sort is needed inside a column.
5. For each `RemovedColumn` (already sorted byte-ascending by `schemaDiff`): build an
   `ImpactColumn` with `changeKind: "removed"`, `storedType: r.storedType`, `liveType: null`,
   `storedClass: classifyFingerprint(r.stored)`, `liveClass: null`,
   `summary: \`The column \\\`${column}\\\` is gone from the table. Its stored type was ${storedType}.\``,
   severity `REMOVED_SEVERITY`.
6. For each `RetypedColumn`: `severity = severityForRetype(r.stored, r.live)`;
   `storedClass`/`liveClass` from `classifyFingerprint`; summary is one of two strings:
   - breaking: `` `The column \`${column}\` changed from ${storedType} to ${liveType}. That moves it from the ${storedClass} type class to ${liveClass}, which is what the app branches on — dependents can break.` ``
   - changed: `` `The column \`${column}\` changed from ${storedType} to ${liveType}. It stays in the ${storedClass} type class, so nothing in the app misbehaves, but the data meaning moved.` ``
   (`unknown` on either side is already forced to `breaking` by `severityForRetype`; the breaking
   sentence reads correctly with `unknown` substituted.)
7. For each `AddedColumn`: `changeKind: "added"`, `storedType: null`, `storedClass: null`,
   `liveType: a.liveType`, `liveClass: classifyFingerprint(a.live)`, `records: []`,
   `summary: \`The column \\\`${column}\\\` is new (${liveType}). Nothing can be broken by it — it only needs to become selectable in the config panels.\``,
   severity `ADDED_SEVERITY`.
8. **Records, per column**: group that column's `ColumnRef[]` by `namingKey(recordKind, recordId)`,
   preserving first-seen order. For each group emit one `ImpactRecord`:

function staleDrillDownFor(
  refsForRecord: ColumnRef[],
  recordKind: ColumnRefRecordKind,
  recordId: number | null,
  severity: ImpactSeverity,
  changeKind: ImpactChangeKind,
  liveClass: ColumnTypeClass | null,
  widgets: ColumnRefsInput["widgets"],
): { frozenType: string; message: string } | undefined {

}
