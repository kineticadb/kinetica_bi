<objective>
Ship the record-naming resolver: the module that turns a `ColumnRef`'s bare
`(recordKind, recordId, recordLabel)` into the operator-facing label Phase 126 renders verbatim.

Purpose: ROADMAP criterion 1 requires affected widgets to be identified "by its title and its
dashboard's name — **not by id**". That stands as the DEFAULT. 124-CONTEXT.md then locks two
exceptions, both of which the operator decided explicitly (2026-09-23) and neither of which is
drift from criterion 1: the id appears as a **disambiguator** when a title collides within its
dashboard, and as a **fallback** when a record has no name at all. In both cases an advisory goes
with it, because the report's governing principle is that it **nudges the operator toward better
naming hygiene rather than silently compensating**. Apply that principle to any naming case this
plan does not enumerate.

Real data this must handle (verified 2026-09-23): 74 widgets across 7 dashboards, all titled, but
**4 (dashboard, title) pairs collide**; `dashboard_layers` has **no name column** — a layer's name
lives at `config.name` and may be absent; all 7 dashboards are named; all 10 custom-metric labels
are distinct today, but the collision rule is applied to metrics too, because a future dataset can
collide and the report's own principle is to nudge rather than paper over.

Output: `packages/server/src/lib/impactNaming.ts` (pure — no db, no express, no fetch) and
`packages/server/tests/lib.impactNaming.spec.ts`.

```ts
export type ImpactAdvisoryKind = "unnamed-record" | "ambiguous-name";

/** A naming advisory. `message` is report-ready prose the UI renders VERBATIM — never re-worded,
 *  never re-assembled downstream. Locked in 124-CONTEXT.md: the advisory appears BOTH on the
 *  individual finding and once, summarised, at report level. */
export type ImpactAdvisory = { kind: ImpactAdvisoryKind; message: string };

export type RecordNaming = {
  /** The record's own name, exactly as stored. "" when it carries none. */
  name: string;
  /** The dashboard this record lives on. null for table-scoped records (custom metrics and
   *  column-format rules belong to a TABLE, not a dashboard). */
  dashboardName: string | null;
  /** The composed operator-facing label. Rendered VERBATIM by Phase 126. */
  displayLabel: string;
  advisories: ImpactAdvisory[];
};

export type DashboardNameRow = { id: number; name: string };

export type NamingContext = {
  /** dashboard id -> name. A dashboard id absent from this map renders as `dashboard <id>`. */
  dashboardNames: Record<number, string>;
  /** namingKey() values whose name collides inside its own group. */
  ambiguous: ReadonlySet<string>;
  /** namingKey() value -> owning dashboard id. Absent for table-scoped records. */
  dashboardOf: Record<string, number>;
};

export function namingKey(recordKind: ColumnRefRecordKind, recordId: number | null): string;
export function buildNamingContext(
  input: ColumnRefsInput,
  dashboards: DashboardNameRow[],
): NamingContext;
export function resolveRecordName(
  ref: { recordKind: ColumnRefRecordKind; recordId: number | null; recordLabel: string },
  ctx: NamingContext,
): RecordNaming;
```

**`namingKey`** is `` `${recordKind}|${recordId}` `` — `recordId` may be `null`, which stringifies
to `"null"` and is only ever reached by `columnDisplayConfig`.

**The operator-facing noun per record kind.** A single file-local map, used everywhere so the
wording cannot diverge:

```ts
const RECORD_NOUN: Record<ColumnRefRecordKind, string> = {
  widget: "widget",
  layer: "map layer",
  customMetric: "custom metric",
  dynamicView: "dynamic view",
  tableView: "saved filter view",
  columnDisplayConfig: "column-format rule",
};
/** Plural forms for the report-level summary and the collision advisory. */
const RECORD_NOUN_PLURAL: Record<ColumnRefRecordKind, string> = {
  widget: "widgets", layer: "map layers", customMetric: "custom metrics",
  dynamicView: "dynamic views", tableView: "saved filter views",
  columnDisplayConfig: "column-format rules",
};
```

**`buildNamingContext`.** Walk the five id-bearing record kinds and build `dashboardOf` plus a
collision count keyed by `${recordKind}|${groupId}|${name}`:

| recordKind | name source | group id |
|---|---|---|
| `widget` | `w.title` | `w.dashboard_id` |
| `layer` | `typeof l.config?.name === "string" ? l.config.name : ""` | `l.dashboard_id` |
| `dynamicView` | `dv.name` | `dv.dashboard_id` |
| `tableView` | `tv.view_name` | `tv.dashboard_id` |
| `customMetric` | `m.label` | `m.table_id` |

`columnDisplayConfig` is **deliberately absent from this table**: its key is
`(table_id, column_name)`, which is unique by construction, and it has no id to append even if it
were not. It is never ambiguous.

**An EMPTY name is never counted toward a collision.** Two unnamed widgets on one dashboard are two
unnamed records, not an ambiguity — they already get the stronger advisory, and telling the
operator to "rename one" when neither has a name would be wrong advice. A key lands in `ambiguous`
only when its name is non-empty AND its count is >= 2.

`dashboardNames` is `Object.fromEntries(dashboards.map(d => [d.id, d.name]))`.

**`resolveRecordName`.** Compose in this order:

```
noun        = RECORD_NOUN[recordKind]
dashClause  = dashboardOf has this key
                ? (dashboardNames[dashId] !== undefined
                     ? ` on dashboard "${dashboardNames[dashId]}"`
                     : ` on dashboard ${dashId}`)          // dangling FK, honest fallback
                : ""                                        // table-scoped record

if recordKind === "columnDisplayConfig":
    displayLabel = `column-format rule for "${recordLabel}"`   // never an id; it has none
    advisories   = []

else if recordLabel === "":
    displayLabel = `${noun} ${recordId} (no name)${dashClause}`
    advisories   = [{ kind: "unnamed-record", message:
        `This ${noun} has no name, so the report can only identify it by its id (${recordId}). ` +
        `Name it and re-run this check to see it by name.` }]

else if ambiguous.has(namingKey(...)):
    displayLabel = `${noun} "${recordLabel}" (id ${recordId})${dashClause}`
    advisories   = [{ kind: "ambiguous-name", message:
        `Two or more ${RECORD_NOUN_PLURAL[recordKind]}${dashClause || " on this table"} are ` +
        `named "${recordLabel}", so the report appends the id (${recordId}) to tell them apart. ` +
        `Rename one and re-run this check to see them by name alone.` }]

else:
    displayLabel = `${noun} "${recordLabel}"${dashClause}`
    advisories   = []
```

`dashboardName` is `dashboardNames[dashId] ?? null` — `null` for a table-scoped record AND for a
dangling dashboard id (the composed `displayLabel` still says `dashboard 99`, so nothing is lost).

```ts
/**
 * The report-level half of the locked BOTH-places rule (124-CONTEXT.md). Finding-level advisories
 * alone risk the pattern going unnoticed across twenty findings; a report-level line alone leaves
 * the operator guessing which findings it refers to. So the same fact is stated in both places,
 * and both strings are composed HERE so they cannot drift apart.
 *
 * Counts BY KIND from the already-composed per-record advisories. It never parses a `message` —
 * `kind` is the machine-readable field precisely so prose stays free to change.
 *
 * Deterministic output order: ambiguous-name, then unnamed-record. A kind with a zero count is
 * OMITTED, never emitted with a count of 0.
 */
export function summariseAdvisories(all: ImpactAdvisory[]): ImpactAdvisory[] {
  const counts: Record<ImpactAdvisoryKind, number> = {
    "ambiguous-name": 0,
    "unnamed-record": 0,
  };
  for (const a of all) counts[a.kind] += 1;

  const out: ImpactAdvisory[] = [];
  if (counts["ambiguous-name"] > 0) {
    const n = counts["ambiguous-name"];
    out.push({
      kind: "ambiguous-name",
      message:
        `${n} ${n === 1 ? "record" : "records"} could not be named unambiguously — ` +
        `rename ${n === 1 ? "it" : "them"} and re-run this check to see exactly which.`,
    });
  }
  if (counts["unnamed-record"] > 0) {
    const n = counts["unnamed-record"];
    out.push({
      kind: "unnamed-record",
      message:
        `${n} ${n === 1 ? "record has" : "records have"} no name — ` +
        `name ${n === 1 ? "it" : "them"} and re-run this check so the report can identify ` +
        `${n === 1 ? "it" : "them"} without ids.`,
    });
  }
  return out;
}
```
