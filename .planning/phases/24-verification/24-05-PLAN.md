From kinetica_bi/src/components/charts/MapConfigPanel.tsx (lines 42-83) — CURRENT (buggy) state initialization:
```tsx

  // ... title / basemap / includedLayerIds reads ...

  // Read defaults via Phase 19 helpers — DO NOT duplicate the literals true / 20 here.

  const infoPopupHeightPx = getInfoPopupHeightPx({ infoPopupHeightPx: widgetCfg.infoPopupHeightPx });

  // clamping. Reset when stored config changes externally.   <-- COMMENT IS A LIE
  const [radiusDraft, setRadiusDraft] = useState<string>(String(infoRadiusPx));
  const [radiusError, setRadiusError] = useState<string | null>(null);
  const [widthDraft, setWidthDraft] = useState<string>(String(infoPopupWidthPx));
  const [heightDraft, setHeightDraft] = useState<string>(String(infoPopupHeightPx));
  const [widthError, setWidthError] = useState<string | null>(null);
  const [heightError, setHeightError] = useState<string | null>(null);
```

ROOT CAUSE — the `useState` initializer arg only runs on FIRST render. When the panel unmounts (operator closes the config) and remounts (operator reopens), React re-runs the function body — BUT the modal that hosts MapConfigPanel may keep the component mounted across saves (re-render with new `config` prop, not unmount/remount). In that case, `useState(String(infoPopupWidthPx))` only captured the FIRST render's `infoPopupWidthPx`, then the draft state is divorced from `config` forever. Even if the component DOES unmount/remount, the previously-cited "Reset when stored config changes externally" comment promises behavior the code does not implement — there is no `useEffect` that re-syncs the drafts when `config` changes.

The fix is one of two shapes — pick FIX A unless the executor finds compelling reason for FIX B:

**FIX A — controlled-input pattern (PREFERRED)**: Make the inputs fully controlled by `widget.config` and drop the draft state entirely. The clamp-on-blur pattern still works:
- `value={String(infoPopupWidthPx)}` (read directly from getter)
- `onChange={(e) => setWidthDraftEcho(e.target.value)}` where `widthDraftEcho` is a transient local state for "user typed but hasn't blurred yet"
- `onBlur` clamps and emits onChange to parent

But the clamp-on-blur pattern (locked in Phase 22 STATE.md decision) requires a transient buffer for free typing. So FIX A actually needs the draft state AND a useEffect that re-syncs the draft when `infoPopupWidthPx` changes from its prior value.

**FIX B — useEffect re-sync (MINIMAL DIFF)**: Keep `useState` initializers as-is; add a `useEffect` that re-syncs each draft when its config-derived value changes. This honors the existing line-comment ("Reset when stored config changes externally") which currently promises behavior that does not exist:
```tsx
useEffect(() => {
  setRadiusDraft(String(infoRadiusPx));
}, [infoRadiusPx]);
useEffect(() => {
  setWidthDraft(String(infoPopupWidthPx));
}, [infoPopupWidthPx]);
useEffect(() => {
  setHeightDraft(String(infoPopupHeightPx));
}, [infoPopupHeightPx]);
```

PITFALL of FIX B: if the user is mid-type (e.g., typed "12" en route to "1200") and another sync source updates `infoPopupWidthPx`, the useEffect would clobber the typed-in-progress text. Mitigate by gating the sync: only re-sync when the draft does NOT represent the current config value. Use the form `if (String(infoPopupWidthPx) !== widthDraft) setWidthDraft(...)` — BUT this comparison is a noop once draft and config agree; it doesn't protect mid-type. The honest answer: the existing clamp-on-blur pattern was designed for a stationary `infoPopupWidthPx`. Mid-type interruption is rare in practice (user types and blurs quickly).

The clean FIX B refinement: do the re-sync ONLY on `infoPopupWidthPx` change AND when the draft equals the PRIOR `infoPopupWidthPx`. Track the prior via `useRef`:
```tsx
const priorWidthRef = useRef(infoPopupWidthPx);
useEffect(() => {
  // If the draft still reflects the prior config value, re-sync to the new one.
  // If the draft differs (user is mid-type), leave it alone — clamp-on-blur will reconcile.
  if (widthDraft === String(priorWidthRef.current)) {
    setWidthDraft(String(infoPopupWidthPx));
  }
  priorWidthRef.current = infoPopupWidthPx;
}, [infoPopupWidthPx, widthDraft]);
```

For most cases (operator opens panel, sees stale value) the draft on mount IS `String(priorWidthRef.current)` (initial render) and the change fires once on first render — but useEffect only fires AFTER first render, so the initializer must already be correct. The initializer IS correct on first render — the bug is that the SAME modal instance can rerender with a different `config` (e.g., user switches between two map widgets without closing the panel). Verify this is the actual repro path by reading the parent ConfigPanel mount site.
