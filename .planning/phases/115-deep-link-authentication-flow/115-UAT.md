## Coverage Limitation — OIDC round trip not exercised live

**This is the headline caveat on this UAT record: "all checks pass" describes password mode only.**

`packages/server/.env:15` is `AUTH_MODE=password`. The operator's entire live walkthrough (UAT-115-1
through UAT-115-7) therefore ran exclusively in PASSWORD mode. The OIDC-specific paths were NOT
exercised live in a browser:

- `handleSignInCommit`'s `sessionStorage.setItem` write is gated on `authMode === "oidc"`
  (`App.tsx:272`) — never fires in password mode.
- The `UNAUTHORIZED_EVENT` handler's `ReturnTo` write is likewise OIDC-relevant only insofar as the
  full-page navigation it survives is an OIDC-only event; in password mode the app never unmounts.
- The post-round-trip address-bar restore (`restoreDashboardUrl`) only matters when the query
  string is destroyed by a full-page navigation, which only OIDC's IdP redirect causes.

So the entire `kbi_returnTo` carry mechanism — the reason this phase needed sessionStorage at all —
is covered by automated tests and mutation probes (see 115-01/02/03-SUMMARY.md) but has NOT been
seen working end-to-end in a real browser against a real IdP. This mirrors 114-UAT.md's precedent
of recording UAT-114-2 as "not exercised" rather than upgrading it to a pass: the same honesty rule
applies here at larger scale.

**Recommendation:** re-verify Group C (UAT-115-8 through 15) live whenever an OIDC-configured
deployment is next available, before treating the OIDC half of DLINK-V121-03 as battle-tested
rather than test-suite-proven.
