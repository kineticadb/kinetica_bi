<objective>
Make the radio config panel author a PER-OPTION TARGET LIST (RADIOMULTI-V111-01, the UI half).

Today `OptionRow` renders ONE target picker + ONE editor per option. This plan changes it to a list of N targets per option, each with add ("+ Add target") / remove affordances, each target reusing its EXISTING editor: layer → the 60.1 full-form side-by-side `RadioLayerConfigEditor`; widget/dynamic-view → the existing simple JSON inputs. The single-target case must stay clean (don't force list chrome onto the common case). On save, options carry `actions: WidgetAction[]`; legacy single-`action` options load via `getOptionActions` (Plan 01) and re-save as `actions`.

Purpose: This is the authoring surface for multi-target options — the bulk of the visible work. Plan 01 already landed the model + dispatch + back-compat.
Output: Updated `RadioGroupConfigPanel.tsx` + panel specs (add/remove target, single-target-clean, multi-target authoring round-trips to actions[], legacy load).
</objective>
