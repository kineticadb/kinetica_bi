<objective>
Build a FRONTEND-ONLY dashboard-level keep-alive hook (`useViewKeepAlive`) that, while a dashboard is open, fires a lightweight READ ("touch") against each LIVE materialized view (filter-views + dynamic-views) a configurable lead-time before that view's `expiresAt`, re-arms after each touch, and tears down cleanly on dashboard switch / unmount.

Purpose: an idle dashboard left open across multiple TTL windows never hits an expired view. The touch ASSUMES a read resets Kinetica's sliding TTL (the premise that Phase 79 / TTLKEEP-V115-02 confirms live — NOT this phase). Best-effort: failures are swallowed; reactive view-not-found recovery (WidgetRenderer / MapChartRenderer) handles real expiry.

Output: `useViewKeepAlive.ts` + its spec, mounted in `DashboardsPage.tsx` `DashboardOpen` alongside `useDynamicViewMaterializeChain`.

NON-NEGOTIABLE locked decisions (78-CONTEXT.md):
- FRONTEND-ONLY. NO server change. The touch is a READ via `runSql("SELECT 1 FROM <viewName> LIMIT 1", {}, signal)`.
- The hook MUST NOT import `materializeFilter` / `materializeDynamicView` / `dropFilterView` / `fromSwap`. `AggregatedWidgetRenderer` stays the SOLE materialize trigger (static-import assertion test).
- RE-ARM uses a captured window length `W`, NOT the unchanged stored `expiresAt` (a touch READ does NOT return a new `expiresAt` — keying re-arm off the fixed stored value would tight-loop).
- NOT in scope: live TTL-reset confirmation / re-materialize fallback (Phase 79 / TTLKEEP-V115-02). No UI surface.
</objective>
