## GROUP B — needs the live Kinetica cluster

**None.** Verified 2026-09-14 by the plan checker and independently confirmed by this
plan: nothing in this phase's surface reaches Kinetica. `TableDetail`
(`DatasetsPage.tsx:125-204`) and `TableEdit` (`DatasetsPage.tsx:205-261`) make NO
`fetchKinetica*` calls — the only such calls in the file belong to `TableCreate`
(`DatasetsPage.tsx:262+`), and `create` is deliberately not linkable (see 116-CONTEXT
"NOT in scope"). Save is `PATCH /api/tables/:id`, which is local SQLite
(`packages/server/src/db.ts` `updateTable`); `listColumnDisplayConfig` and
`listCustomMetrics` are likewise local, not Kinetica-backed.

This correction matters: checks 14-16 above cover the in-place mode-change writer, which
research repeatedly flagged as the highest hand-rolled-History-API risk in the phase and the
one piece with no dashboard precedent. Deferring live verification of exactly that behind a
resource it does not need would have been the worst possible thing to defer. This "None" note
is written here deliberately, so a later reader sees the Group A/B split was considered and
resolved, not forgotten.

## KNOWN NOT COVERED

State this explicitly so the operator does not test for it and report a false defect:

- **Unsaved changes in the table edit form are discarded silently** on Cancel, on sidebar
  navigation away, and on browser Back. This is DELIBERATE and operator-decided for this phase
  (see `TLINK-F1` in `.planning/REQUIREMENTS.md`). It is NOT a regression: before this phase,
  browser Back from a table edit left the application entirely; after this phase it lands on
  the tables list, which is strictly better even without a dirty-state guard.
- `create` screens are not linkable, by design (nothing to identify a not-yet-saved table by).
- Roles and Settings pages are still not linkable (`DLINK-F4`, unchanged by this phase).
- Sidebar "Datasets" is a no-op while a table is already open — the tables twin of the
  pre-existing Phase 113 "Dashboards" no-op tech debt (see `TLINK-F3` in
  `.planning/REQUIREMENTS.md`). Confirmed present, deliberately not fixed here.
