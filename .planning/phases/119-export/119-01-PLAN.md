Exact public surface (these names are the plan's contract — Plan 02 and Phase 120 import them):

```ts
export type RefKind = "table" | "widget" | "layer" | "dynamicView" | "customMetric";

export type ExportRefs = {
  tableIds: number[];
  widgetIds: number[];
  layerIds: number[];
  dynamicViewIds: number[];
  customMetricIds: number[];
};

export const emptyExportRefs = (): ExportRefs => ({ ... all five empty arrays ... });
export const mergeExportRefs = (...parts: ExportRefs[]): ExportRefs;
export const collectFilterSelectionRefs = (value: unknown): number[];
export const collectWidgetConfigRefs = (config: unknown): ExportRefs;
export const collectLayerRefs = (layer: DashboardLayer): ExportRefs;
export const collectDynamicViewRefs = (dv: DashboardDynamicView): ExportRefs;
```

Internal helper — the ONLY place a value becomes an id:

```ts
const asId = (v: unknown): number | undefined =>
  typeof v === "number" && Number.isInteger(v) && v > 0 ? v : undefined;
```
`> 0` matches `WidgetActionTargetSchema`'s `z.number().int().positive()` and every AUTOINCREMENT
rowid in this schema. Strings are rejected outright — this is what makes the `"__spatial_draws__"`
sentinel pass through harmlessly instead of becoming `NaN`.

`mergeExportRefs`: concatenate each of the five lists, then `[...new Set(list)].sort((a, b) => a - b)`.
Every returned `ExportRefs` from every collector MUST be de-duplicated and ascending — run the raw
accumulations through the same normalizer before returning, so callers never have to.

`collectFilterSelectionRefs(value)`:
1. If `typeof value === "string"`, `JSON.parse` it inside a try/catch; on throw return `[]`.
   (`widgets.config.filterSelection` arrives as an object, but `DashboardLayer.filter_scope` is typed
   `string | null` while `mapDashboardLayer` actually hands back a parsed object — accept both rather
   than trusting a type that is documented to lie.)
2. Guard: must be a non-null, non-array object.
3. Read `allowedSourceWidgetIds`; if not an array, return `[]`.
4. Return the `asId`-surviving entries. Anything non-numeric — including `"__spatial_draws__"` — is
   dropped silently. **Never** `Number(entry)`, **never** `parseInt`.

`collectWidgetConfigRefs(config)`: guard `config` is a non-null, non-array object, else return
`emptyExportRefs()`. Then, one clearly-commented block per reference kind, each tagged with its
`REF-n` number so a reviewer can map code to research:

- REF-1 → `asId(cfg.tableId)` into `tableIds`
- REF-2 → `asId(cfg.dynamicViewId)` into `dynamicViewIds`
- REF-3 → `asId(cfg.sourceMapWidgetId)` into `widgetIds`
- REF-4 → `asId(cfg.metricId)` into `customMetricIds`
- REF-5 → if `Array.isArray(cfg.metrics)`, for each non-null object element `asId(el.metricId)` into
  `customMetricIds`
- REF-6 → if `Array.isArray(cfg.includedLayerIds)`, each `asId(el)` into `layerIds`.
  **Add this comment verbatim in intent (do not paraphrase away the warning):** an empty array and an
  absent field BOTH mean "render all layers" (Map-widget sentinel). Both therefore contribute ZERO
  layer references. Never expand either one to the dashboard's full layer list — that would fabricate
  references the operator never made and would defeat the sentinel on import.
- REF-7 → `collectFilterSelectionRefs(cfg.filterSelection)` into `widgetIds`
- REF-8 → if `Array.isArray(cfg.options)`, for each non-null object option:
  ```ts
  const actions = Array.isArray(o.actions) ? o.actions : (o.action ? [o.action] : []);
  ```
  This mirrors `getOptionActions()` in `packages/web/src/lib/radioGroupConfig.ts`. Reading only
  `actions[]` silently drops every pre-Phase-60.2 persisted option. For each action, read
  `action.target` (guard object), then `switch (target.kind)`: `"widget"` → `widgetIds`,
  `"layer"` → `layerIds`, `"dynamicView"` → `dynamicViewIds`, `default` → ignore. Do NOT recurse
  into `configPatch` — research verified the full allow-list contains no id-valued field.

`collectLayerRefs(layer)`: `asId(layer.table_id)` → `tableIds`; `asId(layer.dynamic_view_id)` →
`dynamicViewIds`; `collectFilterSelectionRefs(layer.filter_scope)` → `widgetIds`. Do NOT touch
`cb_config`, `track_config` or `layer.config` — layer `config` is style state and research found no
id-valued field in it.

`collectDynamicViewRefs(dv)`: `asId(dv.source_table_id)` → `tableIds`. Nothing else;
`columns_json` carries no ids.

File header comment: state that this module is the single source of truth for WHERE ids hide in
persisted dashboard JSON, list the eight REF-n kinds by field name, and state that adding a ninth
reference kind anywhere in `packages/web/src/components/charts/` requires updating this module and
its spec. Do NOT restate the phase/plan prose — keep it factual.
