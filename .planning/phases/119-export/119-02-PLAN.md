**`buildDashboardExport(dashboardId)` — exact algorithm:**

1. `const dashboard = getDashboard(dashboardId); if (!dashboard) return undefined;`
2. Read the owned children verbatim — no transformation, no id rewriting, no timestamp stripping:
   `listWidgets`, `listDashboardLayers`, `listDashboardDynamicViews`, `listDashboardTables`.
   (Original ids MUST travel: every intra-file reference points at them. Renumbering is Phase 120's
   job and must not be pre-empted here.)
3. Single pass that BOTH accumulates references and records dangling ones, so provenance is never
   lost to a merge:
   ```ts
   const widgetIdSet = new Set(widgets.map(w => w.id));
   const layerIdSet  = new Set(layers.map(l => l.id));
   const dvIdSet     = new Set(dynamicViews.map(d => d.id));

   const parts: ExportRefs[] = [];
   const danglingReferences: DanglingReference[] = [];

   const absorb = (from: string, refs: ExportRefs) => {
     parts.push(refs);
     for (const id of refs.widgetIds)      if (!widgetIdSet.has(id)) danglingReferences.push({ from, kind: "widget", id });
     for (const id of refs.layerIds)       if (!layerIdSet.has(id))  danglingReferences.push({ from, kind: "layer", id });
     for (const id of refs.dynamicViewIds) if (!dvIdSet.has(id))     danglingReferences.push({ from, kind: "dynamicView", id });
     for (const id of refs.tableIds)       if (!getTable(id))        danglingReferences.push({ from, kind: "table", id });
     for (const id of refs.customMetricIds) if (!getCustomMetric(id)) danglingReferences.push({ from, kind: "customMetric", id });
   };

   for (const w of widgets)      absorb(`widget:${w.id}`,      collectWidgetConfigRefs(w.config));
   for (const l of layers)       absorb(`layer:${l.id}`,       collectLayerRefs(l));
   for (const d of dynamicViews) absorb(`dynamicView:${d.id}`, collectDynamicViewRefs(d));
   const refs = mergeExportRefs(...parts);
   ```
   `danglingReferences` is deterministic by construction (widgets by `position`, then layers, then
   dynamic views; within each, the five kinds in the fixed order above, ids ascending because
   `ExportRefs` lists are pre-sorted). Do not sort it again.

   `danglingReferences` is **informational**: it tells an operator that e.g. a Legend widget binds to
   a map widget on a different dashboard, so the imported Legend will be unbound. It does NOT block
   the export, and Phase 120 is free to ignore it. Its second, structural job is that it makes every
   branch of the Plan 01 walk load-bearing in production code rather than test-only.

   const associatedIds = associated.map(t => t.id);

   const dashboardTableIds = [...associatedIds].sort((a, b) => a - b);

export const exportFileName = (dashboard: Pick<Dashboard, "id" | "name">): string => {
  const slug = String(dashboard.name ?? "")
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, "-")
    .replace(/^-+|-+$/g, "")
