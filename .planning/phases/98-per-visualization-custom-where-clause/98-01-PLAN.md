<objective>
Create a single shared pure helper for splicing a user-supplied raw-SQL WHERE predicate into a query, and thread an optional `customWhere` arg through the three pure own-SQL builders (timeline, numeric-line, calendar). Each of these builders already emits a `WHERE <col> IS NOT NULL` clause, so the custom predicate is appended as ` AND (<predicate>)` — parenthesized so mixed AND/OR predicates bind correctly. Empty/absent/whitespace customWhere must leave output BYTE-IDENTICAL (VIZSQL-V119-03).

Purpose: This is the lowest-risk, pure-library foundation (no React/store/network) and is consumed by the renderer wiring in plan 98-03. Doing it first and TDD-style locks the backward-compat contract before any UI exists.
Output: `customWhere.ts` helper + 3 builders accepting `customWhere?`, all with byte-identical-when-empty tests.
</objective>

    ```ts
    /** Returns ` AND (<predicate>)` (leading space) for a non-empty trimmed predicate, else "". */
    export function andCustomWhere(customWhere?: string): string {
      const p = (customWhere ?? "").trim();
      return p ? ` AND (${p})` : "";
    }
    /** Returns ` WHERE (<predicate>)` (leading space) for a non-empty trimmed predicate, else "". */
    export function whereCustomWhere(customWhere?: string): string {
      const p = (customWhere ?? "").trim();
      return p ? ` WHERE (${p})` : "";
    }
    ```

    The empty-guard is `.trim()` → no-op (returns ""). This is the single source of truth for the parenthesization rule used by ALL injection sites across plans 98-01/98-02/98-03. Add a short header comment documenting: parenthesization mandatory (mixed AND/OR binding), NO client-side parsing (raw SQL trusted), empty = byte-identical no-op.
