<objective>
Surface the shared "Custom filter (SQL)" field on every registry-driven in-scope widget (bar, pie, line, scatter, big number, aggregated table, records) and inject the predicate into the two config-save / read paths these widgets use:
1. Aggregated charts (bar/pie/line/scatter/big-number/table) bake their SQL into `widget.config.sql` in ChartConfigPanel's `generatedSql` useMemo — inject `WHERE (<predicate>)` there, before GROUP BY/ORDER BY/LIMIT.
2. Records table builds its SQL at render time in `RecordsTableRenderer` — inject `WHERE (<predicate>)` before ORDER BY/LIMIT in BOTH SQL sites (page-fetch + CSV export).
Empty/absent → byte-identical (VIZSQL-V119-03). Invalid → existing per-widget error path (VIZSQL-V119-04, no new UI).

Purpose: Covers the aggregated + records widget set end-to-end (field UI → persistence → execution). The aggregated path is genuinely distinct from the own-SQL builders (it bakes SQL at config-save, not build time) so it lives in its own plan from the own-SQL builder wiring (98-03).
Output: 7 definition files gain the field; ChartConfigPanel + RecordsTableRenderer inject the WHERE; tests lock injection + byte-identical-when-empty.
</objective>
