Express 4.22.2 `res.download(path, filename, options, callback)` -> `res.sendFile` -> send@0.19.2 (verified in research):
- `Accept-Ranges: bytes` by default; `Range: bytes=N-` -> 206 + `Content-Range: bytes N-(len-1)/len`; suffix `bytes=-N` supported; unsatisfiable -> 416 + `Content-Range: bytes */len`; multi/invalid range -> 200 full.
- `If-Range` with the current ETag -> 206; with a stale ETag/date -> 200 full body. ETag is weak `W/"size-mtime"`; keep `etag`/`lastModified` defaults (true).
- `cacheControl: false` suppresses send's default `Cache-Control: public, max-age=0`.
- `res.download` sets `Content-Disposition: attachment; filename="..."` via content-disposition@0.5.4 and ignores a caller-supplied Content-Disposition header.
- Content-Type: `.csv` -> `text/csv; charset=UTF-8`; `.gz` -> `application/gzip`; no Content-Encoding.
- ENOENT between our stat and send's open -> callback receives an error with `code === "ENOENT"` before headers are sent.
