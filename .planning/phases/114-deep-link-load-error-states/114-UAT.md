## Findings outside this phase

- **theme-guard has a systematic hole for colours in global.css rules.** `#cae8ff`
  was not allowlisted individually — `global.css` is exempt WHOLESALE from the hex
  scan (`theme-guard.spec.ts:57`), on the sound reasoning that `:root` blocks
  legitimately contain hex because they ARE the token definitions. That comment
  says the structural guard enforces `var()` in rules instead, but the second
  guard only covers **px/ms literals, not colours**. So any colour literal in a
  global.css RULE (as opposed to `:root`) passes both checks.

  This is a class of bug, not a one-off, and it matches the project's existing
  note that theme-guard misses rgba() and wrong-token usage. Narrowing the
  exemption to `:root` blocks only would catch the whole class, but has real
  blast radius across existing rules — logged for the operator rather than done
  here.
