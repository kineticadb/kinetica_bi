<objective>
Persist a per-dashboard filter display mode (`'topbar' | 'panel'`) server-side, return it (always coalesced to a concrete value) to every viewer on dashboard load, default unconfigured dashboards to `'topbar'` (byte-identical to today), and accept it — validated — on the existing dashboard PATCH. Mirror the field into the web api-client `DashboardDto` type so Phases 107/110 can read it.

Purpose: This is v1.20's ONLY server touch. It is deliberately isolated for a clean BOTH-stack review before the frontend-only panel phases (107+) consume the persisted mode.

Output: `dashboards.filter_display_mode` column + `Dashboard` DTO field + PATCH validation + BOTH-auth-mode supertests + web `DashboardDto` field. NO UI, NO render switch, NO store wiring (those are Phase 107/110).

Scope guard — explicitly NOT in this plan: the designer toggle UI (Phase 110), the top-bar-vs-panel RENDER switch (Phase 107), any zustand store logic beyond carrying the field, any panel component, and NO new RBAC permission (reuse `DASHBOARDS_EDIT`).
</objective>
