FormatSpec discriminated union (LOCKED shape — lives in columnFormatter.ts, the shared contract):
```typescript
export type FormatSpecNumber = {
  kind: "number";
  thousandsSep: boolean;     // true = grouping separator
  decimals: number;          // 0..N fixed decimal places
  currency: false | string;  // false = none; string = symbol PREFIX (default "$"), placed BEFORE the number
  percent: boolean;          // true = append LITERAL % WITHOUT x100
};
export type FormatSpecDate = {
  kind: "date";
  preset: "iso" | "us" | "long" | "us_time" | "long_time" | "custom";
  customPattern?: string;    // only when preset === "custom"; tokens YYYY MM DD HH mm (ss optional)
};
export type FormatSpecD3 = {
  kind: "d3";
  specifier: string;         // raw d3-format string passed verbatim — % DOES x100 here (intentional)
};
export type FormatSpecNone = { kind: "none" }; // explicit no-op (operator cleared a prior spec)
export type FormatSpec = FormatSpecNumber | FormatSpecDate | FormatSpecD3 | FormatSpecNone;
```

CRITICAL percent rule (Pitfall 1): the number PRESET must NOT use d3's `%` type (it x100s). Format numerically with a `.Nf` specifier then append a literal `"%"`. Only `kind:"d3"` passes `%` verbatim to d3.

Date approach (RESEARCH "Building a date formatter"): EXTEND the codebase's hand-rolled UTC approach (UTC getters + MONTH_NAMES) — do NOT add d3-time-format. MONTH_NAMES already exists in columnTypes.ts (formatDatetimeRange pattern at columnTypes.ts:99-178). Inputs may be ISO string, epoch ms, or epoch seconds — normalize to ms before UTC getters. Presets: iso `2026-06-19`, us `06/19/2026`, long `Jun 19, 2026`, us_time `06/19/2026 HH:mm`, long_time `Jun 19, 2026 HH:mm`. Custom pattern: token-replace YYYY/MM/DD/HH/mm (ss optional) using zero-padded UTC parts; wrap in try/catch → raw on error.

defaultFormatKind (RESEARCH "inferDataTypeFromColumn → default FormatSpec.kind"):
```typescript
import { inferDataTypeFromColumn } from "./columnTypes";
export function defaultFormatKind(colName: string, columns: Record<string, string>): FormatSpec["kind"] {
  const dt = inferDataTypeFromColumn(colName, columns);
  if (dt === "number") return "number";
  if (dt === "datetime") return "date";
  return "none";
}
```
NOTE: importing `columnTypes.ts` (a pure type-inference lib, no store/DOM/SQL) is allowed — it is NOT a store/DOM/fetch import. `defaultFormatKind` is for the Plan 03 / Phase 76 picker, never called inside `buildFormatter`.

d3-format dependency (RESEARCH "Standard Stack"): `d3-format@3.1.2` (runtime) + `@types/d3-format@3.0.4` (devDep — d3-format ships NO types). Zero deps, ~18kB. Install scoped to packages/web ONLY: `npm install d3-format --workspace=packages/web` and `npm install --save-dev @types/d3-format --workspace=packages/web`. NO server / SQL coupling.
