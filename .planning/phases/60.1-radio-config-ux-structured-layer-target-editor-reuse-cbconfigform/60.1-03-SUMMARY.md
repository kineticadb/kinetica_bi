## What Was Built

### Task 1: `hideSpatialMode` prop on `KineticaWmsLayerForm`

Added `hideSpatialMode?: boolean` (default false) to `KineticaWmsLayerFormProps`. Destructured in the component with `hideSpatialMode = false`. The SPATIAL MODE `<div className="config-group config-spatial-mode">` block is wrapped in `{!hideSpatialMode && (...)}`. RENDER MODE, TRACK STYLE, raster/heatmap params, CbConfigForm, ZOOM RANGE, and INFO POPUP all still render. Existing callers (LayersModal, MapConfigPanel) pass no argument → default false → SPATIAL MODE renders as before → zero diff for existing callers.

### Task 2: `RadioLayerConfigEditor` — full form embed

Complete rewrite (from 150 lines to 90 lines). Drops the narrow render-mode `<select>` + standalone `CbConfigForm`. Props unchanged (panel passes the same set). New body:
- `const { config: formConfig, info } = snapshotToLayerForm(configPatch)` — seeds form from snapshot
- Renders `<KineticaWmsLayerForm config={formConfig} columns={columns} hideSpatialMode={true} isValid={onCbValid} infoEnabled / infoColumns / infoTemplate + onChangeInfoConfig>` — DATA SOURCE suppressed by omitting `layer`/`onDataSourceChange`
- `onChange` fires `layerFormToSnapshot(nextFormConfig, info)` — strips data-binding/meta keys
- `onChangeInfoConfig` fires `layerFormToSnapshot(formConfig, {...info, ...patch})` — folds info_* into snapshot
- `data-testid="radio-layer-form-${idx}"` wrapper div for spec assertion

### Task 3: `RadioGroupConfigPanel` — two-pane layout + CSS

`OptionRow` now branches on `kind`:
- `kind === "layer"`: renders `.radiogroup-layer-editor` grid (LEFT: Advanced JSON `<details>`; RIGHT: `RadioLayerConfigEditor` with the full form)
- `kind === "widget" | "dynamicView"`: single-column JSON textarea exactly as before

Panel root computes `hasLayerOption = cfg.options.some(o => o.action.target.kind === "layer")` and adds `radiogroup-has-layer-editor` marker class when true.

CSS additions in `global.css`:
- `.modal-config:has(.radiogroup-has-layer-editor) { max-width: min(960px, 92vw); }` — widens modal for layer-target editing only
- `.radiogroup-layer-editor { display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1.4fr); gap: 16px; }` — two-pane grid
- `.radiogroup-layer-editor-right { border-left: 1px solid var(--border-color, var(--border, #3a3a4a)); padding-left: 16px; }` — theme token borders
- `@media (max-width: 720px)` — responsive collapse

### Task 4: `RadioGroupConfigPanel.spec.tsx` — rewritten structured layer editor tests

Added `vi.mock("./KineticaWmsLayerForm")` with a factory that renders RENDER MODE marker, conditionally renders SPATIAL MODE (gated on `!hideSpatialMode`) and DATA SOURCE (gated on `props.layer && props.onDataSourceChange`), and exposes buttons to trigger `onChange` and `onChangeInfoConfig` via user interaction (not synchronously in render — avoids infinite-render loop).

Removed obsolete `radio-layer-rendermode` and `radio-layer-cbform` assertions. Added 7 new/rewritten tests:
1. Full form wrapper present; RENDER MODE marker in DOM; SPATIAL MODE + DATA SOURCE absent; two-pane DOM present; Advanced JSON present
2. Render-mode change → snapshot with `renderMode="classbreak"` and NO `table_id`/`dynamic_view_id`/`spatialMode`/`latColumn`
3. INFO POPUP toggle → `info_enabled: 0` at snapshot top-level
4. Advanced JSON round-trips; invalid JSON shows error + no onChange
5. Non-surfaced `track_config` survives MERGE + adapter round-trip
6. Widget target: no `radio-layer-form`, no two-pane, direct JSON textarea
7. DV target: no `radio-layer-form`, no two-pane, direct JSON textarea
