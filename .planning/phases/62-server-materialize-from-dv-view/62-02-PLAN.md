<objective>
Extend `POST /api/filter/materialize` and `DELETE /api/filter/materialize` (packages/server/src/index.ts) with an additive, back-compat DV PATH. When `body.dynamicViewId` is present, materialize a filtered sub-view of the dynamic view's OWN materialized view: `CREATE OR REPLACE MATERIALIZED VIEW <dv-filter-view> AS (SELECT * FROM <buildDynamicViewName(...)> WHERE <filters>)`. When absent, the existing table path is byte-unchanged. No new route.

Purpose: This is the sole server-side piece of the v1.12 dv-drill-down fix (DVDRILL-V112-03 server portion). It defines the `dynamicViewId` request-body contract that the Phase 63 client (AggregatedWidgetRenderer) will call.
Output: dv-path branch in POST + DELETE; supertests in both auth modes.
</objective>
