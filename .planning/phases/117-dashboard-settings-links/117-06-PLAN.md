  <what-built>
Dashboard settings and edit screens are now reachable by URL:
- `?dashboard=<id>` — the RUNNING dashboard (unchanged; this is the link people already have)
- `?dashboard=<id>&mode=view` — the settings/detail screen
- `?dashboard=<id>&mode=edit` — the edit screen

jsdom proves the state machine: the right URL is written, the right screen mounts, the marker is
preserved, the bar is cleared on leave. It cannot prove three things, which is what these checks are
for: whether the in-place Edit transition FLASHES in a real browser, whether the failure banner
READS correctly in both themes, and whether the running dashboard is genuinely unaffected.
  </what-built>

  <how-to-verify>

work through these in order. Each has an unambiguous PASS condition and a stated failure shape.

1. Open the app, go to Dashboards, click **Open** on any dashboard.
