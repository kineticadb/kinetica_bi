<objective>
Make the browser address bar reflect which dashboard, if any, is open, using the native History API and no new dependency.

Purpose: dashboards become linkable — the address bar is the shareable link (DLINK-V121-01), the browser's Back button is the app's Back (DLINK-V121-06), and leaving a dashboard by ANY route clears its id so a copied URL never describes a screen the user has left (DLINK-V121-07).

Output: one new pure-ish helper module `src/lib/dashboardUrl.ts` with its own spec, five small wiring edits in `DashboardsPage.tsx` (import, Open button, open-branch onBack, popstate listener, DashboardOpen unmount cleanup), and a dedicated component spec.
</objective>

<scope_fence>
This plan WRITES the URL and REACTS to history navigation. It does NOT read the URL on app boot to open a dashboard — that is **Phase 114**, together with the not-permitted and not-found states. The logged-out deep-link flow is **Phase 115**.

Keep these two concerns strictly apart. They are NOT the same thing:
- *"Open a dashboard because the URL says so"* — Phase 114. Nothing here does this.
- *"Keep the address bar honest about what is currently on screen"* — squarely this phase's charter (DLINK-V121-07). Doing this never requires resolving a URL into a dashboard; it only ever REMOVES the param.

Concretely, these are OUT OF SCOPE and must not be added:
- Any parse of `window.location.search` at mount / on first render / in `App.tsx` boot. The only reads are inside a `popstate` handler and inside an unmount cleanup — both are reactions to something that already happened, never a boot-time resolve.
- Any change to `App.tsx`. This plan does not touch `App.tsx` at all.
- Any change to the Phase 7 sessionStorage `RETURN_TO_KEY` block (`App.tsx:167-223`). Phase 115 extends it; do not pre-empt or duplicate it.
- Any handling that re-OPENS a dashboard from the URL. When a `popstate` arrives with the param still present (browser Forward), this plan **reconciles the address bar down to the list** — it never sets `view.mode` to `"open"` and never looks a dashboard up. Say so in a code comment.

    ```ts
    export const DASHBOARD_URL_PARAM = "dashboard";
    export const DASHBOARD_HISTORY_MARKER = "kbiDashboardEntry";

    export function readDashboardIdFromSearch(search: string): number | null {
      const raw = new URLSearchParams(search).get(DASHBOARD_URL_PARAM);
      if (raw === null || !/^\d+$/.test(raw)) return null;   // rejects "", "12abc", "1.5", "-3"
      const id = Number(raw);
      return id > 0 ? id : null;                              // rejects "0"
    }

    export function buildDashboardUrl(
      loc: { pathname: string; search: string; hash: string },
      id: number | null,
    ): string {
      const params = new URLSearchParams(loc.search);
      if (id === null) params.delete(DASHBOARD_URL_PARAM);
      else params.set(DASHBOARD_URL_PARAM, String(id));
      const qs = params.toString();
      return `${loc.pathname}${qs ? `?${qs}` : ""}${loc.hash}`;
    }

    export function openDashboardUrl(id: number): void {
      // Locked decision 3: opening pushes exactly ONE entry, marked as ours so
      // leaveDashboardUrl() knows there is something to pop.
      window.history.pushState(
        { [DASHBOARD_HISTORY_MARKER]: true },
        "",
        buildDashboardUrl(window.location, id),
      );
    }

    export function clearDashboardUrl(): void {
      // DLINK-V121-07: the address bar must never describe a screen the user is not on.
      // replaceState ONLY — we are correcting the CURRENT entry, not navigating and not
      // manufacturing a new one. Also drops our marker from this entry, which is correct:
      // once the param is gone the entry no longer represents an open dashboard.
      window.history.replaceState(null, "", buildDashboardUrl(window.location, null));
    }

    export function leaveDashboardUrl(): "popped" | "wrote" {
      const state = window.history.state as Record<string, unknown> | null;
      if (state && state[DASHBOARD_HISTORY_MARKER] === true) {
        // We pushed this entry — pop it, so the app's Back and the browser's Back
        // are the same action and the stack stays shallow.
        window.history.back();
        return "popped";
      }
      // No entry of ours to pop (e.g. a Phase 114 deep-link arrival). Calling
      // history.back() here would eject the user out of the application entirely,
      // so clear the param in place instead.
      clearDashboardUrl();
      return "wrote";
    }
    ```
