<objective>
Fix GAP-54-01 (CRITICAL): a saved Track+Raster (and Track+Class Break) layer renders ZERO WMS requests — the layer is silent/inert on the map while a latlon layer on the same map fires requests normally.

**CONFIRMED ROOT CAUSE (diagnosed read-only, to be locked by the reproduction test in Task 1):**
`track_config` is a TOP-LEVEL `DashboardLayerDto` column (`layer.track_config`), NOT a key inside `layer.config`. LayersModal.tsx:557-573 proves this — it merges `track_config` INTO the form's config prop for editing, then splits it back OUT to the top-level `onPatch` field on save. So at persist time `layer.config` does NOT contain `track_config`.

In `MapChartRenderer.tsx` Effect 2:
- Line 1037 gates layer creation on `isConfigComplete(cfg)` where `cfg = layer.config`.
- `isConfigComplete` (line 151-154) for `spatialMode === "track"` reads `(config).track_config` and `coalesceTrackConfig`s it. Because `layer.config.track_config` is `undefined`, it coalesces to `{ enabled: false }` with no xCol/yCol → `isConfigComplete` returns **false** → `continue` → **no ImageWMS source created → no request ever fires.**
- Ironically line 1079 passes `track_config: layer.track_config` (the correct top-level field) to `buildWmsParams`, but that code is never reached because line 1037 already skipped the layer.

This asymmetry is exactly why latlon fires (latColumn/lonColumn ARE in `layer.config`, read directly by `isConfigComplete`) and track does not (its columns live on the top-level `track_config` field, invisible to `isConfigComplete`'s `cfg`-only read).

**Fix:** make `isConfigComplete`'s track branch read `track_config` from the same source `buildWmsParams` uses — the top-level DTO field. The minimal, lowest-risk fix is at the Effect 2 call site: pass the merged config (`{ ...cfg, track_config: layer.track_config }`) to `isConfigComplete`, mirroring exactly what LayersModal does for the form and what line 1079 already does for buildWmsParams. (Do NOT change `isConfigComplete`'s signature/contract — it correctly reads `config.track_config`; the caller was feeding it the wrong object.)

Purpose: Close the blocking render gap so Track+Raster and Track+Class Break layers actually paint tiles.
Output: A render-path reproduction test that fails before the fix, the call-site fix, and a buildWmsParams unit test confirming the track branch was never the problem.
</objective>
