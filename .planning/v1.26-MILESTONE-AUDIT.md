## Integration (gsd-integration-checker, static trace)

- **Export E2E:** records Download → dialog → POST /api/exports → runner (snapshot, caps, per-batch session principal, zip/csv writer) → tracker polling → preflight + resumable download (open-download tracking) → Exports page → sweep and boot reconcile. Field names match end to end (compress with gzip alias, format, name, filters, sort; DTO name/dashboardName/widgetTitle/expiresAt). **WIRED.**
- **Row limits:** export batch size is bounded by KINETICA_MAX_ROWS_PER_QUERY, but the total is not (offset paging, exact count check). The line LIMIT+1 probe and 127's "Limited to N rows" notice are mutually exclusive. **WIRED.**
- **/me config:** maxBarGroupBySeriesCap, csvInBrowserMaxRows, maxRowsPerQuery and exportLimits are mapped by fetchMe and applied by both bootstrap and login (shared meToState). **WIRED.**
- **Shared WidgetRenderer:** the export trigger (RecordsTableRenderer) and the line changes (LineRenderer) are separate. **WIRED.**
- **Formula guard on every server CSV path, incl. formatted mode:** **WIRED.**
  - The checker suspected formatted negatives get a leading `'`. The orchestrator tested this and refuted it: d3-format emits U+2212 `−`, so `$−1,234.50` / `−5.00` do not match the guard's leading `-` and pass unprefixed.
  - Formatted output is display text by design; raw mode stays numeric.
