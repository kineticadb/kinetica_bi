### Reviewer notes — three things worth knowing

**1. Table links duplicate the dashboard modules rather than sharing them.** `lib/tableUrl.ts` and `hooks/useDeepLinkTable.ts` are structural siblings of `dashboardUrl.ts` / `useDeepLinkDashboard.ts`, not a shared abstraction. This was deliberate: Phase 116's success criterion required every Phase 113–115 test to pass *unmodified*, and de-duplicating would have forced import-path edits across 132 tests. The standing cost — a fix in one must be mirrored in the other — is recorded as `TLINK-F4`, with the recommendation to extract the shared core when a third linkable entity (Roles/Settings) arrives. Criterion 6 is therefore honestly half-met, and the phase verifier graded it 22/23 rather than passing it outright.

**2. The OIDC auth path has not been verified in a browser.** Operator UAT ran in password mode (`AUTH_MODE=password`). The `kbi_returnTo` sessionStorage carry — the entire reason that storage exists, since only an OIDC full-page redirect destroys the query string — is covered by automated tests and mutation probes but has never been observed live. Named in both `115-UAT.md` and `116-UAT.md` under Coverage Limitation. Worth re-verifying on the next OIDC deployment.

**3. One Phase 114 test was replaced by two.** `App.deeplink.spec.tsx`'s "a pasted link beats the Phase 7 ReturnTo page restore" asserted precedence that Phase 115 deliberately inverts for the session-expiry case. Before amending it, we verified no real code path emits that test's hand-written state for a paste — it is reachable only via a genuine expiry, which is exactly the case Phase 115 exists to handle. Phase 114's intent survives in a replacement test matching the shape the app actually produces, and the file carries a `PHASE 115 AMENDMENT` comment plus a pointer to where the relocated guard now lives. Net coverage rose.
