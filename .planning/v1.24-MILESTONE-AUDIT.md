## PG-1: phases 119 and 120 were never verified

Eight requirements appear in no phase VERIFICATION.md, because two of three phases never ran one.

**Why this is worth recording rather than waving through:** this milestone's defining lesson is that
green gates plus confident paperwork is exactly the state in which four real defects hid. A missing
verifier pass is the same category of absence.

**Why it is not a blocker:** Phase 121 existed precisely to verify 119 and 120's output, and it did
so more stringently than a verifier document would have — a live operator round trip between two
independent databases. It found four defects no automated gate could:

| Defect | Found | Outcome |
|---|---|---|
| REF-9 `spatialTargets[].tableId` never remapped | 121-04 | Fixed `6c6de97` |
| `max_records: 0` (UNLIMITED) rejected at import | 121-04 | Fixed `21e8690`; reopened + re-closed DXIM-V124-11 |
| Custom metrics loaded for the wrong table | 121-04 | Fixed `4a8c117` |
| `config.sql` froze the custom-metric expression | 121-04 | Fixed 121-05/06; reopened + re-closed DXIM-V124-10 |

Retroactive verification of 119/120 is available via `/gsd:validate-phase 119` and `120` if the
record matters more than the substance. My recommendation is to note it and move on: the functional
verification happened, and re-deriving a document for work already proven live is ceremony.

## Integration — clean

No wiring gaps, no orphans, no missing links. Traced:

- **Export/import contract.** Every field `buildDashboardExport` writes is read by
  `validateImportFile`/`applyDashboardImport`. No orphaned write, no unbacked read.
- **REF-1..9 symmetry.** Export's `collect*` and import's `remap*` drive the *same*
  `visitWidgetConfigRefs`/`visitFilterSelectionRefs`. A kind structurally cannot exist on one side
  only — which is the fix for how REF-9 went missing. A deliberate search for a tenth id-valued or
  text-valued environment-specific reference found none.
- **Route ↔ client.** The import gate is an AND of `DASHBOARDS_CREATE` and `DATASETS_MANAGE` on the
  server (two middleware) and `canCreate && hasPermission(DATASETS_MANAGE)` on the client — mirrored
  exactly, so the UI cannot offer what the server refuses.
- **E2E.** Export button → route → envelope → blob download → Import modal → route → Tier-1 validate
  → single-transaction two-pass apply → report rendered verbatim → `refetch()`. No break point.
- **The 121 fix composes.** Metric resolution happens before `fromSwap`, and `MapChartRenderer` was
  checked for the same treatment: map widgets have no `metricId` concept at all, so this is genuine
  non-applicability rather than a missed read-path.
