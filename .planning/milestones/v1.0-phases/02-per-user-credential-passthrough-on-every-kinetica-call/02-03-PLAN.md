<objective>
Refactor the four SQL-shaped Kinetica call sites in `kinetica_bi/server/src/index.ts` to use the new `kineticaSql(req, sql, { route, op, extra? })` helper from Plan 02. The four sites are: `POST /api/sql` (the user-facing SQL proxy at lines 442-475) and the three discovery routes (`schemas` at 367-378, `schemas/:schema/tables` at 380-392, `schemas/:schema/tables/:table/columns` at 394-410) which currently share the local `kineticaSql` helper at lines 333-365. The local helper is DELETED in this plan because its only callers are these three discovery routes.

Purpose: This is the highest-blast-radius refactor in Phase 2 (4 of 5 call sites at once, sharing the SQL contract) and lands the milestone's headline behavior for non-WMS, non-materialize Kinetica access. Once these routes route through the helper, a restricted Kinetica user will see only the schemas/tables/columns they're permitted to read (CRED-06 functionally satisfied at this point, even before WMS and materialize land in later plans).

Output: `index.ts` no longer contains its inline `kineticaSql` helper, no longer references `kineticaUser`/`kineticaPassword` in any of these 4 routes, and 2 new spec files prove per-user credential passthrough end-to-end.
</objective>
