# Requirements: Kinetica BI v1.5 Spatial filtering on map

**Defined:** 2026-05-11
**Core Value:** Click-through data exploration — users drill into chart elements and the entire dashboard filters to that slice of data, enabling fast iterative analysis without writing SQL.

**Milestone Goal:** Users draw bbox / lasso / circle shapes directly on map widgets to filter the dashboard to that spatial region; multiple shapes OR within and AND with column filters via the v1.3 materialize pipeline.

**Phase numbering continues from v1.4 close (Phase 24 → starts at Phase 25).**

---

## v1.5 Requirements

Requirements for this milestone. Each maps to exactly one phase via the roadmap. Reference IDs follow `[CATEGORY]-V15-[NUMBER]`.

### Kinetica Predicate Spike (gates all SQL builder code)

- [x] **SPIKE-V15-01**: Operator-driven spike (Phase 25, 2026-05-11) confirmed `STXY_WITHIN(lon_col, lat_col, ST_GEOMFROMTEXT('POLYGON ((…))')) = 1` (latlon mode, table `demo.nyctaxi`) and `ST_INTERSECTS(geom_col, ST_GEOMFROMTEXT('POLYGON ((…))')) = 1` (WKT mode, table `ki_home.us_states`) execute against the deployed Kinetica instance for representative shapes (4-corner bbox, 64-vertex circle, 150-vertex lasso polygon). ST_WITHIN for WKT mode was rejected as semantically wrong (correctly returned 0 — features must intersect, not be fully contained). See `.planning/phases/25-spatial-predicate-spike/25-SPIKE-NOTES.md`.
- [x] **SPIKE-V15-02**: Spike findings committed to `phases/25-spike/SPIKE-NOTES.md`; runner script preserved at a known commit so future re-runs (e.g., for new Kinetica versions) are one-shot. Decision record: PASS → unblock WHERE-builder; FAIL → escalate (predicate name swap or alternative form).

### Server Spatial WHERE Builder

- [x] **WHERE-V15-01**: Pure server module `kinetica_bi/server/src/lib/spatialWhereClause.ts` exports `buildSpatialOrBlock(shapes, target)` that builds the OR-chain of spatial predicates per shape: `(STXY_WITHIN(lon, lat, ST_GEOMFROMTEXT(wkt1)) = 1 OR STXY_WITHIN(lon, lat, ST_GEOMFROMTEXT(wkt2)) = 1)` for latlon-mode targets; `ST_WITHIN(geom_col, ST_GEOMFROMTEXT(wkt)) = 1` for WKT-mode targets; throws `SpatialFilterWkbDeferredError` for WKB-mode (deferred — TD-V14-WKB-SPIKE).
- [x] **WHERE-V15-02**: Pure server helper `composeWhereClause(columnClause, spatialClause)` produces `(spatial_OR_chain) AND (col_AND_chain)` with correct paren grouping; single-shape edge case still wrapped (`(pred) AND col_filter`); empty spatial chain → returns column-only clause unchanged.
- [x] **WHERE-V15-03**: `POST /api/filter/materialize` request body extended to accept `{ filters: ActiveFilter[], spatialFilters?: SpatialFilter[], spatialTarget?: SpatialTarget }`; endpoint dispatches by `spatialTarget.spatialMode` (latlon → STXY_WITHIN builder; wkt → ST_WITHIN builder; wkb → HTTP 501 mirror of `POST /api/info/query`); composes WHERE clause via `composeWhereClause` before DDL.
- [x] **WHERE-V15-04**: Supertest coverage for column-only / spatial-only / combined / 0-shape / 1-shape / 3-shape OR-composition; OR-clause parenthesis correctness asserted explicitly (V15-P-07 mitigation); both `AUTH_MODE=password` and `AUTH_MODE=oidc` sessions.

### Frontend Spatial Filter Store

- [x] **STORE-V15-01**: New Zustand slice `kinetica_bi/src/store/spatialFilterStore.ts` with flat `Shape[]` (session-only, dashboard-scoped); shape type `{ id, type: 'bbox'|'lasso'|'circle', wkt: string (EPSG:4326), label: string, measurement: string, addedAt: number }`.
- [x] **STORE-V15-02**: Actions `addShape`, `removeShape(id)`, `clearAll()`, `reset()`; auto-generated label `{Type} {N}` where N = sequential per-session draw order (resets on dashboard-switch + logout).
- [x] **STORE-V15-03**: `spatialFilterVersion` counter increments on any shape mutation (add / remove / clearAll); consumed by `AggregatedWidgetRenderer` dep array as the spatial counterpart to v1.2's `filterVersion`.
- [x] **STORE-V15-04**: 5-store reset block: `filterViewStore` → `filterStore` → `infoSelectionStore` → `lastInfoClickContextStore` → `spatialFilterStore` wired into `App.tsx` UNAUTHORIZED + `DashboardsPage.tsx` DashboardOpen cleanup (5th store, no DROP loop — session-only).

### Per-Map Spatial Filter Targets Config

- [x] **TARGET-V15-01**: `widget.config.spatialTargets: SpatialTarget[]` field persisted via existing `PATCH /api/widgets/:id`; shape `{ tableId, spatialMode: 'latlon'|'wkt'|'wkb', lonCol?: string, latCol?: string, spatialCol?: string }`; default empty `[]` for legacy v1.4 widgets (spatial filtering inert until user configures).
- [x] **TARGET-V15-02**: Pure helper module `kinetica_bi/src/lib/spatialTargets.ts`: `getSpatialTargets(widget)`, `isSpatialTargetEligible(target)` (returns false for WKB mode until TD-V14-WKB-SPIKE closes).
- [x] **TARGET-V15-03**: `MapConfigPanel.tsx` gains "Spatial filter targets" section — add/remove rows; per-row table picker + spatial mode picker + spatial column picker(s); WKB row inline-warns "deferred — WKB spatial mode not yet supported"; persists via existing 300ms-debounced auto-save.

### Drawing UX (Toolbar, Modes, OL Interactions)

- [x] **DRAW-V15-01**: `MapDrawToolbar.tsx` — React-rendered absolutely-positioned overlay placed alongside the existing OL zoom controls (NOT an `ol/control/Control` subclass — anti-pattern per ARCHITECTURE.md, root-cause family of GAP-24-01-A / GAP-24-02-A); 5 mutually-exclusive mode icons (Pan / Info / Bbox / Lasso / Circle) + "Clear all spatial filters" trash icon (visible only when `shapes.length > 0`).
- [x] **DRAW-V15-02**: Mode local state in `MapChartRenderer` via `useState`; active mode receives depressed/highlighted style + cursor change (crosshair for draws, pointer for Info, grab for Pan) via `map.getViewport().style.cursor`; `previousMode` stored for Info auto-restore (operator-included differentiator).
- [x] **DRAW-V15-03**: Existing Effect 6 (v1.4 singleclick info-popup) gains mode-guard as its first line: `if (drawMode !== 'pan' && drawMode !== 'info') return` reading from `useSpatialFilterStore.getState()` (not closed-over selector — V15-P-01 mitigation). The mode is read via `useRef` inside the singleclick callback for stale-closure safety.
- [x] **DRAW-V15-04**: OL Draw interaction mounted in new Effect 8 per active draw mode: bbox via `type: 'Circle', geometryFunction: createBox()`; lasso via `type: 'Polygon', freehand: true`; circle via `type: 'Circle', geometryFunction: createRegularPolygon(64)`; ESC keydown calls `abortDrawing()` and switches back to `previousMode`.
- [x] **DRAW-V15-05**: Live measurement tooltip follows cursor during draw — circle radius (km/m switchover at 1 km), bbox W×H (km/m), lasso area (km²/m²); ALL measurements via `ol/sphere.getDistance` / `getArea` (NEVER raw EPSG:3857 — V15-P-04 mitigation).
- [x] **DRAW-V15-06**: `drawend` produces shape `{ wkt: EPSG:4326, label, measurement }` via `ol/format/WKT.writeGeometry` with `{ dataProjection: 'EPSG:4326', featureProjection: 'EPSG:3857' }` (always `.clone()` before transform — STACK.md lock); rejects zero/near-zero shapes (<10 screen px² area) with toast "Shape too small — try again"; Douglas-Peucker simplifies lasso silently via `geometry.simplify(map.getView().getResolution() * 2)` before store add.

### Shape Display & Cross-Map Rendering

- [x] **SHAPE-V15-01**: `VectorLayer` + `VectorSource` added to MapChartRenderer Effect 1 setup; semi-transparent fill (~10% opacity), 2px solid outline, color-coded; subscribed to `useSpatialFilterStore` via primitive `shapesKey` selector (joined IDs string — PITFALL S-02 mitigation).
- [x] **SHAPE-V15-02**: New Effect 7 syncs store shapes → OL features by re-reading WKT into OL geometry on `shapesKey` change; clears stale features atomically before re-adding (avoids feature-id collision on edit).
- [x] **SHAPE-V15-03**: Persistent measurement label per committed shape via `ol/Overlay` anchored to geometry centroid; text mirrors live-draw label (e.g., "2.5 km", "5km × 3km", "12.4 km²"); follows pan/zoom automatically (Overlay handles repositioning).
- [x] **SHAPE-V15-04**: Click on a committed shape on the map selects it (visual highlight on outline); Delete keydown removes it from the store; selection mode-gated to draw modes only (NOT Info mode — would conflict with v1.4 singleclick popup); `mountedRef` cleanup-gate (v1.4 Phase 24-06) and source-listener cleanup pattern (v1.4 Phase 24-04) extended to cover new Effects 7-8 and VectorSource listeners.

### FilterBar Integration

- [x] **CHIP-V15-01**: `FilterBar.tsx` renders spatial chips mixed in the SAME row as column-filter chips (operator-locked "Mixed chips, one per shape"); chip label `{Type} {N}` (e.g., "Bbox 1") with measurement as secondary text in muted style (operator-included differentiator): "Bbox 1 (5km × 3km)" / "Circle 1 (2.5 km)" / "Lasso 1 (12.4 km²)".
- [x] **CHIP-V15-02**: Chip × calls `removeShape(id)` which triggers re-materialize via `spatialFilterVersion` bump; per-map "Clear all spatial filters" toolbar button (DRAW-V15-01) calls `clearAll()` (dashboard-scoped — clears every shape in the store, not just shapes filtering this map's tables).

### Materialize Trigger Extension

- [x] **MAT-V15-01**: `AggregatedWidgetRenderer` Effect 1 dep array gains `spatialFilterVersion` alongside existing `filterVersion`; the existing 300ms debounce + `materializeAbortRef` + `markMaterializing → materializeFilter → setView` sequence is reused identically — single materialize chokepoint preserved (v1.3 invariant); no new component, no trigger in `MapChartRenderer`.
- [x] **MAT-V15-02**: `materializeFilter` client helper (`kinetica_bi/src/api/client.ts`) body type extends to include `spatialFilters?: SpatialFilter[]` and per-target `spatialTarget?: SpatialTarget`; `_mv` (materializeVersion) cache-buster increments on every materialize call regardless of trigger (shape OR column change — single counter).
- [x] **MAT-V15-03**: Eligibility gates at three points (mirrors v1.4 info-query pattern): (1) config-time — `MapConfigPanel` warns when WKB mode selected, (2) materialize-time — `isSpatialTargetEligible(target)` skips ineligible (WKB) targets silently, (3) server-time — `buildSpatialOrBlock` throws `SpatialFilterWkbDeferredError` → endpoint returns HTTP 501 mirroring v1.4 info-query.

## Out of Scope (v1.5)

Explicitly excluded with reasoning. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| WKB-binary spatial filter target support | Carried forward as TD-V14-WKB-SPIKE — operator has no reachable WKB column; same blocker that deferred v1.4 SPATIAL-V14-03. Endpoint returns HTTP 501. |
| Vertex editing of committed shapes (OL Modify) | Requires shape-selection state orthogonal to draw state, conflicts with v1.4 Info singleclick handler. Kepler.gl peer ships only delete-and-redraw. v1.6+. |
| Per-shape AND / OR / SUBTRACT boolean toggle | Anti-feature for non-GIS BI users — implicit OR is the industry-confirmed default (ArcGIS Dashboards, Kepler.gl). Adds mode complexity before users understand the feature. |
| Per-shape spatial-target override at draw-end | Operator locked per-map config only; every shape filters all map-configured targets uniformly. |
| Shape persistence across sessions (SQLite) | Session-only mirrors v1.3 `useFilterStore` / v1.4 `useInfoSelectionStore` reset contract — operator-locked. |
| Shareable spatial-filter URLs | Same trade-offs as shareable column-filter URLs (deferred in v1.3 research). |
| Import / export GeoJSON / KML | No team need validated; defers core exploration scope; v1.6+. |
| Snap-to-feature drawing | No peer BI tool ships this at v1; significant complexity for marginal gain. |
| Hover-only measurement tooltip (no persistent label) | Conflicts with v1.4 Info singleclick handler; persistent label is the operator-locked + differentiator-confirmed pattern. |
| Modifier-key draw activation (Shift+drag etc.) | Operator chose explicit toolbar UX; modifier-keys are hidden affordances and fail discoverability. |
| True `STXY_DWITHIN` sphere-distance circle predicate | 64-gon WKT POLYGON approximation has ~0.5% area error at the equator — acceptable for BI spatial exploration. v1.6 if precise GIS use case emerges. |
| Shape highlight on chip hover | Deferred from v1.5 differentiator scoping (operator selected Measurement-in-chip + Info-auto-restore only). |
| Named/saved shapes | Auto-labeling "{Type} {N}" is sufficient for session-only scope. |
| `ol/control/Control` subclass for toolbar | Anti-pattern — root-cause family of GAP-24-01-A and GAP-24-02-A (OL/React reconciler conflict). Toolbar is React-rendered absolutely-positioned overlay instead. |
