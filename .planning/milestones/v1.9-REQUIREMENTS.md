# Requirements: Kinetica BI — v1.9 Better Track Rendering

**Defined:** 2026-06-07
**Core Value:** Click-through data exploration — users drill into chart elements and the entire dashboard filters to that slice of data, enabling fast iterative analysis without writing SQL.
**Milestone goal:** Track rendering becomes a first-class, discoverable workflow in map layer config — a selectable spatial mode that drives sensible column defaults, narrows render modes to what applies, and shows only the parameters that matter.

**Locked decisions (from milestone questioning, 2026-06-07):** Track is a SPATIAL MODE (replacing the v1.7 auto-detect sub-section + override checkbox); column pickers with TRACKID/TIMESTAMP defaults; auto-suggest on column-shape match; render modes narrow to Raster + Class Break under Track; Track+Raster shows track params only; Track+CB shows CB builder + track params (per-break point/shape advanced hidden); proper color picker for track colors; HARD CUTOVER for old-model track layers (reconfigure overlay, Phase 12 precedent, no auto-migration).

## v1.9 Requirements

### Track Spatial Mode

- [x] **TRACKMODE-V19-01**: User can select **Track** as a spatial mode in the Map Layers form (alongside lat/lon, WKT, WKB)
- [x] **TRACKMODE-V19-02**: Selecting Track reveals column pickers — x, y, track ID, ordering — with track ID defaulting to `TRACKID` and ordering defaulting to `TIMESTAMP` when the table has those columns (case-insensitive match)
- [x] **TRACKMODE-V19-03**: Track mode is auto-suggested when the layer's table matches the track column shape (TRACKID + x + y + TIMESTAMP, case-insensitive); the user can freely switch to another mode
- [x] **TRACKMODE-V19-04**: The v1.7 track sub-section + "Treat as track table" override checkbox are removed — the spatial-mode picker is the single entry point for track rendering

### Render Modes & Param Surfaces

- [x] **RENDER-V19-01**: With Track selected, the render-mode picker offers only **Raster** and **Class Break** (heatmap not offered)
- [x] **RENDER-V19-02**: Track + Raster shows only track styling params (head/trail color/size/shape, line width) — point/shapeline/shapefill parameter groups hidden
- [x] **RENDER-V19-03**: Track + Class Break shows the CB break builder + track params; per-break point/shape advanced params hidden
- [x] **RENDER-V19-04**: WMS emission stays correct per combo (DOTRACKS + TRACK_* under raster; comma-separated TRACK_* under cb_raster per the Phase 37 spike Decision Record) — regression-locked incl. lastEmittedParamsRef fingerprint coverage

### Color Picker

- [x] **COLOR-V19-01**: Track head/trail colors use a proper color picker (with alpha support) instead of raw AARRGGBB text inputs

### Cutover

- [x] **CUTOVER-V19-01**: The old track model is removed cleanly — TrackSubSection/override code deleted, stale `track_config` on any existing layer is ignored without error (operator confirmed nobody uses track rendering yet; NO reconfigure overlay needed); existing latlon/WKT/WKB layers unaffected

### Verification

- [x] **VERIFY-V19-01**: Live operator walk-through — configure a track layer end-to-end via the new flow (defaults, auto-suggest, both render modes, param surfaces, color picker, cutover overlay) + frontend/server test gates green at established baselines (frontend 100% green; server set-based known-flaky gate)

## v1.9 Gap-Closure Requirements (added after Phase 54 UAT, 2026-06-07)

- [x] **TRACKFIX-V19-01** (GAP-54-01, CRITICAL): A saved track-mode layer renders on the map — buildWmsParams emits a complete track WMS request (DOTRACKS + LAYERS + X_ATTR/Y_ATTR + TRACK_* / track-id+order attrs) and MapChartRenderer creates the ImageWMS source so a request actually fires on load/zoom. Verified by reproduction test through buildWmsParams + the render path, NOT just the gate.
- [x] **TRACKFIX-V19-02** (GAP-54-03): TRACK STYLE section gains trail line styling controls — TRACKLINECOLOR (color+alpha idiom) and TRACKLINEWIDTH — persisted into track_config and emitted via the existing TRACKLINECOLORS/TRACKLINEWIDTHS params.
- [x] **TRACKFIX-V19-03**: Re-walk §2 (Track+Raster) + §3 (Track+Class Break) of 54-UAT.md — PASS. No POINT*/SHAPE* in request; all 8 TRACK_* params present with correct names (incl. TRACKHEADSHAPES + TRACKMARKERSHAPES distinct); head/line/marker controls visible and effective; tiles render reflecting head/line/marker styling. Per-break categorical CB track coloring confirmed by operator re-walk 2026-06-08.
- [x] **TRACKFIX-V19-04** (GAP-54-05): Under spatialMode==="track", the WMS request does NOT emit the non-track point/shape params — POINTCOLORS, POINTOPACITY, POINTSIZES, POINTSHAPES, SHAPEFILLCOLORS, SHAPELINECOLORS, SHAPELINEWIDTHS are suppressed (track requests carry only TRACK_*/DOTRACKS/spatial-attr params, plus CB_* under classbreak).
- [x] **TRACKFIX-V19-05** (GAP-54-06): The full Kinetica TRACK_* visual param surface is emitted AND has UI controls in the TRACK STYLE section, each defaulting to Kinetica's documented default:
    - Head: TRACKHEADCOLORS (color+alpha; default FF/FFFFFF white), TRACKHEADSHAPES (shape dropdown; default circle), TRACKHEADSIZES (0-20; default 10)
    - Line: TRACKLINECOLORS (color+alpha; default FF/00FF00 green), TRACKLINEWIDTHS (0-20, 0=no line; default 3)
    - Marker (track points): TRACKMARKERCOLORS (color+alpha; default FF/0000FF blue), TRACKMARKERSHAPES (shape dropdown incl. "none"; default none), TRACKMARKERSIZES (0-20; default 2)
    - Head shape emits TRACKHEADSHAPES (NOT TRACKMARKERSHAPES — corrects the OQ-9 misnaming); marker shape is a distinct control emitting TRACKMARKERSHAPES.
    - Shape dropdowns offer the full Kinetica list: none, circle, dash, diamond, dot, hollowcircle, hollowdiamond, hollowsquare, hollowsquarewithplus, pipe, plus, square (marker also allows SYMBOLCODE — optional). SYMBOLROTATIONS + WORLDLAYERS are OUT of v1.9.
- [x] **TRACKFIX-V19-06** (GAP-54-07): Categorical per-break track coloring under Track + Class Break.
    - WMS emission: under track+classbreak, TRACKHEADCOLORS + TRACKLINECOLORS + TRACKMARKERCOLORS are each the comma-separated list of the per-break colors (cb_config.breaks[].color, normalized AARRGGBB), positionally matching CB_VALS — NOT the single TRACK STYLE color replicated. One break color drives all three track color params for that class. The non-color track params (TRACKHEADSHAPES/SIZES, TRACKMARKERSHAPES/SIZES, TRACKLINEWIDTHS) stay uniform (single value expanded ×N).
    - UI: under Track + Class Break the form shows the FULL normal CB builder (CB column, method, auto-suggest, N, color theme, per-break rows with per-break color picker) — same as a non-track CB layer; per-break point/shape advanced panels stay hidden (trackContext). The single-color TRACK STYLE color controls (Head color, Track line color, Marker color + their alpha) are HIDDEN under classbreak (the breaks define color); head/marker shape+size and line width stay visible as uniform controls.
    - Confirmed by operator live §3 re-walk 2026-06-08 (Kinetica renders per-break track colors correctly).
- [x] **TRACKFIX-V19-07** (GAP-54-08): The map info popup works on track-mode layers — clicking a track point fires POST /api/info/query and returns records. Root cause (same class as GAP-54-01): buildSpatialColumns(cfg) reads cfg.track_config which is undefined (track_config is a top-level DashboardLayerDto field), returns null → info fan-out skips the layer (errorCount++) → "Failed to fetch info" toast with NO network call. Fix: buildSpatialColumns accepts track_config (mirror buildWmsParams' layerJsonFields pattern); thread layer.track_config at all 3 call sites (MapChartRenderer info handler + InfoSelectionView dropdown-switch + Load-more). Track resolves to latlon query via xCol/yCol.
- [x] **TRACKFIX-V19-08** (GAP-54-09): A spatial-filter target configured for a track-shaped table actually filters. ROOT CAUSE (operator-confirmed: target row shows mode "Track"/none): MapConfigPanel's spatial-target section stores spatialMode "track" (autoSuggestSpatialMode now returns it for track-shaped tables), but SpatialTarget is a 3-mode wire union and isSpatialTargetEligible has no track branch → target ineligible → draw-to-filter no-ops. FIX (keep-manual-targets model): in the spatial-target section, translate "track"→"latlon" with lonCol=xCol/latCol=yCol at ALL target paths (new-row autoSuggest, changeTable, changeMode) AND never offer/store "track" as a target mode — a track-shaped table's target auto-selects Lat/Lon with X/Y prefilled. SpatialTarget union stays 3-mode; server untouched. Verified: a track-table target stored from MapConfigPanel is {spatialMode:"latlon", lonCol, latCol} and isSpatialTargetEligible returns true; drawing a shape materializes + filters.
- [x] **TRACKFIX-V19-09** (GAP-54-10, closes carried TD-V15-MAP-ONLY-TRIGGER): Drawing a spatial shape filters a table that is shown ONLY on a map widget (no aggregated-chart/records-table widget on that table to trigger the materialize). ROOT CAUSE (server confirmed CORRECT; not a track bug): materializeFilter is only fired by AggregatedWidgetRenderer/RecordsTableRenderer Effect 1 for their OWN tableId (WidgetRenderer.tsx:421); MapChartRenderer is a pure consumer (0 materializeFilter calls) — so a map-only table never triggers. FIX: a DASHBOARD-SCOPE effect fires materializeFilter for each table that has (a) an eligible spatial target via aggregateSpatialTargetsByTable AND (b) drawn shapes AND (c) NO aggregated/records widget already triggering it — deduped against the existing in-flight materialize Promise cache (keyed dashboardId:tableId, v1.6) so it NEVER doubles up with the sole-trigger path. Preserves the Phase 30 sole-trigger invariant for tables that DO have a chart/records widget (those still trigger there; the map-side effect skips them). Frontend only; server + spatialWhereClause unchanged. Mirrors the useDynamicViewMaterializeChain dashboard-scope orchestrator precedent (Phase 35).
