# Requirements: Kinetica BI — v1.15 Column Formatting & View Lifecycle

**Defined:** 2026-06-19
**Core Value:** Click-through data exploration — users drill into chart elements and the entire dashboard filters to that slice of data, enabling fast iterative analysis without writing SQL.

## v1.15 Requirements

Five categories across three feature areas: column formatting/labels (COLCFG + COLEDIT + COLAPPLY), view-TTL keep-alive (TTLKEEP), and app-settings infrastructure (SETTINGS), plus a milestone verification gate (VERIFY). NOT frontend-only — server tables/endpoints + a new permission.

### Column Display Config — Foundation (COLCFG)

- [x] **COLCFG-V115-01**: A new GLOBAL per-table column display config (custom label + format spec, keyed by `table_id` + `column_name`) is persisted server-side with CRUD endpoints; it is reused across every dashboard that uses that table.
- [x] **COLCFG-V115-02**: A pure client-side formatter library formats values WITHOUT changing the SQL sent to Kinetica — numbers (thousands separators, fixed decimal places, currency with a configurable symbol, percent) plus an advanced d3-format string; timestamps/dates (preset formats + a custom date pattern). Invalid/empty config falls back to the raw value.
- [x] **COLCFG-V115-03**: A client store + helpers load a table's column display config and resolve, for any column, its display label (falling back to the raw column name) and its value formatter (falling back to identity).

### Column Formatting Editor (COLEDIT)

- [x] **COLEDIT-V115-01**: Operator can open a per-table Column Formatting editor (reached from the Tables area) that lists the table's columns with their detected types.
- [x] **COLEDIT-V115-02**: Per column, the operator can set a custom display label (e.g. `Device_Manufacturer` → "Device Manufacturer"); clearing it reverts to the raw column name.
- [x] **COLEDIT-V115-03**: Per column, the operator can choose a format — number (commas / decimal places / currency symbol / percent), date (preset or custom pattern), or advanced d3-format string — with a LIVE PREVIEW of a sample value; Save persists to the global per-table config.

### Apply Labels + Formatting at Render Surfaces (COLAPPLY)

- [x] **COLAPPLY-V115-01**: The Records Table visualization shows the custom label on column headers and the formatted value in cells.
- [x] **COLAPPLY-V115-02**: Chart tooltips AND chart axis titles / in-chart series legends show the custom label, and tooltip values are formatted per the column's format spec.
- [x] **COLAPPLY-V115-03**: Map info popups (both template `{column}` substitution mode and key/value mode) show the custom label + formatted value.
- [x] **COLAPPLY-V115-04**: The map layers legend (`LayersLegendPanel`) is explicitly NOT affected — it continues to render layer/break config with no column label/format applied.

### View TTL Keep-Alive (TTLKEEP)

- [x] **TTLKEEP-V115-01**: While a dashboard is open, the client fires a lightweight "get first records" touch on each live materialized view (filter-views + dynamic-views) a configurable lead-time before its TTL expiry, re-arming after each touch, so an idle dashboard does not hit expired views.
- [ ] **TTLKEEP-V115-02**: It is verified against the deployed Kinetica that reading a materialized view resets its TTL (so the touch keeps it alive); if a read does NOT reset TTL, re-materialize is the documented fallback mechanism.

### Env-Driven TTL Defaults (SETTINGS)

> Revised 2026-06-19: descoped from a runtime app-settings store/UI/permission to **environment-variable config** (deploy-time, read once at boot). See `.planning/phases/74-app-settings-infrastructure-ttl-defaults/74-CONTEXT.md`.

- [x] **SETTINGS-V115-01**: Both TTL values are configured via environment variables read once at boot (following the `AUTH_MODE` pattern + ARCHITECTURE.md AP-5), with built-in defaults; an invalid/missing value falls back to its default with a boot warning. No SQLite store, no CRUD endpoints, no new permission, no admin UI.
- [x] **SETTINGS-V115-02**: A `DEFAULT_VIEW_TTL_MINUTES` env var (default 5) controls the TTL used when creating filter-views AND dynamic-views — replacing the hardcoded `TTL = 5` at all THREE materialize sites (`index.ts:967` filter-on-dynamic-view, `:1053` filter-materialize, `:1716` dynamic-view materialize), including the `expiresAt` each returns; the client's expiry tracking reflects the configured value.
- [x] **SETTINGS-V115-03**: A `TTL_KEEPALIVE_LEAD_MINUTES` env var (default 1) controls how many minutes before expiry the keep-alive touch fires; it is exposed to the client top-level on `GET /api/me` (as `ttlKeepaliveLeadMinutes`) and the keep-alive (TTLKEEP-V115-01) reads it from there.

### Verification (VERIFY)

- [ ] **VERIFY-V115-01**: The whole milestone is proven via green automated gates on BOTH stacks (server supertests both auth modes + server `tsc` + server vitest set-based ⊆ TD-V16-TEST-ISOLATION; frontend vitest 100% from `packages/web` + web `tsc` + theme-guard) AND a blocking live operator walk-through (column formatting/labels across all surfaces incl. legend-exclusion, env-driven TTL flow (DEFAULT_VIEW_TTL_MINUTES / TTL_KEEPALIVE_LEAD_MINUTES), keep-alive), with a compiled verification record and in-session repro-test-driven gap fixes re-walked PASS.

## Out of Scope

Explicitly excluded for v1.15. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Server-side / SQL-level formatting (formatting in Kinetica) | Decision (2026-06-19): formatting is CLIENT-SIDE only — never alters the SQL sent to Kinetica |
| Column labels/formatting in the map layers legend | Decision: legend renders layer/break config, not column data — explicitly excluded |
| Per-dashboard (per dashboard+table) formatting overrides | Decision: config is GLOBAL per-table, reused everywhere; per-dashboard overrides deferred |
| Conditional / value-based formatting (color scales, thresholds on cell values) | Out of scope; this milestone is static label + value-format only |
| Re-materialize-based keep-alive as the primary mechanism | Touch-query is primary (verify-live); re-materialize is only the documented fallback |
| General app-settings catalog beyond the two TTL settings | Only `default_view_ttl_minutes` + `ttl_keepalive_lead_minutes` this milestone; the store is extensible but no other settings are in scope |
