## 🚧 v1.14 Class-Break & Chart Config Refinements (In Progress)

**Milestone Goal:** Three targeted, independent, FRONTEND-ONLY refinements to map class-break rendering and time/numeric line charts — a numeric `<other>` catch-all bucket, spatial-mode-aware SHAPE* field hiding for lat/lon point layers, and a group-by dimension for the timeline + numeric-line charts — closed with a blocking live operator walk-through.

All three features live entirely in `packages/web` and run through the existing `/api/sql` + WMS-param paths (no new server routes). They are mutually independent (no cross-feature dependency), so Phases 70/71/72 may execute in any order or in parallel; Phase 73 verifies all three after they land.

### Phase 70: Numeric `<other>` Catch-All Bucket
**Goal**: Operators can add an `<other>` catch-all bucket to a NUMERIC class-break config (mirroring the categorical `<other>` shipped in v1.7 Phase 39) — emitted into the Kinetica WMS `CB_VALS` string as a literal `<other>` after the numeric ranges, default-ON for new/edited configs only, with its own per-break color/style in the form and legend.
**Depends on**: Nothing (independent feature)
**Requirements**: CBOTHER-V114-01, CBOTHER-V114-02, CBOTHER-V114-03
**Stack**: FRONTEND-ONLY (`packages/web`) — `lib/cbConfig.ts`, `lib/wmsUrlBuilder.ts:372-418` (numeric `CB_VALS` branch ~392), `components/charts/CbConfigForm.tsx` (`<other>` toggle ~660-673 + numeric break builder). Flag any server diff.
**Success Criteria** (what must be TRUE):
  1. With the `<other>` toggle ON, a numeric class-break layer renders an `<other>` catch-all on the map and its `CB_VALS` string ends with the literal `<other>` after the numeric ranges (e.g. `1:3,3:5,<other>`).
  2. The `<other>` toggle is ON by default when an operator creates a new numeric class-break config or re-saves an existing one; a previously-saved numeric layer that has no stored `<other>` flag renders exactly as it did before this change (no silent injection).
  3. The numeric `<other>` row appears in `CbConfigForm` consistently with the categorical `<other>` row — a read-only value/chip with an assignable per-break color/style — and that color shows for the catch-all bucket in both the legend and on the map.
  4. Toggling `<other>` off on a numeric config removes the `<other>` token from `CB_VALS` and the catch-all bucket from the legend/map.
**Plans**: 1 plan
- [ ] 70-01-PLAN.md — numeric CB_VALS <other> emission + form toggle/default-on/validation + regression-locked preservation invariant

### Phase 71: SHAPE* Hidden for Lat/Lon Point Layers
**Goal**: When a layer's spatial mode is `latlon` (points), the SHAPE* style fields are hidden in both the layer-level raster form and the per-break advanced panel AND their WMS params are suppressed — so SHAPE* values (which don't apply to points) neither confuse operators nor leak into the rendered point layer. Mirrors the v1.9 POINT*/SHAPE* suppression under track mode.
**Depends on**: Nothing (independent feature)
**Requirements**: SHAPE-V114-01, SHAPE-V114-02, SHAPE-V114-03
**Stack**: FRONTEND-ONLY (`packages/web`) — `KineticaWmsLayerForm.tsx:1184-1313` (layer-level raster SHAPE* fields), `CbConfigForm.tsx:948-1056` (per-break advanced SHAPE* fields), `wmsUrlBuilder.ts:340-349` (SHAPE* emission); `SpatialMode` at `lib/columnTypes.ts:242`. Flag any server diff.
**Success Criteria** (what must be TRUE):
  1. When spatial mode = `latlon`, the SHAPEFILLCOLOR / SHAPELINECOLOR / SHAPELINEWIDTH fields are hidden in the layer-level raster config (`KineticaWmsLayerForm`) for point raster mode, and remain visible for non-latlon modes (e.g. wkt).
  2. When spatial mode = `latlon`, the per-break shapeFillColor / shapeLineColor / shapeLineWidth advanced fields are hidden in `CbConfigForm` for class-break (cb) raster mode, and remain visible for non-latlon modes.
  3. For a `latlon` layer, the rendered WMS request omits SHAPEFILLCOLORS / SHAPELINECOLORS / SHAPELINEWIDTHS even when SHAPE* values were saved before this change or carried over from a switched-to-latlon layer — so stale SHAPE* values do not leak into the point layer.
  4. Switching a layer's spatial mode away from `latlon` re-reveals the SHAPE* fields and resumes emitting their WMS params.
**Plans**: 2 plans (Wave 1, parallel — no file overlap)
- [ ] 71-01-PLAN.md — Hide SHAPE* fields in layer raster form + per-break cb panel for latlon (SHAPE-V114-01, -02)
- [ ] 71-02-PLAN.md — Suppress SHAPE* WMS emission for latlon in raster + classbreak branches; leak-prevention regression tests (SHAPE-V114-03)

### Phase 72: Group-By for Timeline + Numeric-Line Charts
**Goal**: Operators can set an optional group-by dimension on the Timeline and Numeric-Line charts (mirroring the existing bar/line/pie group-by pattern); when set, the chart renders one color-coded series per group value over a SINGLE metric, with a top-N group cap; clearing it returns to ungrouped multi-metric behavior.
**Depends on**: Nothing (independent feature)
**Requirements**: GROUP-V114-01, GROUP-V114-02, GROUP-V114-03, GROUP-V114-04
**Stack**: FRONTEND-ONLY (`packages/web`) — `TimelineConfigPanel.tsx` + `TimelineRenderer.tsx` (+ `definitions/timeline.ts`), `NumericLineConfigPanel.tsx` + `NumericLineRenderer.tsx` (+ `definitions/numericline.ts`); group-by SQL pattern reused from `ChartConfigPanel.tsx:268-321`. Both charts are `usesAggregation:false` (own their SQL lifecycle — NOT routed through `AggregatedWidgetRenderer`). Flag any server diff.
**Success Criteria** (what must be TRUE):
  1. An operator can set an optional "Group By" dimension column on the Timeline chart via `TimelineConfigPanel`, and clearing it returns the chart to its ungrouped (multi-metric) behavior.
  2. An operator can set an optional "Group By" dimension column on the Numeric-Line chart via `NumericLineConfigPanel`, and clearing it returns the chart to its ungrouped behavior.
  3. When a group-by dimension is set, the config UI restricts the chart to a SINGLE metric (each rendered series = one group value); multi-metric (1–4) is selectable only when no group-by is set — the UI enforces the mutual exclusion.
  4. With a group-by set, the chart's SQL emits `GROUP BY <dimension>` alongside the existing time/x bin and the renderer plots one color-coded series per group value, capped at a sensible top-N so a high-cardinality dimension does not explode the chart.
**Plans**: 3 plans (Wave 1: SQL builders + shared helper; Wave 2: Timeline + Numeric-Line config panels & renderers, parallel)
- [ ] 72-01-PLAN.md — Optional group-by arg on buildTimelineSql/buildNumericLineSql (ungrouped byte-identical) + groupedSeries.ts helper (MAX_SERIES/top-N/pivot) + specs (GROUP-V114-04 SQL)
- [ ] 72-02-PLAN.md — Timeline Group By picker (single-metric-when-grouped) + grouped N-series renderer (shared Y-axis, top-12-of-N, drag preserved) (GROUP-V114-01, -03, -04)
- [ ] 72-03-PLAN.md — Numeric-Line Group By picker (single-metric-when-grouped) + grouped N-series renderer (numeric-bucket pivot, top-12-of-N, drag preserved) (GROUP-V114-02, -03, -04)
