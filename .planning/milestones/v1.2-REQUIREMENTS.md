# Requirements: Kinetica BI

**Defined:** 2026-05-04
**Core Value:** Click-through data exploration over Kinetica-backed dashboards.
**Milestone:** v1.2 — Interactive Dashboards

## v1.2 Requirements

Requirements for the Interactive Dashboards milestone. Adds the project's first dashboard-experience feature set: a new map chart powered by Kinetica's WMS endpoint, click-driven drill-down across all chart types, and automatic cross-chart filter coordination for charts pointed at the same Kinetica table. All built on a shared transient filter store; no persistence-layer changes.

### Filter Foundation

The cross-chart filter state model that everything else writes to or reads from. Must be locked correctly on day 1 — store shape decisions are expensive to retrofit.

- [x] **FILT-01**: A new `useFilterStore` Zustand slice holds active filters per table — keyed by `tableId: number` (`Record<tableId, ActiveFilter[]>`), transient (client memory only — no persistence). `addFilter` REPLACES any existing filter on the same column rather than appending (last-click-wins). A 10-filter cap per table prevents unbounded query degradation. A `filterVersion: number` counter increments on every add/remove/clear so consumers can subscribe to a primitive-typed dep that always changes.
- [x] **FILT-02**: `AggregatedWidgetRenderer` subscribes to the filter store and re-runs its underlying SQL whenever the filter set for its table changes. The active WHERE clause is injected into the chart's base SQL via a `injectWhereClause(baseSql, whereClause)` utility. In-flight fetches are cancelled via `AbortController` so stale results from a prior filter state can never overwrite fresh data.
- [x] **FILT-03**: A SQL-safe filter-builder utility (`buildEqualityFilter` + `escapeKineticaStringLiteral` + `IS NULL` handling for null values) ships in the same plan as the filter store. The escape utility is the only sanctioned way to interpolate user-clicked values into SQL strings. `column = NULL` is silently rewritten to `column IS NULL` because SQL three-valued logic makes the literal form always-false.
- [x] **FILT-04**: When a filter changes on a table that a map chart is rendering, the map's WMS tiles are invalidated and refetched via `TileWMS.updateParams()` with the new server-side filter param (`QUERY` or equivalent — confirmed via spike). The `/api/wms` proxy route sets `Cache-Control: no-store` so neither the browser nor any intermediate cache serves stale tiles after a filter change OR after a per-user OIDC token rotation.

### Drill-Down (existing chart types)

Wire click-to-filter on the 5 existing aggregated chart types. Each chart's click handler maps the clicked element to a `(column, value)` pair that gets added to the table's filter set.

- [x] **DRILL-01**: Clicking an interactive element on a bar chart (segment), pie chart (slice), line chart (data point), scatter chart (point), or table chart (row) calls the configured drill-down handler with the clicked element's `(column, value)`, which dispatches `addFilter` on the chart's table in the filter store. Per-chart-type click contracts are documented in `ARCHITECTURE.md`.
- [x] **DRILL-02**: Each chart type that supports drill-down exposes a chart-config-time picker for "drill-down column" — the column whose value becomes the equality filter on click. Geometry-typed columns (WKT, WKB, Kinetica geometry) and large-text columns are filtered out of the picker; equality filters on these are nonsensical and would silently fail.
- [x] **DRILL-03**: The existing display-only filter bar in `DashboardsPage.tsx` becomes interactive — each active filter renders as a dismissable badge (× to remove a single filter) and a "Clear all" button removes every filter on the dashboard's tables. The bar reads from `useFilterStore`; dismissing a badge dispatches `removeFilter`.
- [x] **DRILL-04**: After a drill-down, the source chart shows a visual "selected" state on the clicked element (highlight/border) so the user can see which click triggered the active filter. A toast confirms the filter was added (`column = value`). The Toast component already exists from v1.0.

### Map Chart (rendering + config)

A new `map` chart type powered by OpenLayers + Kinetica's WMS endpoint, configurable across the four primary Kinetica WMS render modes.

- [x] **MAP-01**: A new `map` chart type renders Kinetica WMS tiles in any of four render modes selectable at chart-config time: raster (point markers), heatmap (density blending), classbreak (categorical/numeric color breaks), contour (contour lines). The exact `STYLES` parameter values for each mode are confirmed by a `?SERVICE=WMS&REQUEST=GetCapabilities` spike at the start of the map phase.
- [x] **MAP-02**: The map's chart-config UI lives in a `CustomConfigPanel` (the registry's existing escape hatch) and includes a spatial-column-mode picker with three options: lat/lon pair (X_ATTR / Y_ATTR), single WKT geometry column (GEO_ATTR), and Kinetica native WKB geometry (GEO_ATTR with type-spec validation). The picker reads existing column-type metadata from the column-discovery endpoint and auto-suggests the right mode based on detected types.
- [x] **MAP-03**: The map supports standard interactions — pan, zoom, hover-tooltip (driven by the identify probe), loading spinner during initial tile fetch, and error toast on tile-fetch failure. The OpenLayers View is locked to `EPSG:3857` (Web Mercator); the WMS request includes `SRS=EPSG:3857` explicitly. The map component cleans up on unmount via `map.setTarget(undefined); map.dispose()` to prevent memory leaks under React 18 Strict Mode.
- [x] **MAP-04**: The map's config panel includes three differentiator controls: a point-size slider (raster mode), a basemap style selector (OSM default + at least one alternate tile source), and a "zoom to data" button that fits the viewport to the dataset's bounding box (one bbox SQL query + `view.fit()`).

### Map Drill-Down v1.3

Click-to-filter on the map. Different from the existing-chart drill-down because map clicks are spatial; we resolve them to the closest underlying row via a server-side identify endpoint. Originally scoped for v1.2 Phase 12; deferred when Phase 12 was dropped from the v1.2 roadmap.

- **IDENT-V13-01**: A new `POST /api/identify` Express route accepts `{ table, lat, lon, spatialMode, columns: { x?, y?, geo? }, n? }`, builds a Kinetica SQL query using `ST_Distance` with `ORDER BY ... LIMIT 1` (or `LIMIT n` for ties), and delegates to the existing `kineticaSql` helper. The route reuses the existing typed-error middleware (`KineticaAuthError` → 401-REAUTH, `KineticaPermissionError` → 403, `KineticaUpstreamError` → 502) and per-call audit log (`auth_mode` field). The exact `ST_Distance` signature on the deployed Kinetica is confirmed by a one-task spike at the start of the identify phase.
- **IDENT-V13-02**: The map component listens for OpenLayers `singleclick` events. On click in raster, heatmap, or classbreak render modes, it calls `POST /api/identify` with the clicked map coordinate, then dispatches `addFilter` on the map's drill-down column with the closest row's value. Tie-breaking is deterministic (lowest primary-key value, or stable order from Kinetica). Contour mode is read-only — clicks in contour mode are ignored (the mode is locked out of drill-down because contour cells aren't 1:1 with rows).
- **IDENT-V13-03**: Clicking on empty map area (where the identify probe returns no rows within a reasonable proximity threshold, e.g., 100 pixels of map distance) is a no-op — no filter is added, no error is shown. Distinguishes "user clicked on data" from "user clicked on background."

## Out of Scope

Explicitly excluded for v1.2. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Hover-based filter activation | Hovering would flood Kinetica with identify-probe queries; UX-locked decision: hover = tooltip only, click = filter |
| SQL editor in the filter bar | Existing structured filter primitives are sufficient; SQL editor would expose the SQL surface Kinetica BI deliberately abstracts |
| Per-chart filter-exclusion toggle ("this chart ignores filters") | Contradicts the locked auto-share decision; adds UX confusion. If a chart shouldn't share filters, point it at a different table. |
| Contour mode drill-down | Contour cells aren't 1:1 with underlying rows; an equality filter on a contour click would have no semantic meaning. Contour stays read-only by design. |
| H3 / geohash spatial column types | Less common in Kinetica deployments; not blocking for the dominant use cases (point + WKT geometry). Revisit if needed. |
| Filter persistence across reload (any form) | Keeps v1.2 surgically scoped to interaction logic. URL-encoding and saved-with-dashboard both deferred to v1.3 (see v1.3 requirements). |
| Multi-IdP map / per-table-filter scope | Each map chart is bound to ONE Kinetica table at config time. Cross-table joins are a v1.3+ concern. |
