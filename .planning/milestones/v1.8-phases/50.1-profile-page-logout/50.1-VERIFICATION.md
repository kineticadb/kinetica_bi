#### 2. Logout session clearing and back-button protection

**Test:** Log in, click Log out (via the Topbar menu), confirm you land on the LoginPage. Then press the browser's Back button.
**Expected:** The app stays on the LoginPage (or equivalent unauthenticated view); the session cookie is cleared and the user is NOT silently re-authenticated.
**Why human:** Real HTTP session/cookie clearing and browser history behavior require a live browser + actual server.

**Test:** Log in as designer, click the Topbar trigger, click Profile. Verify the three sections. Repeat as user_admin.
**Expected:** (a) Username matches the logged-in user. (b) Auth mode shows "password sign-in" (or "SSO" in OIDC mode). (c) Role chips match the persona's roles (e.g., "designer" chip for designer persona). (d) Effective permissions are grouped correctly: Dashboards, Design, Users etc. headings appear for the permissions the persona holds.
**Why human:** Requires real store population from a live `/me` response to validate per-persona correctness.
