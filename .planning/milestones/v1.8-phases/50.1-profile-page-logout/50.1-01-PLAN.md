CRITICAL — how logout reset works (do NOT duplicate it):
App.tsx has a `useEffect` keyed on `status`. When `status === "unauthenticated"` it runs the canonical 6-store lifecycle reset (filterView + filter + infoSelection + lastInfoClickContext + spatialFilter + dynamicView) and the render guard at line 227 (`if (status !== "authenticated") return <LoginPage/>`) routes to LoginPage. So the Topbar "Log out" handler ONLY needs to call `useAuthStore.getState().logout()` (or the `logout` selector) — setting status to unauthenticated automatically fires the existing reset and LoginPage routing. NO new reset chain, NO manual store clears in the Topbar.

Current Page union (App.tsx line 21):
```typescript
type Page = "dashboards" | "datasets" | "settings" | "users" | "roles";
```

The grouping to extract (RolesPage.tsx lines 27-72): NOUN_TO_GROUP (record), GROUP_ORDER (tuple), and groupPermissions() which buckets ALL_PERMISSIONS by `perm.split(":")[0]` into ordered groups with an "Other" catch-all. ProfilePage needs a variant that groups an ARBITRARY permission list (the user's effective permissions), not the full catalog — so the shared module should export `groupPermissionList(perms: string[])` that takes the list to group.
