Add self-healing stale-permission handling at the apiFetch seam: on any 403 with `code: "PERMISSION_DENIED"`, show a toast naming the permission and trigger a debounced `/api/auth/me` re-fetch that updates `useAuthStore` so gated surfaces re-render immediately. This mirrors the existing `REAUTH_REQUIRED` 401 dispatch pattern exactly.

Purpose: GATE-V18-01 self-healing requirement (CONTEXT.md "Stale-UI 403 handling"). When an operator changes a user's roles mid-session, the user's first denied action re-syncs their permissions and the now-forbidden surfaces vanish — no polling.
Output: A `PERMISSION_DENIED` branch in apiFetch + an App.tsx listener that performs the re-sync.
</objective>

It uses the `UNAUTHORIZED_EVENT` window-event indirection precisely to AVOID a runtime import of useAuthStore (auth.ts imports fetchMe from client.ts → client.ts must NOT runtime-import auth.ts or a cycle forms). Therefore:
- The /me re-fetch + setPermissions MUST live in App.tsx (event listener), NOT in client.ts. App.tsx already runtime-imports useAuthStore.

Existing REAUTH_REQUIRED 401 dispatch in apiFetch (packages/web/src/api/client.ts lines 39-60):
```typescript
const apiFetch: typeof fetch = async (input, init) => {
  const response = await fetch(input, { ...init, credentials: "include" });
  if (response.status === 401 && typeof window !== "undefined") {
    let shouldDispatch = false;
    try {
      const peek = await response.clone().json();
      if (peek?.code === "REAUTH_REQUIRED") shouldDispatch = true;
    } catch {}
    if (shouldDispatch) window.dispatchEvent(new CustomEvent(UNAUTHORIZED_EVENT));
  }
  return response;
};
```
