<decisions>
## Implementation Decisions

### Bug 1: UsersPage table misalignment (ROOT-CAUSED)
- Cause: `packages/web/src/styles/global.css` sets `display: flex` directly on `<td>` elements (`.users-td-username` ~line 3902, `.users-td-roles` ~line 3915). A flexed `<td>` leaves table-cell layout, so role chips stack under the username and Last Seen / Actions cells slide left under the wrong headers (operator screenshot confirms).
- Fix: `<td>`s stay table-cells. Move the flex to an inner wrapper: in `UsersPage.tsx` wrap the username cell content and roles cell content each in `<div className="users-cell-flex">` (or equivalent); CSS flex rules move to the wrapper class. Expected result: every datum sits under its own column header (Username | Roles | Last Seen | Actions), chips inline in the Roles column.
- Add/extend an RTL spec asserting td count per row matches header count and that chips render within the roles cell (structure-level assertion; pixel layout is the operator's re-check).

### Bug 2: negative "x ago" (ROOT-CAUSED)
- Cause: server `known_users` timestamps come from SQLite `datetime('now')` → UTC formatted as `"YYYY-MM-DD HH:MM:SS"` with NO timezone marker. `new Date(s)` parses marker-less strings as LOCAL time, so on a UTC-4 machine timestamps appear ~4h in the future → `Date.now() - then` goes negative (screenshot: "-9131s ago").
- Fix in `packages/web/src/lib/relativeTime.ts` (single consumer):
  1. Normalize: if the string contains no `T` and no `Z`/offset, parse as UTC — `new Date(s.replace(" ", "T") + "Z")`.
  2. Defensive clamp: any non-positive diff renders `"just now"` (covers clock skew).
- Extend `relativeTime.spec.ts`: a space-separated UTC timestamp from the recent past renders positive ("Xm ago"); a future timestamp renders "just now".
- Do NOT change the server storage format (other rows already exist; parsing fix is backward-compatible with both formats).
