Edit `humanizeRelativeTime` in relativeTime.ts. LOCKED approach:

1. Normalize marker-less strings to UTC before parsing. After the null guard, compute the parse input:
   ```ts
   // Server (SQLite datetime('now')) emits "YYYY-MM-DD HH:MM:SS" with NO timezone
   // marker; new Date() would parse it as LOCAL time. Treat marker-less strings as UTC.
   const hasMarker = isoString.includes("T") || /[zZ]|[+-]\d\d:?\d\d$/.test(isoString);
   const normalized = hasMarker ? isoString : isoString.replace(" ", "T") + "Z";
   const diffMs = Date.now() - new Date(normalized).getTime();
   ```
   (A plain marker-less string like "2026-06-06 14:20:38" → "2026-06-06T14:20:38Z".)

2. Defensive clamp: any non-positive diff renders "just now" (covers clock skew / future timestamps). Immediately after computing diffMs:
   ```ts
   if (diffMs <= 0) return "just now";
   ```
   Keep the existing s/m/h/d bucket cascade below unchanged.

Do NOT change the function signature or the server storage format.

**relativeTime.spec.ts:** Extend (do not replace) with two cases:
- Marker-less UTC recent past renders positive minutes. Build the string from a UTC date 5 minutes ago in "YYYY-MM-DD HH:MM:SS" form, e.g.:
  ```ts
  const d = new Date(Date.now() - 5 * 60 * 1000);
  const utc = d.toISOString().replace("T", " ").replace(/\.\d+Z$/, "");
  expect(humanizeRelativeTime(utc)).toMatch(/\d+m ago/);
  ```
- Future timestamp renders "just now":
  ```ts

  ```
