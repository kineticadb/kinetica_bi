<objective>
Fix three operator-reported light-mode/theming bugs on the new RBAC surfaces, plus patch the Phase 51 UAT checklist to catch this bug class going forward. ALL fixes are CSS + the one checklist edit — NO server changes, NO behavior changes, NO React markup changes.

Three bugs (all root-caused in CONTEXT.md):
1. RolesPage.css references non-existent `--color-*` variables → every value falls back to a hardcoded dark hex → the page is permanently dark regardless of theme. Fix: rewrite onto the REAL global.css tokens.
2. `.users-table-wrap { overflow-x: auto }` establishes a clip context; the absolutely-positioned `.users-popover` renders outside its bounds and gets clipped. Fix: `overflow: visible` (option a — the 5-column table does not need horizontal scroll at normal widths).
3. `.role-chip` hardcodes dark-theme greens (`color:#86efac` on translucent green) → washed out / unreadable on light backgrounds. Fix: add a `:root[data-theme="light"] .role-chip` override. Plus sweep the other v1.8 RBAC CSS (Topbar user-menu, ProfilePage) for the SAME class of bug — they reference non-existent `--surface-hover` / `--text-muted` tokens that fall back to dark-only translucent whites.

Purpose: the Roles/Users/Profile surfaces must be usable in light mode before the Phase 51 live UAT.
Output: 4 CSS edits + 1 checklist patch.
</objective>
