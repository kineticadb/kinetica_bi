<objective>
Create the canonical, code-defined RBAC permission catalog and the default built-in role→permission mappings as pure TypeScript constants in a single source-of-truth module. This is the foundation every other Phase 46 plan (and Phases 47/48) imports — the seed reads `DEFAULT_ROLE_MAPPINGS`, `getEffectivePermissions` reads `ALL_PERMISSIONS`, the middleware (Phase 47) and frontend (Phase 48) read `PERMISSIONS`.

Purpose: A single canonical permission catalog prevents string drift between server enforcement and frontend gating (PITFALLS Pitfall 3). The catalog is code-defined (new permissions require a release); only the role→permission mappings live in the DB.
Output: `packages/server/src/lib/permissions.ts` + co-located spec locking the exact 15 strings and the locked default mappings.
</objective>

Target export shape (the executor defines these exact names):

```typescript
// A const object whose VALUES are the canonical permission strings.
export const PERMISSIONS = {
  DASHBOARDS_VIEW: "dashboards:view",
  // ...15 entries total
} as const;

export type Permission = (typeof PERMISSIONS)[keyof typeof PERMISSIONS];

// Flat array of all 15 permission string values (for the admin short-circuit + catalog seed).
export const ALL_PERMISSIONS: readonly Permission[];

// The four built-in role names, stable order.
export const BUILTIN_ROLES: readonly ["admin", "user_admin", "designer", "analyst"];
export type BuiltinRole = (typeof BUILTIN_ROLES)[number];

// Default permission set per built-in role (the seed source of truth).
export const DEFAULT_ROLE_MAPPINGS: Record<BuiltinRole, readonly Permission[]>;
```
