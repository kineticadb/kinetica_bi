    - clearMaterializing preserves reference identity of entries for all other tableIds (C-02 lock)

    2. Add the implementation to the `create` call body after `markMaterializing`:
       ```typescript
       clearMaterializing: (tableId) =>
         set((state) => {
           const prev = state.views[tableId];
           if (!prev) return state; // no-op — entry absent, nothing to clear
           if (!prev.materializing) return state; // no-op — already false, avoid allocating
           return { views: { ...state.views, [tableId]: { ...prev, materializing: false } } };
         }),
       ```
       The double no-op guard (absent entry, already-false flag) matches the `bumpMaterializeVersion` guard pattern in the same file.

      it("preserves viewName, expiresAt, materializeVersion, dashboardId on the entry")

    }
