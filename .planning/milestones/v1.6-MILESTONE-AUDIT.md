# v1.6 Dynamic Views — Milestone Audit Report

**Audited:** 2026-05-18
**Status:** ⚠ **GAPS FOUND** (1/15 requirements unsatisfied — pre-existing tech-debt, not v1.6 regression)
**Scope:** Phases 32–36 (5 phases, 18 plans, 15 requirements)

## Executive Summary

The v1.6 Dynamic Views milestone delivered all 14 feature requirements (DV-V16-01..14) with **zero broken cross-phase wiring** and **zero orphaned exports**. The integration checker verified 28/28 cross-phase contracts. Phase 32's 7 dynamic-view supertest spec files pass **86/86 in their assigned auth mode**.

The audit is gated `gaps_found` solely because of **VERIFY-V16-01** — the verification requirement marks the milestone's automated test gate. The gate failed because the server vitest suite is RED in both auth modes due to **pre-existing cross-mode test isolation tech-debt** (OIDC-specific tests failing when run under `AUTH_MODE=password` and password-specific tests failing when run under `AUTH_MODE=oidc`, plus 1 `routes.info-query.spec.ts` timeout). **This failure pre-dates v1.6** and is not a Phase 32 regression. Each mode's own specs pass cleanly; the failures are mode-mismatched tests leaking into the wrong run.

Live operator UAT for the three end-to-end create→preview→materialize→drop scenarios (e2e.1–3) was explicitly DEFERRED per the v1.5 Phase 31 source-only attestation precedent. The operator has been exercising v1.6 interactively throughout development and each surfaced gap was closed inline (see In-Cycle Gap Closures below).

**Operator decision required:**
- **Accept tech-debt** → `/gsd:complete-milestone v1.6` (closes v1.6 with the test-isolation work item carried to v1.7)
- **Close the gate first** → `/gsd:plan-milestone-gaps` (creates a Phase 36.x to fix the server vitest cross-mode isolation before closing v1.6)
