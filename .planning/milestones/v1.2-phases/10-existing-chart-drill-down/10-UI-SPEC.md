## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f172a` (`--bg`) | Page background |
| Secondary (30%) | `#111827` (`--panel`) + `rgba(255,255,255,0.04)` (`--card`) | Filter bar item background, widget cards |
| Accent (10%) | `#22c55e` (`--accent`) | Chip background tint, chip border, row-tint background, config-group drill-down label |
| Destructive | `#ef4444` | Not used in Phase 10 (no destructive actions) |

**Source:** `global.css :root` block — all tokens present.

**Primary visual anchor:** The `.filter-bar-chip` row draws the eye first via accent color contrast — green border and tinted background against the dark `var(--card)` panel background — making active store filters immediately distinguishable from the muted static SQL clause.

**Accent reserved for (Phase 10 only):**
1. `filter-bar-chip` background: `rgba(34, 197, 94, 0.12)` — low-opacity tint to distinguish store chips from static clause
2. `filter-bar-chip` border: `rgba(34, 197, 94, 0.35)` — visible border to separate chip from bar background
3. `filter-bar-chip` text color: `var(--accent)` — matches existing `.filter-bar-clause` color convention
4. `widget-table-row-active` background: `rgba(34, 197, 94, 0.08)` — subtle row tint for filtered rows
5. `widget-table-row-active` hover: `rgba(34, 197, 94, 0.14)` — slight lift on hover for rows with tint active
6. Drill-down picker config-group label border-bottom: inherits `config-group-label` accent color (already `var(--accent)`)

**Muted color for static clause:**
- `view.filter_clause` static label: `color: var(--muted)` (`#94a3b8`), NOT accent — visually distinct from dismissable store chips. No chip shape — plain `<span>` with monospace font, no border, no background. Prefix text `WHERE ` rendered inline. Source: existing `.filter-bar-clause` class targets this, but it currently uses `var(--accent)`. Phase 10 changes `.filter-bar-clause` to `color: var(--muted)` to differentiate it from store chips which use accent. The distinction signal: static clause is muted + no × button; store chips are accent-tinted + have × button.

**Second accent color:**
- `--accent-2: #38bdf8` — NOT used in Phase 10 filter bar elements. Reserved for login/OIDC UI.

## Interaction Contracts

### 1. Dim-Peers Click Animation (DRILL-04)

**Source:** CONTEXT.md locked decisions + RESEARCH.md Pattern 4.

| Property | Value |
|----------|-------|
| Non-matching peer opacity | 0.3 (`fillOpacity` via Recharts `<Cell>`) |
| Active element opacity | 1.0 (full saturation) |
| Animation duration | 300ms |
| Timing function | `ease-out` |
| CSS property animated | `fillOpacity` on Recharts `<Cell>` (bar, line, pie, scatter); not `opacity` — avoids affecting labels/axes |
| ScatterChart symbol | `fillOpacity` on `<Scatter>` shape; same 0.3/1.0 contract |
| Pie `<Cell>` strategy | `fillOpacity` on each `<Cell>` keyed to slice index; active slice at 1.0, others at 0.3 |
| Cleanup trigger | On data arrival (new filtered data replaces current data; `clickedElement` state clears to `null`) |
| Sequencing | `setClickedElement(value)` FIRST (triggers dim render), then `setTimeout(300, () => addFilter(...))` — never dispatch before dim render is visible |

**Exact transition declaration (per Cell):**
```tsx
// No CSS transition needed — fillOpacity is a React-controlled prop,
// not a CSS property on SVG. The 300ms is the time clickedElement stays
// set before addFilter clears data. The visual "fade" is achieved by
// the instant state change + the 300ms delay before dispatch.
// Result: user sees dimmed state for ~300ms, then loading spinner.
```

**Note on "ease-out" language:** The ~300ms is a JavaScript timeout, not a CSS transition. The ease-out feel comes from the React render cycle — the dim appears immediately (sharp cut) and the loading state replaces it after 300ms. There is no CSS keyframe needed.

### 2. Cursor Affordance (DRILL-04)

| Condition | Cursor |
|-----------|--------|
| `supportsDrillDown && cfg.drillDownColumn` is truthy | `cursor: pointer` |
| `!cfg.drillDownColumn` OR `!supportsDrillDown` | `cursor: default` (or unset — inherits) |
| Chart header, toolbar, axes | unchanged — no cursor override |
| Table/records `<tr>` with drill-down enabled | `cursor: pointer` via inline style on `<tr>` |
| Table/records `<tr>` without drill-down | no style applied — inherits `cursor: default` |

Implementation: inline `style={{ cursor: cfg.drillDownColumn ? "pointer" : undefined }}` on `<tr>`. For Recharts charts: `style={{ cursor: cfg.drillDownColumn ? "pointer" : "default" }}` on the `<BarChart>` / `<LineChart>` / etc. wrapper.

### 3. Filter Bar Layout (DRILL-03)

**Source:** CONTEXT.md "unified per-table row" decision + RESEARCH.md Pattern 6.

Entire bar is hidden when NO table has either (a) active store filters OR (b) non-empty `view.filter_clause`. The outer `views.length > 0` condition is replaced with this compound check.

Per-table row layout (left to right, single row, no wrap):
```
[ schema.table: ]  [ WHERE <static-clause> ]  [ chip1 × ] [ chip2 × ] [ chip3 × ] ...  [ Clear all ]
```

- Table label: `<span class="filter-bar-table">schema.table:</span>` — weight 600, `var(--text)`
- Static clause: `<span class="filter-bar-clause">WHERE {v.filter_clause}</span>` — 12px monospace, `var(--muted)`, no dismiss button, no chip shape. Hidden (not rendered) when `v.filter_clause` is empty/null.
- Store chips container: `<div class="filter-bar-chips">` — `flex: 1; overflow-x: auto` — takes remaining row width, scrolls horizontally when chips overflow. Hidden (not rendered) when `storeFilters.length === 0`.
- Each chip: `<span class="filter-bar-chip">{text}<button class="filter-bar-chip-dismiss" aria-label="Remove filter {column}">×</button></span>`
- Clear-all button: `<button class="filter-bar-clear">Clear all</button>` — rendered only when `storeFilters.length > 0`

**Clear-all label copy:** "Clear all" — short, action-oriented, matches the per-table scope. "Clear filters" rejected (redundant word). "Reset" rejected (implies restoring a default, not clearing a user action).

**Chip overflow behavior:** `overflow-x: auto` on `.filter-bar-chips`. Scrollbar rendered by browser default (thin scrollbar via `scrollbar-width: thin`). No gradient fade indication — scroll is implied by the chip overflow pattern. The `filter-bar-item` height stays fixed; no wrap to second line.

**Empty per-table row:** A table with no store filters AND no static clause produces no visible row — the entire `filter-bar-item` for that table is not rendered. The outer `<div class="filter-bar">` is hidden when all tables are in this state.

### 4. Drill-Down Column Picker (DRILL-02)

**Source:** CONTEXT.md "Drill-down column picker" decision + RESEARCH.md Pattern 2.

| Property | Value |
|----------|-------|
| Control type | `<select>` — native HTML select, matches existing `<ds-select>` pattern in ChartConfigPanel |
| CSS class | `ds-select` — reuses existing input/select styling |
| Position | Below the `groupByColumn` field in ChartConfigPanel, inside a new `config-group` with label "Drill-Down" |
| Visibility condition | Rendered only when `chartDef.supportsDrillDown === true` |
| Empty/null option | `<option value="">— none —</option>` as first option; selecting it sets `drillDownColumn: ""` (no-op click) |
| Column list | All columns from `selectedTable.columns` where `isColumnDrillDownSafe(type)` returns true |
| Default value | `groupByColumn` value for bar/line/pie; `xAxisKey` for scatter; `""` for records/table |
| Config-group label | "Drill-Down" — uses `.config-group-label` (12px / 600 / uppercase / var(--accent)) |
| Hint text | `<div class="config-hint">Column whose value becomes the filter on click</div>` — 12px, `var(--muted)` |

The picker also sets `drillDownColumnType` in `widget.config` at save time (ChartConfigPanel has `selectedTable.columns` and calls `inferDataTypeFromColumn` at column-select time). Renderers read `cfg.drillDownColumnType` directly — no runtime column-type lookup.

### 5. Row Tint — Records and Table Charts (DRILL-04)

**Source:** CONTEXT.md "persistent row-tint" decision + RESEARCH.md Pattern 5.

| Property | Value |
|----------|-------|
| CSS token | New token `--filter-active-row-bg` is NOT introduced. Use `rgba(34, 197, 94, 0.08)` directly in `.widget-table-row-active` class. Rationale: a single CSS variable for one use-case adds overhead without benefit; the global.css color system uses direct rgba values for opacity tints throughout. |
| CSS class | `widget-table-row-active` (new — add to global.css) |
| Applied when | `cfg.drillDownColumn` is set AND `row[cfg.drillDownColumn]` matches `activeFilter.value` (string comparison via `String(row[col]) === String(filter.value)`) |
| Zebra stripe compatibility | `.widget-table-row-active` uses `!important` to override `.widget-table-stripe`'s `rgba(255,255,255,0.02)` background. No z-index or specificity issue — both are class selectors on `<tr>`. |
| Hover | `.widget-table-row-active:hover` lifts to `rgba(34, 197, 94, 0.14)` |
| Non-matching rows | No change to existing zebra-stripe behavior |
| Tint survives refetch | Yes — `tableFilters` selector output is compared against each row on every render; rows matching the active filter get the class on each render cycle after refetch |

### 6. Toast (DRILL-04)

**Source:** RESEARCH.md Pattern 4 + toast.ts source read.

| Property | Value |
|----------|-------|
| Store | `useToastStore.getState().showToast(message, kind)` |
| Kind | `"info"` — neutral confirmation, not "success" (no "success" kind exists in `ToastKind`). Valid values: `"permission" | "info" | "error"` |
| Position | Fixed bottom-right, 24px from edges (existing `.toast-container` positioning) |
| Duration | 5000ms auto-dismiss (existing store behavior) |
| Dedup window | 5s on `kind::message` key (existing store behavior — known edge case: clear + re-click within 5s suppresses second toast; accepted per RESEARCH.md Pitfall 4) |
| Fires when | First add only: new column with no prior filter on that column for this table |
| Suppressed when | Same column + same value (exact dedupe, Phase 9 no-op path), OR same column + different value (replace path — chip change is the feedback) |
| Message format | `buildChipText(column, value, dataType)` output — identical to chip text |
| Message examples | `region = 'EAST'`, `status IS NULL`, `score = 42`, `active = TRUE` |
| Cap-reached toast | Fired by `addFilter` itself (Phase 9); Phase 10 does not re-fire. Message: `"Filter limit reached (10 per table). Clear some first."` Kind: `"info"` |

## A11y Minimums

**Source:** CONTEXT.md deferred section + standard `<button>` semantics.

| Element | Contract |
|---------|---------|
| Chip × dismiss | `<button>` element (not `<span>`) with `aria-label="Remove filter {column}"` |
| Clear-all | `<button>` element; no additional aria needed — visible label is descriptive |
| Drill-down picker | `<select>` with a visible `<label>` element ("Drill-Down column") and `id`/`for` linkage |
| Clickable chart elements | No additional aria role — chart click affordance indicated by pointer cursor only. Keyboard drill-down deferred to future a11y phase. |
| Clickable table rows | `cursor: pointer` but no `role="button"` or `tabIndex` — keyboard drill-down deferred per CONTEXT.md deferred list |

Full keyboard accessibility on chart clicks is explicitly deferred per CONTEXT.md. The minimum contract for Phase 10 is: dismiss buttons and Clear-all are proper `<button>` elements so they receive focus and respond to Enter/Space naturally.
