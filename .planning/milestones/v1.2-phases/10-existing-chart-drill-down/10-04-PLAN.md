<objective>
Wire the click-to-filter behavior into all five aggregated chart renderers (Bar, Line, Pie, Scatter, Table) plus the standalone RecordsTableRenderer in `WidgetRenderer.tsx`. On click, each renderer:

1. Reads `cfg.drillDownColumn` and `cfg.drillDownColumnType` from the persisted widget config (Plan 10-03 wrote these)
2. No-ops if either is unset (graceful fallback for legacy widgets)
3. Sets a local `clickedElement` state (drives the dim-peers transient)
4. Pre-checks the store for dedupe/replace status to decide whether the toast fires
5. Schedules a 300ms `setTimeout` that fires `useFilterStore.getState().addFilter(...)` (Phase 9 PITFALL C-03 — dim-peers must render BEFORE the data-clear triggered by addFilter)
6. The toast (when applicable) fires using `buildChipText` for human-readable text (DRILL-04 SC-5)
7. The cursor on chart elements is `pointer` only when `supportsDrillDown && drillDownColumn` are both truthy
8. RecordsTableRenderer additionally subscribes to the filter store for the persistent row-tint (DRILL-04 — `widget-table-row-active` CSS class shipped by Plan 10-02)
