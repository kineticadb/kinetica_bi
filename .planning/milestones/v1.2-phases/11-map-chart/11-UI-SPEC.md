# Phase 11 — UI Design Contract

> Visual and interaction contract for the map chart widget, its config panel, and its loading/error/empty states. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase introduces a new chart type (`map`) into a codebase whose visual language is already locked by Phases 1-10. **Phase 11 MUST align with the existing dark-theme tokens and component patterns in `src/styles/global.css`**; it does NOT introduce a new design system. Every value below is sourced from the existing stylesheet (line numbers cited where load-bearing).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled CSS in `src/styles/global.css`; no Tailwind, no shadcn, no Radix) |
| Preset | not applicable |
| Component library | none (raw HTML elements + CSS classes; chart drawing via `recharts`; `react-grid-layout` for dashboard grid) |
| Icon library | none — single-character glyphs in monospace (e.g. `M` for map, `×` for dismiss, custom unicode arrows). Phase 11 uses glyph + label pattern for the zoom-to-data button (`⤢ Zoom to data`) — no SVG icon set is added |
| Font | `"Manrope", "Segoe UI", system-ui, -apple-system, sans-serif` (sans, set on `:root`); `"JetBrains Mono", "Fira Code", monospace` (mono, used for SQL clauses, filter chips, and config color hex values) |

**shadcn gate decision:** This is a React 18 + Vite + TypeScript project but **shadcn was NOT initialized**. Rationale: the project ships with a hand-rolled CSS design system (~1460 lines in `src/styles/global.css`) that is the source of truth for Phases 1-10. Forcing shadcn now would create two parallel systems and break visual continuity with already-shipped widgets. UI-SPEC contract is therefore expressed in the existing CSS-token vocabulary. `Tool: none` per the shadcn-gate fallback path.

## Spacing Scale

### Phase 11 Spacing Scale (strict multiples of 4)

These are the ONLY spacing values that Phase 11 components introduce in their NEW CSS declarations. Every value below is a multiple of 4. Net-new Phase 11 styles MUST pick from this scale.

| Token | Value | Usage in Phase 11 |
|-------|-------|-------------------|
| xs | 4px | Icon-glyph gap inside chips; range-slider value-label margin |
| sm | 8px | Config-group internal gap; toolbar button gap; classbreak row gap; toolbar inset from canvas edge; zoom-to-data button inner padding; `.widget-map-error` internal flex gap |
| md | 12px | Card padding (left/right of widget body — net-new declarations); modal-section gap; spatial-mode picker option gap; zoom-to-data button horizontal inner padding |
| lg | 16px | Config-panel-body inter-group gap declared by Phase 11 (between Spatial / Render Mode / Params sections); modal padding-x; `.widget-map-error` padding (16px all sides) |
| xl | 20px | Modal-section-title-spaced top margin (existing) |
| 2xl | 24px | Toast container offset from screen edge (existing `.toast-container`) |

**Phase 11 exceptions (still multiples of 4):**
- **Zoom-to-data button**: 36×36px tap target (multiple of 4), positioned at top-right of map canvas with `8px` inset from each edge. Inner padding 8px (vertical) × 12px (horizontal).
- **Tile fade-in**: not a spacing token, but a `transition: opacity 200ms ease-out` is the timing token, declared once and reused for `cb_radio` mode-switching transitions.
- **Map widget min-height**: 240px (multiple of 4) enforced on `.widget-card` containing `case "map"` so OL has a sensible target on small dashboard tiles. (Other chart types do NOT enforce a min-height; map is special because OL renders to a real DOM element rather than a flex-sized SVG.)

### Toast Notifications

Routed through the existing `useToastStore.getState().showToast(message, kind)` API. All Phase 11 toasts use existing `.toast` styling.

| Trigger | Toast copy | Kind |
|---------|------------|------|
| Tile-fetch error (debounced 2s burst — fires once per cluster of failures) | `Map tiles failed to load.` | `error` (uses existing `.toast-error` border) |
| Cardinality probe shows > 100 (fires once per column-pick) | `That's a lot of breakpoints — consider a heatmap or numerical range instead.` | `permission` (informational; reuses existing `.toast-permission` amber border) |
| Cardinality probe shows > 256 (fires alongside the inline hard-cap hint) | `Too many distinct values — Kinetica classbreak supports up to 256.` | `error` |
| Capabilities probe failed at app boot (not tile-time) | (silent in production; logged to console only) | none |

### Destructive Actions

Phase 11 has **no irreversible destructive actions** at the user-facing level.

The classbreak `× Remove break` per-row button is destructive in the sense that it discards configured break values, but:
- The change is staged in `draft` state inside the config modal (existing `setDraft` pattern in `ChartConfigPanel.tsx`)
- The user must click `Apply` to commit, or `Cancel` to discard
- Therefore **no inline confirmation dialog is required** — same convention as removing a recharts series in existing config panels

If the user clicks `Cancel` on the config modal after deleting break rows, the original `widget.config.classbreaks` array is preserved unchanged. This matches the existing `ChartConfigPanel` draft/apply pattern; Phase 11 introduces no exceptions.

## Interaction Contract

The minimum behavior the executor must implement for the UI to be considered correct.

### Spatial-mode picker (MAP-02)

1. On modal open, if `widget.config.spatialMode` is unset, run the auto-detect logic (see CONTEXT.md / RESEARCH.md). Apply the suggested mode AND show the `Auto-detected from column types` hint under the picker. Hint dismisses on first manual override.
2. Switching modes does NOT clear the other modes' column picks (per-mode preservation: `latColumn`/`lonColumn`/`wktColumn`/`wkbColumn` are independent slots).
3. Column dropdowns filter via `getValidSpatialColumns(columns, mode)` — the user only ever sees columns valid for the active mode.
4. Modes the deployed Kinetica doesn't support are hidden from the radio group entirely (gated by `/api/wms/capabilities` probe at app boot; if probe fails, all four modes are shown — graceful degradation).

### Render-mode picker (MAP-01)

1. Render-mode change preserves the OL `Map` instance and the user's pan/zoom state.
2. Switching render mode shows ONLY the param group for the active mode (raster/heatmap/classbreak/contour). Switching is instant — no transition.
3. The raster default fallback applies when `widget.config.renderMode` is unset; auto-set to `raster` on first config-modal open.

### Classbreak builder (M-06)

1. On `cbColumn` pick, fire the cardinality probe (`SELECT COUNT(DISTINCT cbColumn) FROM table` via `runSql` with AbortSignal — Phase 9 contract).
2. While probe is in flight, show `Counting distinct values…` hint. Hide `+ Add break` button (it would be premature to add rows before knowing the cap).
3. On probe resolve:
   - distinct ≤ 100 → no warning; `+ Add break` enabled
   - 100 < distinct ≤ 256 → warning hint (accent color) + toast (informational, fires once); `+ Add break` enabled
   - distinct > 256 → hard-cap hint (red) + toast (error); `+ Add break` disabled
4. Min 2 break rows enforced before Apply (Apply button disabled with tooltip `Add at least 2 break rows`).
5. Per-row remove: clicking `×` is destructive on staged state but discardable via Cancel; no inline confirm dialog (per Destructive Actions contract above).

### Zoom-to-data button (MAP-04)

1. Visible only when `spatialMode + columns` are configured. Hidden in empty-config state.
2. Auto-fires once on the renderer's first effectful mount when configuration is complete (the "world view first impression" lock).
3. Subsequent renders preserve user's pan/zoom — the button does not re-fire on filter change, render-mode change, or basemap change. Only manual click re-fires.
4. Click handler: invoke bbox SQL helper → `view.fit(bbox, { padding: [40, 40, 40, 40] })`.
5. Visual: hover shows `border-color: var(--accent); color: var(--accent)` (matches existing `.ghost:hover`).

### Tile fade-in (MAP-03 loading affordance)

1. Each WMS tile transitions from `opacity: 0` to `opacity: 1` over 200ms ease-out.
2. The fade applies on initial load AND on `updateParams`-driven refetches (filter changes). Trade-off documented: less explicit "we're working" than a global spinner, but matches the locked decision per CONTEXT.md.
3. No global spinner overlay. (Revisit post-launch if user testing shows confusion during slow refetches.)

### Tile-error overlay (MAP-03)

1. Triggered by OL `tileloaderror` (any tile fails).
2. Overlay is centered on the map canvas, ~320px max width. Single overlay; subsequent errors during the same burst do NOT stack.
3. Toast also fires (debounced 2s burst) — once per cluster of failures, not per tile.
4. `Retry` button calls `tileWmsSource.refresh()`. Overlay does NOT auto-dismiss on retry click; it dismisses on the next successful `tileloadend` event.
5. **HTTP 401 path is special:** the custom `tileLoadFunction` detects status 401, dispatches `UNAUTHORIZED_EVENT`, does NOT show the overlay, does NOT show the toast. The existing `App.tsx` re-auth listener handles UI from there. (Pattern 4 in RESEARCH.md.)

### Filter subscription (FILT-04 / M-02)

1. Map subscribes to `useFilterStore(s => s.filters[tableId] ?? [])` and `s.filterVersion` (the primitive dep — S-02 lock from Phase 9).
2. On `filterVersion` change: build new `whereClause` via `buildWhereClause`, call `tileWmsSource.updateParams({ QUERY: whereClause || undefined, _v: filterVersion })`. NEVER rebuild the OL Map.
3. The cache-buster `_v: filterVersion` forces OL to treat new tiles as new cache keys. Combined with `Cache-Control: no-store` on `/api/wms` (M-08), this guarantees no stale tile is served.
4. The map renders no per-chart "filter active" badge or border — the existing top-of-page filter bar IS the cross-chart filter feedback (Phase 10 lock).

### Basemap selector (MAP-04)

1. Three options: OSM (default), CartoDB Voyager, CartoDB Dark Matter.
2. `onChange` calls `basemapLayer.setSource(newSource)` — does NOT rebuild the Map.
3. Active option is bordered with `--accent`; non-active options use `--border`.
4. Attribution text appears via OL's Attribution control — auto-included with each basemap source.
