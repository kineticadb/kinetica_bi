    ### Criterion 1: Layer CRUD via the modal works end-to-end

    1. Open a dashboard, click "Layers" → modal opens.
    2. Modal title is "Layers"; "+ Add layer" button visible at the bottom of the left rail.
    3. If dashboard had 0 layers and at least 1 associated table → a blank layer auto-creates and the right pane shows the form ready to fill (TABLE dropdown + KineticaWmsLayerForm).
    4. Pick a table from the right-pane TABLE dropdown; spatial-mode auto-suggest sets `spatialMode` based on the table's columns; relevant column dropdowns populate.
    5. Render mode dropdown switches between Raster / Heatmap / Classbreak / Contour; each surfaces its mode-specific param controls.
    6. Click `+ Add layer` → second blank layer appears with `position = max + 1`.
    7. Drag layer 2 above layer 1 → row order swaps; Network tab shows `PATCH /api/dashboards/:id/layers/reorder` with `orderedIds`.
    8. Click duplicate icon on layer 1 → new layer cloned at end of list; row count increases by 1.
    9. Click eye icon → aria-label flips, eye icon dims to 0.3 opacity; map stops fetching that layer's tiles.
    10. Drag the per-row OPACITY slider on a layer to ~50 → verify a PATCH fires with `config.POINTOPACITY: 50`; map widget reflects the new opacity within ~300ms.
    11. Click trash → inline `[Delete layer] [Keep layer]` buttons; click `Keep layer` → cancels (no DELETE fires); click trash again → click `Delete layer` → DELETE fires, row vanishes.

    Expected: PASS. RED if any of the above fail.

    ### Criterion 2: Multi-layer rendering on a map widget

    1. Add a map widget to the dashboard (Visualizations → Map). The widget renders the basemap plus all dashboard layers (lazy/inclusive default).
    2. Configure the widget — open its config gear icon. Title + Basemap selector + LAYERS section with a checkbox per dashboard layer should appear. NO spatial-mode / render-mode controls (those moved to LayersModal).
    3. Uncheck a layer → that layer's WMS tiles disappear from the widget; remaining layers stay visible.
    4. Re-check it → tiles reappear without remounting the OL Map (zoom/pan retained).
    5. Add a second map widget to the same dashboard. Both widgets show the same layers in the same `position` order. Both subscribe independently to the layers store.

    Expected: PASS.

    ### Criterion 3: Per-layer filter subscription preserves M-02 lock

    1. With a map widget showing layer A (table T) and layer B (table U), apply a drill-down filter on a chart of table T (e.g., a bar chart drill-down).
    2. Network tab: a NEW `/api/wms?...&_v=<filterVersion>` request fires for layer A's tiles WITH the new `QUERY` param reflecting the filter.
    3. Layer B's tiles do NOT need a content-changing refetch (the QUERY value for table U did not change). The OL Map instance is NOT disposed (zoom/pan retained on both widgets).
    4. Clear the filter → layer A's tiles refetch without the QUERY clause; layer B unaffected.

    Expected: PASS. RED if the OL Map gets rebuilt (zoom/pan resets), if all layers refetch on every filter change, or if NEITHER layer responds to the filter (which would indicate the renderer is reading from `cfg.tableId` instead of `layer.table_id` — see Plan 05 Test G).

Alternatively, dump a current Phase 11 widget's config in `data/kinetica.db` and manually delete the `includedLayerIds` field.
