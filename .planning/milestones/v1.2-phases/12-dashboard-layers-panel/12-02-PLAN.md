Extract the spatial-mode/render-mode/render-param/classbreak sections of `MapConfigPanel.tsx` into a NEW reusable component `KineticaWmsLayerForm.tsx`. Delete the dead-code `bboxHelper.ts` + spec + the zoom-to-data button + auto-fit-on-mount logic from `MapChartRenderer.tsx`.

Purpose: The new layers panel (Plan 04) and the shrunk MapConfigPanel (Plan 05) both need the layer config UI. Extracting it now in its own plan keeps the surgery contained. Deleting `bboxHelper.ts` here lifts the dead-code lock from CONTEXT.md ("zoom-to-data... Phase 11's bboxHelper.ts becomes dead code; planner deletes it as part of the hard cutover").

Output: A standalone `KineticaWmsLayerForm` component with the prop signature `{config, onChange, columns, isValid?}` (matches Phase 11 ConfigPanelProps); `MapConfigPanel` continues to work as-is (Plan 05 will shrink it); `MapChartRenderer` no longer imports `bboxHelper` and no longer renders the zoom-to-data button.

**Table-binding split (CONTEXT.md compliance):** The layer's table binding (`layer.table_id`) is a top-level field on `DashboardLayerDto`, NOT a JSON-blob field inside `layer.config`. KineticaWmsLayerForm intentionally has NO table picker — the LayersModal (Plan 04) renders the table dropdown ABOVE the form in the right pane and patches the top-level `table_id` via `onPatch(layerId, {table_id: newId})`. This keeps the form purely controlled (its only inputs are `config`, `columns`, `onChange`) while still giving the user a way to change a layer's table after creation.
</objective>
