<objective>
Rework `MapChartRenderer.tsx` to render N stacked ImageWMS layers — one per dashboard layer whose id is in `widget.config.includedLayerIds`. Shrink `MapConfigPanel.tsx` to only Title + Basemap + layer-inclusion picker (delete the spatial/render/classbreak/contour sections — their successor is `KineticaWmsLayerForm` driven by `LayersModal`). Add the `.widget-map-reconfigure` overlay for old-config Phase 11 widgets and the `.widget-map-empty` overlay for the zero-included-layers state. Remove the `tableRef` prop from both `<MapChartRenderer>` call sites in `WidgetRenderer.tsx`.

Purpose: This is the "hard cutover" — Phase 11 map widgets configured with the old single-WMS shape become inert with a reconfiguration prompt; new widgets render any number of dashboard layers in `position` order. Each layer keeps its own filter subscription so cross-table filter changes do not over-refetch.

Output: A multi-layer renderer that preserves M-01 (single Map instance), M-02 (updateParams not rebuild), per-layer cache-bust, and per-layer opacity; a shrunk MapConfigPanel; explicit reconfigure + empty-state overlays; WidgetRenderer.tsx call sites updated.

**Critical correctness fix:** the per-layer filter subscription key MUST read `layer.table_id` (the top-level `DashboardLayerDto` field — a real column on the SQLite table per Plan 01) and NOT `layer.config.tableId` (which is `undefined` because Phase 12 stores `table_id` as a top-level column, not inside the JSON config blob). Reading the wrong field makes per-layer filter subscription a permanent no-op for QUERY — Criterion 3 of phase verification would fail silently.
</objective>
