# Requirements: Kinetica BI — v1.4 Map Info Popup

**Defined:** 2026-05-07
**Core Value:** Click-through data exploration — users drill into chart elements and the entire dashboard filters to that slice of data, enabling fast iterative analysis without writing SQL.

**Milestone goal:** Add click-to-popup info display on map widgets across all 3 spatial column modes (lat/lon, WKT, Kinetica WKB), backed by a dashboard-level info-selection store, with a net-new Info Card chart type as the cross-widget consumer. Builds on v1.3's map filtering foundation and the existing `dashboard_layers` schema.

---

## v1.4 Requirements

### Spatial Query (SPATIAL)

The backend primitive that resolves a map click to nearby records. Covers all three spatial modes supported by the map widget.

- [x] **SPATIAL-V14-01**: System performs a Kinetica spatial-nearest query for `lat/lon` mode using `GEODIST(lon_col, lat_col, click_lon, click_lat)` to rank records by distance from the click point; returns up to 50 records per page ordered by ascending distance.
- [x] **SPATIAL-V14-02**: System performs a Kinetica spatial-nearest query for `WKT` mode using `STXY_DISTANCE(wkt_col, click_lon, click_lat)` to rank records by distance; passing the click as raw `(x, y)` avoids the cost of `ST_GEOMFROMTEXT` conversion on every query. Returns up to 50 records per page ordered by ascending distance.
- [ ] **SPATIAL-V14-03**: System performs a Kinetica spatial-nearest query for Kinetica WKB (binary geometry) mode; exact function syntax determined during Phase 18 spike (candidate: `ST_DISTANCE` with binary geometry column); spike must confirm the correct function name, argument types, and whether a conversion wrapper is needed before the endpoint is built. → DEFERRED to TD-V14-WKB-SPIKE (2026-05-08): no WKB-binary column reachable for spike; re-run when one becomes available. Phase 18 ships SPATIAL-V14-01 + V14-02 only.
- [x] **SPATIAL-V14-04**: New `POST /api/info/query` endpoint accepts `{ layerId, tableId, schema, table, spatialMode, spatialColumns, clickLon, clickLat, radiusPx, mapBbox, mapWidthPx, mapHeightPx, page }` and returns `{ rows: Record<string, unknown>[], columns: string[], totalEstimate?: number, hasMore: boolean, page: number }`; routes to the correct spatial function per `spatialMode`; pagination via `LIMIT 50 OFFSET (page * 50)`.
- [x] **SPATIAL-V14-05**: Endpoint converts `radiusPx` to a ground-distance threshold using the map bounding box and pixel dimensions supplied in the request, so the click radius is consistent across zoom levels and map sizes.

### Info Selection Store (STORE)

Frontend Zustand slice that holds the current info selection at dashboard scope. Session-only — mirrors `useFilterStore` lifecycle.

- [x] **STORE-V14-01**: New `useInfoSelectionStore` Zustand slice with shape `Record<layerId, { rows: Record<string, unknown>[], columns: string[], page: number, hasMore: boolean, loading: boolean, error: string | null }>` plus top-level `activeLayerId: number | null` and actions `setSelection`, `clearSelection`, `setActiveLayer`, `setLoading`, `setError`, `reset`.
- [x] **STORE-V14-02**: Store state is session-only — not persisted to URL parameters, localStorage, or any database; state is lost on page refresh, dashboard switch, and logout.
- [x] **STORE-V14-03**: Dashboard-switch lifecycle reset — `useInfoSelectionStore.reset()` called in the same `DashboardOpen` cleanup effect that resets `useFilterViewStore`; ensures selection from a prior dashboard does not bleed into a newly opened dashboard.
- [x] **STORE-V14-04**: Logout lifecycle reset — `useInfoSelectionStore.reset()` called alongside `useFilterStore.reset()` and `useFilterViewStore.reset()` in the `App.tsx` unauthenticated effect.
- [x] **STORE-V14-05**: Layer-switch pagination reset — when `setActiveLayer(layerId)` is called with a different layer than the current `activeLayerId`, the previously active layer's `page` counter resets to 0 so the next fetch starts from page 1.

### Map Click Popup (POPUP)

The popup UX rendered inside `MapChartRenderer` when a user clicks on the map, and all supporting client-side behaviour.

- [x] **POPUP-V14-01**: User clicks on a map widget with info popup enabled → click handler fires a `POST /api/info/query` for each visible, enabled layer using the map's current viewport bbox, widget pixel dimensions, and configured `info_radius_px`; the popup opens above the click point showing results for the first layer that returns records.
- [x] **POPUP-V14-02**: The popup body contains a layer dropdown listing all visible, enabled layers; switching layers in the dropdown fetches and displays results for the selected layer; pagination counter resets on each layer switch per STORE-V14-05.
- [x] **POPUP-V14-03**: The popup shows records in pages of 50; a "Load more" control appends the next page of results on demand (no full-page replace); the control is hidden when `hasMore` is false.
- [x] **POPUP-V14-04**: Each record is rendered using the layer's `info_template` HTML string if configured; when no template is configured the popup falls back to a plain key-value table of all selected columns.
- [x] **POPUP-V14-05**: User can dismiss the popup with a close button or by clicking outside the popup area; dismissal calls `useInfoSelectionStore.reset()` and clears the `activeLayerId`.
- [x] **POPUP-V14-06**: A per-map-widget kill switch (`info_enabled` on the widget config) completely disables the click handler and popup for that widget; clicking a map with info disabled has no effect.

### Configuration (CONFIG)

Schema extensions and UI panels for per-layer and per-widget info popup settings.

- [x] **CONFIG-V14-01**: `dashboard_layers` SQLite table gains three new columns: `info_enabled INTEGER NOT NULL DEFAULT 1` (per-layer toggle), `info_columns TEXT` (JSON array of column names to include; NULL means all columns), `info_template TEXT` (raw HTML template string; NULL means default key-value table).
- [x] **CONFIG-V14-02**: Map widget config (`widget.config`) gains two new fields: `infoEnabled: boolean` (per-widget kill switch, default `true`) and `infoRadiusPx: number` (click radius in pixels, default `20`).
- [x] **CONFIG-V14-03**: Layer config panel in `LayersModal` / `KineticaWmsLayerForm` gains a new "Info Popup" tab containing: an enable/disable toggle, a column multi-picker (lists all columns from the layer's table; default all selected), and a freeform HTML template editor (textarea with a syntax note).
- [x] **CONFIG-V14-04**: Map widget config panel (`MapConfigPanel`) gains a new "Info Popup" section with: an enable/disable toggle (per-widget kill switch) and a numeric input for `infoRadiusPx` (pixel radius, integer, min 1, max 200, default 20).

### Info Card Chart (CARD)

A net-new chart type that reads the current info selection from the store and renders it inside a standard dashboard widget.

- [x] **CARD-V14-01**: System registers a new `info-card` chart type in the chart-type registry alongside the existing 8 types (bar/line/pie/scatter/table/records-table/big-number/map); it is selectable from the chart type picker when adding a new widget.
- [x] **CARD-V14-02**: The Info Card widget renders records from `useInfoSelectionStore` for a configured layer; an in-widget layer dropdown (sticky header band of the card body — NOT a widget config panel dropdown) lets the user switch which dashboard layer's info selection to display. Dropdown source is dashboard-scoped: all layers where `info_enabled === 1` AND `spatialMode !== "wkb"`. On-demand `POST /api/info/query` fires when the switched-to layer has no entry in the store, using replayed spatial coords from `useLastInfoClickContextStore` (Phase 23 relaxed pure-consumer lock — see PROJECT.md Key Decisions). When `useLastInfoClickContextStore.context === null` (no prior click), dropdown switch only updates focus and does NOT fetch (Pitfall 2 lock).
- [x] **CARD-V14-03**: The Info Card renders records using the selected layer's `info_template` HTML string when configured; falls back to a plain key-value table when no template is set; matches the popup rendering path in POPUP-V14-04.
- [x] **CARD-V14-04**: When no info selection exists for the configured layer (store empty or `activeLayerId` null), the Info Card displays a neutral empty state ("Click a point on the map to see details") rather than a blank panel or an error.

### Verification (VERIFY)

End-to-end validation that v1.4 closes its stated goals.

- [x] **VERIFY-V14-01**: End-to-end verification documented in `18-VERIFICATION.md` (or equivalent phase directory) — covers: map click → spatial query fires → popup opens with records → layer switch → pagination → HTML template rendering → Info Card receives same selection → dashboard switch clears selection → per-layer and per-widget kill switches suppress the popup; manual UAT covers all 3 spatial modes (lat/lon, WKT, WKB) and both auth modes (password + OIDC); report follows the 17-VERIFICATION.md pattern.

## v2 Requirements

Acknowledged but deferred. Not in the v1.4 roadmap.

### Persistence

- **PERSIST-V2-01**: URL-encoded info selection — serialize `activeLayerId` + page to URL query param so selections survive page refresh.
- **PERSIST-V2-02**: Server-side info selection persistence — save the current selection to SQLite so it can be restored on dashboard reload or shared via URL.

### Hover Mode

- **HOVER-V2-01**: Hover over a map point triggers a lightweight info preview tooltip (not a full popup); configurable per layer alongside the existing click config.

### Aggregate-layer Info

- **AGG-V2-01**: Heatmap and contour layer info click returns aggregated bucket statistics rather than underlying records; configurable aggregate function (count / sum / avg) per layer.

### Cross-widget Broadcast

- **XWIDGET-V2-01**: Existing chart types (bar, line, pie, scatter, table, records-table, big-number) can optionally subscribe to the info selection store as a data source, rendering the selected records in their own chart layout rather than requiring an Info Card widget.

## Out of Scope

Explicitly excluded from v1.4.

| Feature | Reason |
|---------|--------|
| Carry-over TDs from v1.3 (TD-V12-04, TD-V11-04, TD-V13-01) | Deferred indefinitely; fixing OIDC test mocks and fetch-mock brittleness adds backend test risk without user-facing value; v13 fixture demo is informational |
| URL / DB persistence of info selection | Session-only is sufficient; persisting selection adds complexity (serialization, schema changes) with negligible user benefit for a v1 feature |
| Hover behavior | Click-only reduces accidental triggers on dense maps; hover UX is a v2 enhancement (HOVER-V2-01) |
| Aggregate views for heatmap / contour layers | Heatmap/contour are derived render modes; info click always queries underlying records for maximum data fidelity; aggregate stats are a v2 option (AGG-V2-01) |
| Retrofitting existing chart types as info consumers | Only Info Card is net-new in v1.4; adding optional store-subscribe to bar/line/pie/etc. is XWIDGET-V2-01 |
| Filter side effects from info click | Info click is purely informational — it must NOT add a filter chip or trigger `useFilterStore.addFilter`; conflating inspection with filtering would confuse the data model |
| Multi-popup (simultaneous clicks on multiple map widgets) | Single active info selection per dashboard; second click replaces the first |
