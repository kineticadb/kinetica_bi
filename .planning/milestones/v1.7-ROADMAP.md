## Phase Details

### Phase 37: CB/Track WMS Spike
**Goal**: Lock the exact Kinetica WMS parameter surface for classbreak and track styling against the deployed instance before any UI code ships — eliminating the CB_COLUMN_NAME vs CB_ATTR discrepancy and the color format ambiguity.
**Depends on**: Nothing (P0 gate for all subsequent phases)
**Requirements**: SPIKE-V17-01, SPIKE-V17-02, SPIKE-V17-03, SPIKE-V17-04, SPIKE-V17-05, SPIKE-V17-06
**Success Criteria** (what must be TRUE):
  1. `37-SPIKE-NOTES.md` is committed with a PASS/FAIL verdict for every probe: CB param names (CB_ATTR vs CB_COLUMN_NAME), categorical CB_VALS string support including `<other>` and comma-escaping, color format (8-char AARRGGBB vs 6-char RRGGBB), DOTRACKS=TRUE under STYLES=raster, and TRACK_* + comma-separated raster params under STYLES=cb_raster — each verdict backed by both HTTP 200 status AND a visual tile diff.
  2. The exact classbreak param name set is locked in the notes file (CB_ATTR or CB_COLUMN_NAME, CB_VALS or CB_BREAK_POINT_N, per-break color param name), with a Decision Record so Phase 38 can implement against known names without further probing.
  3. The 6-char RRGGBB vs 8-char AARRGGBB finding is explicit in the notes file, documenting the existing `wmsUrlBuilder.ts` bug for mandatory fix in Phase 38.
  4. The spike runner (`kinetica_bi/server/src/cbTrackSpike.ts` or equivalent) is committed and executable via `npm run cb-track-spike` from a clean checkout.
  5. NTILE quantile SQL syntax (PARTITION BY 0 vs PARTITION BY null) is validated against the deployed instance and locked in the notes file so Phase 38 can implement `/api/quantile` without ambiguity.
**Plans**: 1 plan
  - [ ] 37-01-cb-track-wms-spike-PLAN.md — Operator-driven spike runner + Decision Record locking CB param names, color format, NTILE syntax, DOTRACKS/TRACK_* matrix

### Phase 38: Schema + WMS Engine Foundation
**Goal**: The server-side and URL-builder foundation is in place — schema migrated, DTO extended, wmsUrlBuilder emitting correct CB_* and TRACK_* params per spike findings, 6-char color bug fixed, and `/api/quantile` endpoint live — so Phases 39 and 41 can persist and test real data.
**Depends on**: Phase 37 (spike findings dictate CB param names, color format, NTILE SQL)
**Requirements**: SCHEMA-V17-01, SCHEMA-V17-02, SCHEMA-V17-03, SCHEMA-V17-04, SCHEMA-V17-05, SCHEMA-V17-06, SCHEMA-V17-07
**Success Criteria** (what must be TRUE):
  1. A running server restarts cleanly against an existing database — the PRAGMA-guarded `cb_config` and `track_config` ALTER migrations are idempotent (second restart produces no error).
  2. `POST /api/quantile` returns `{ breaks: number[] }` for a valid numeric column request; supertest cases pass under both `AUTH_MODE=password` and `AUTH_MODE=oidc` (AUTH_MODE-agnostic spec pattern, no TD-V16-TEST-ISOLATION regressions added).
  3. `wmsUrlBuilder.buildWmsParams` for a classbreak layer emits colors as 8-char AARRGGBB (not 6-char RRGGBB); a regression spec locks this format so the bug cannot silently re-appear.
  4. A PATCH request with `cb_config` or `track_config` JSON round-trips through the server and is returned unchanged on the subsequent GET — the full DTO extension (server type, mapDashboardLayer projection, CRUD route, frontend DTO) is wired end-to-end.
  5. `lib/trackDetect.ts` `isTrackTable(columns)` correctly identifies a TRACKID + x + y + TIMESTAMP column set and rejects sets missing any of the four fields (unit spec confirms both cases).

### Phase 39: Classbreak Form UI + Auto-Suggest
**Goal**: Operators can configure classbreak rendering end-to-end from the LayersModal: pick the CB column, build numeric or categorical breaks with labels and colors, optionally add per-break advanced params, use Auto-suggest to populate quantile boundaries, and have the map re-render correctly on every change.
**Depends on**: Phase 38 (cb_config schema must exist for persistence; /api/quantile must be live for Auto-suggest)
**Requirements**: CB-V17-01, CB-V17-02, CB-V17-03, CB-V17-04, CB-V17-05, CB-V17-06, CB-V17-07, CB-V17-08, CB-V17-09
**Success Criteria** (what must be TRUE):
  1. The render-mode picker in KineticaWmsLayerForm shows three options (Raster, Heatmap, Class Break); selecting Class Break reveals the CB column picker and break-row builder without disturbing the existing Raster and Heatmap paths.
  2. Clicking [Auto-suggest breaks] with a numeric column selected calls `/api/quantile`, replaces the current rows with the returned boundaries, and shows a confirmation prompt if rows were hand-edited — the map re-renders with the new break colors after save.
  3. Categorical (string) mode is available when a TEXT/CHAR column is selected: break values are text inputs, the `<other>` bucket toggle appears, and a distinct-value count probe warns and caps at 256 if exceeded.
  4. WKB-binary columns are excluded from the CB column picker; an inline message "WKB columns not supported for classbreak in v1.7" explains why.
  5. Editing any CB param (color picker, break value, label, per-break advanced field) triggers a WMS tile re-render — `lastEmittedParamsRef` fingerprint covers all new CB_* params so no silent cache-bust misses occur.
