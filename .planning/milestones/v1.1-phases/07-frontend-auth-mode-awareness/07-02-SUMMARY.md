## Decisions Made

- **Vitest pinned to `^4.1.5`** to match the server's existing pin (RESEARCH Open Question #1). Did NOT install Vitest 5.x — Vitest 5 has not landed yet at writing and the server-frontend pin parity matters for future shared config.
- **`isolate: true`** mirrors `kinetica_bi/server/vitest.config.ts` — each spec file gets its own worker; module-singleton state (auth store, sessionStorage) cannot bleed across files.
- **`globals: true`** matches server style; the sanity spec STILL imports `describe`/`it`/`expect` explicitly to verify both styles work side-by-side, future specs may use either.
- **Co-located specs** (`src/**/*.spec.{ts,tsx}`) chosen over `tests/` mirror. Frontend code is small and component-adjacent specs improve discoverability (RESEARCH Open Question #3 recommendation).
- **`__mocks__/zustand.ts` at project root, not under `src/`** — Vitest's automock discovery follows the same convention as Jest: root-level `__mocks__/<package>` is auto-applied by `vi.mock("<package>")`. This is why the file MUST live at `kinetica_bi/__mocks__/zustand.ts`, not `kinetica_bi/src/__mocks__/zustand.ts`.
- **Sanity spec is intentionally fat** (5 tests) — it doubles as a regression test for the rig itself. Two of the five tests deliberately verify Zustand reset isolation by writing in one test and reading the default value in the next.
