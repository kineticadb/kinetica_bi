<objective>
Refactor sessionStore.ts to support both password and OIDC credential storage in a single typed API. Rename `encryptPassword`/`decryptPassword` → `encryptSecret`/`decryptSecret` in place. Extend `SessionRow` with `secret`/`credentialType`/`idToken` fields (replacing `password`). Switch `createSession` to an options-object signature accepting optional `credentialType` and `idToken`. Extend `getSession` to eagerly decrypt id_token when present, dropping the row on decrypt failure (symmetric with the secret-decrypt path).

Purpose: This is the typed contract every downstream phase depends on. Without this, auth.ts cannot read `session.secret`/`session.credentialType` and Phase 5's OIDC callback handler has no way to call `createSession` with a token + id_token. The rename + options-object decision is locked in CONTEXT.md.

Output: Updated `sessionStore.ts` with new type + signatures; updated crypto + CRUD test files (mechanical identifier rename + a new OIDC round-trip test). Existing crypto behavior (AES-256-GCM, fresh IV, drop-row-on-decrypt-failure) preserved verbatim.
</objective>
