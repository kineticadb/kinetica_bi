<objective>
Add a proactive access-token-expiry check inside `getSession` (sessionStore.ts) so OIDC sessions whose stored access_token's `exp` claim is in the past never have their token forwarded to Kinetica. The check uses a small decode-only JWT helper (no signature reverify — the signature was verified once at callback time per PITFALL I-07). Opaque tokens (non-JWT or malformed) skip the check and fall through — the existing reactive 401-REAUTH chain handles them. Password sessions are untouched.

Purpose: SC3 (expired token never forwarded — `requireAuth` returns null → 401 REAUTH). Backbone of UX-04 + UX-05.

Output: `tryDecodeAccessTokenExp` helper exported from sessionStore.ts (or co-located near `getSession`); `getSession` extended with the new branch as the fourth drop-row trigger; new tests in `sessionStore.crud.spec.ts` covering past/future/opaque/password-mode.

This helper is consumed by Plan 06-03 (opaque-token warning at /oidc/callback).

    ```typescript
    /**
     * Decode-only JWT exp extraction. Single failure mode: returns null on ANY parse problem
     * (≠3 segments, malformed b64, malformed JSON, missing/non-numeric exp). Caller treats
     * null as "opaque or unparseable — skip proactive check, defer to reactive 401 from Kinetica."
     *
     * NOT signature-verified — id_token was signature-verified at OIDC callback time
     * (PITFALL I-07; AES-256-GCM auth tag protects integrity at rest).
     */
    export const tryDecodeAccessTokenExp = (token: string): number | null => {
      const parts = token.split(".");
      if (parts.length !== 3) return null;
      let payload: unknown;
      try {
        const json = Buffer.from(parts[1], "base64url").toString("utf8");
        payload = JSON.parse(json);
      } catch {
        return null;
      }
      if (
        !payload ||
        typeof payload !== "object" ||
        !("exp" in payload) ||
        typeof (payload as { exp: unknown }).exp !== "number"
      ) {
        return null;
      }
      return (payload as { exp: number }).exp;
    };

    // Clock-skew tolerance: 30 seconds — matches Phase 5 openid-client clockTolerance: 30 (PITFALL T-06).
    // Single window across callback verify and request-time exp re-check.
    const ACCESS_TOKEN_CLOCK_SKEW_SECONDS = 30;
    ```
