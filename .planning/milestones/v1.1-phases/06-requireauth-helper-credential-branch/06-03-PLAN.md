<objective>
Add three operator-facing observability signals to `index.ts`:
1. **oidc_boot structured log** — one JSON line at boot in OIDC mode naming issuer + audience (pre-empted from Phase 8 SC5 per CONTEXT.md).
2. **Unauthenticated Kinetica reachability probe** — async fetch to `${KINETICA_URL}/version` at boot in OIDC mode; on rejection/non-2xx, emit one `kinetica_unreachable` warn log and continue boot (do NOT fail-fast).
3. **Opaque-token warning at /oidc/callback** — once-per-login warn log when the access_token can't be decoded as a JWT (PITFALL T-05 + Phase 5 STATE.md Q2).

Purpose: Makes Kinetica OIDC trust misconfig (PITFALL I-06) and opaque-token deployments diagnosable from logs without reading the runbook. Phase 8 will reference these log lines from DEPLOY-RUNBOOK.md.

Output: Updated `index.ts` with all three signals (gated to OIDC mode); extended `bootstrap.spec.ts` with boot-probe success/failure tests; extended `auth.oidc.spec.ts` with opaque-token warning fire/no-fire tests.

This plan depends on Plan 06-02 because the opaque-token warning reuses `tryDecodeAccessTokenExp` (sessionStore.ts).
