# Phase 107 — UI Design Contract

> Visual and interaction contract for the collapsible right-side filter panel, the top-bar↔panel XOR switch, grid reflow, and the shared `FilterChip`. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Consumed by gsd-planner and gsd-executor as the visual source of truth.

**Scope reminder (from 107-CONTEXT.md):** this spec covers the panel shell, collapse/expand + rail, reflow, XOR mode switch, chip anatomy + provenance, group headers, per-chip remove, per-group clear, empty state, and count badge. It explicitly does NOT design: the applies-to list / on-canvas highlight (Phase 108), the global clear-all action (Phase 109), or the designer mode-toggle control (Phase 110). Where this spec reserves layout room for those, it says so and stops there.

### Media-query behavior (add inside the same new-class rules, not separate classes)
```css
/* Narrow-viewport: expanding the panel must OVERLAY, never reflow (Pitfall 9 / CONTEXT lock).
   Reuses the SAME 900px breakpoint already gating #root's sidebar collapse (global.css ~1774),
   so "narrow" has one consistent definition app-wide. */
@media (max-width: 900px) {
  .filter-panel {
    position: fixed;
    top: 0;
    right: 0;
    bottom: 0;
    z-index: 1000;
    border-radius: 0;
    box-shadow: var(--shadow-lg);
    background: var(--panel-solid); /* solid, not translucent — must read over dashboard content */
  }
}
```
The rail (`.filter-panel-rail`) needs NO media-query variant — it stays in-flow at all widths (44px is cheap to reflow around even on narrow screens).

**No width-transition / no ResizeObserver-thrash risk (Pitfall 3 lock):** collapse↔expand is a **discrete conditional render** (`.filter-panel` swaps for `.filter-panel-rail`, or vice versa) — NOT an animated width. This guarantees `useContainerWidth`'s ResizeObserver fires exactly once per toggle, never mid-transition. Do not add a `transition: width` to `.filter-panel`/`.filter-panel-rail`.

## Interaction / State Contract

| State | Behavior |
|---|---|
| Default (mode=panel, wide viewport) | Panel expanded, in-flow flex sibling of `.filter-panel-grid-wrap`; grid measurably shrinks by `var(--filter-panel-width)` via `useContainerWidth`'s ResizeObserver |
| Collapsed (any viewport) | `.filter-panel` swaps for `.filter-panel-rail` (discrete render, no width animation) — rail shows expand button + count badge |
| Narrow viewport (≤900px), default | Auto-collapses to rail on load (JS `matchMedia`/window-width check feeding the initial collapsed state — CSS alone cannot drive this) |
| Narrow viewport, user expands | `.filter-panel` gets `position:fixed` overlay via the 900px media query — grid width is UNCHANGED (no reflow), panel floats over the rightmost widgets |
| Collapse state persistence | `localStorage`, keyed per-user per-dashboard (per 107-CONTEXT.md) — client-only, never sent to the server, independent of the designer's saved `filter_display_mode` |
| Mode = topbar / absent | `.filter-panel-layout`/`.filter-panel-grid-wrap`/`.filter-panel`/`.filter-panel-rail` are NEVER rendered; the `containerRef` div keeps zero extra className — byte-identical to pre-Phase-107 DOM/CSS |
| Group collapse | Conditional render of the group body (unmount, not `display:none`) — mirrors `LayersLegendPanel`'s existing collapse pattern |
| Empty panel (0 active filters, expanded) | `.filter-panel-empty` renders in `.filter-panel-body` instead of any groups |
| Empty rail (0 active filters, collapsed) | `.filter-panel-rail-badge--empty` variant, showing "0" |
| Chip truncation | `.filter-panel-chip-value` truncates via CSS `text-overflow:ellipsis`; the FULL untruncated `buildChipText(...)` output is always available via the native `title` attribute on that span |
| Focus visibility | Every new icon button gets `:focus-visible { outline: 1px solid var(--accent); ... }` — mirrors `.sidebar-toggle:focus-visible` / `.filter-bar-chip-dismiss:focus-visible` exactly |
